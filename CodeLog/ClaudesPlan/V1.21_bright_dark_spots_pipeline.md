## 0. TL;DR for the implementer

Add a fourth `AnalysisPipeline` to the General Analysis tab that reproduces the
behavior of Nikon NIS-Elements **General Analysis 3 → Bright Spots / Dark Spots**
binary-creation operators. The pipeline is a classical scale-space blob
detector with a circularity gate, an LUT-histogram intensity gate, optional
mask growth, and a toggle between point-output (circular disk at the centroid)
and true-region output (the connected-component mask of the detected blob).

1. **Qt-free subpackage** at `nd2studios/backend/analysis/spots/` (six modules).

## 1. Background — what GA3 Bright/Dark Spots actually does

Nikon's General Analysis 3 (GA3) is a node-graph image-analysis tool inside
NIS-Elements. The **Bright Spots** and **Dark Spots** binary operators are the
go-to detector for punctate structures (foci, nuclei, vesicles, granules,
particles). Nikon does not publish the exact algorithm, but the behavior of
the parameters is well-characterised in the user manual, application notes,
and from comparisons against scikit-image's reference blob detectors.

The detector has three logical stages:

### 1.1 Scale-space spot localisation

GA3 looks for **local extrema in a band-pass-filtered image**. The standard
formulation is the **Laplacian of Gaussian (LoG)** response

```
L(x, y; σ) = σ² · ∇²(I * G_σ)(x, y)
```

evaluated at a single scale σ tuned to the user's "typical diameter" `d`.
For a circular Gaussian blob of FWHM = `d`, the optimal LoG response occurs at

```
σ = d / (2 · √2 · √(ln 2))     ≈ d / 2.355
```

In practice GA3 likely uses **Difference of Gaussians (DoG)** as a cheap
LoG approximation, with an inner sigma `σ₁ = d / (2·√2·√(ln 2))` and an outer
sigma `σ₂ = κ·σ₁` (κ ≈ 1.6 is the Marr-Hildreth ratio):

```
DoG(I) = I * G_{σ₁} − I * G_{σ₂}
```

For **bright spots** the algorithm finds local maxima of the LoG/DoG response;
for **dark spots** it finds local minima (or inverts the image and reuses the
maxima detector). Local extrema with magnitude below the **contrast threshold**
are rejected as noise.

### 1.2 Symmetry / shape gate

After candidate extrema are localised, GA3 grows each candidate to a small
neighbourhood (size proportional to `d`) and tests its **circularity /
symmetry**. The published "All objects / More objects / Medium / Less objects"
options correspond to four bins of an internal circularity threshold:

| GA3 setting    | Strictness | Effective circularity floor |
|----------------|-----------|----------------------------|
| All objects    | None       | 0.0  (accepts everything)  |
| More objects   | Loose      | ≈ 0.45                     |
| Medium         | Moderate   | ≈ 0.65                     |
| Less objects   | Strict     | ≈ 0.80                     |

Circularity is the standard `4π · area / perimeter²` ∈ [0, 1]. Equivalent
formulations use `(minor_axis / major_axis)` (eccentricity-based) or
`solidity = area / convex_hull_area`. For the V1.21 implementation we will
expose **circularity** as the primary symmetry score and document the mapping.

### 1.3 LUT-histogram intensity gate

In addition to the contrast/prominence gate (which is a *local* test), GA3
applies a **global intensity gate** derived from the channel's LUT histogram.
For bright spots the user typically sets a percentile floor (e.g. P50–P95)
that the centroid intensity must exceed; for dark spots a ceiling (e.g.
P5–P50) that the centroid intensity must fall below.

In ND2Studios this maps directly onto the existing `histothresh.histogram`
module (V1.20): `compute_histogram(image, bit_depth=12).percentile(p)` already
returns the integer DN at percentile `p`. We will reuse it verbatim — no
duplication.

### 1.4 Optional grow-objects step

After the gates pass, GA3 optionally **grows** each accepted blob with a
morphological dilation or watershed expansion to capture the full extent of
the bright/dark region (not just the LoG peak). The grow size is given in
pixels or microns, and the grown mask is intersected with a region-of-interest
constraint (e.g. tissue mask) when applicable.

### 1.5 Output mode — circular vs. spot vs. region

GA3 lets the user choose between three output modes:

1. **Spot output (point)** — a single-pixel centroid mask. Useful for counting,
   point-pattern statistics, density mapping. *Out of scope for V1.21.*
2. **Circular area output** — a synthesized disk of radius `d/2` centred on
   each detected centroid. Independent of the actual blob shape; reproducible.
3. **Region output** — the true connected-component mask of the bright/dark
   blob, obtained by thresholding the LoG response near the local extremum
   followed by watershed-from-marker.

The V1.21 implementation will expose `circular` and `region` as the two output
modes (a `point_output` mode is trivial to add later — it is just the
`circular` mode with `radius = 1`).

## 2. Literature & references

The classical underpinnings are stable and well-documented; cite these in the
docstrings and in `Research/2026-05-06_bright_dark_spots.md` (template at
`Research/templates/literature_review.md`):

1. **Lindeberg, T. (1998)** — "Feature detection with automatic scale selection",
   *IJCV* 30(2), 79–116. The canonical scale-space blob detector. Establishes
   the σ²·∇² normalisation used in `skimage.feature.blob_log`.
2. **Marr, D. & Hildreth, E. (1980)** — "Theory of edge detection",
   *Proc. R. Soc. Lond. B* 207, 187–217. Origin of the κ ≈ 1.6 DoG
   approximation to LoG.
3. **Lowe, D. G. (2004)** — "Distinctive image features from scale-invariant
   keypoints", *IJCV* 60(2), 91–110. SIFT's DoG pyramid; the prototype for
   how GA3-style detectors stack scales and threshold contrast.
4. **Smal, I. et al. (2010)** — "Quantitative comparison of spot detection
   methods in fluorescence microscopy", *IEEE TMI* 29(2), 282–301. Direct
   benchmark of LoG, DoG, h-dome, top-hat, and wavelet detectors on synthetic
   and real fluorescence images. Use the SNR/spot-density grids from this
   paper to seed our cross-validation.
5. **van Vliet, L. J. & Verbeek, P. W. (1995)** — "Estimators for orientation
   and anisotropy in digitized images". Source of the structure-tensor-based
   symmetry measures GA3 likely uses.
6. **Vincent, L. (1993)** — "Morphological grayscale reconstruction in image
   analysis: applications and efficient algorithms", *IEEE TIP* 2(2),
   176–201. The h-maxima / h-minima transform — GA3's likely back-end for
   "contrast" thresholding via dynamic-prominence selection.
7. **Soille, P. (2003)** — *Morphological Image Analysis*, 2nd ed., Springer.
   Reference for opening/closing, watershed-from-marker, and grayscale
   reconstruction used in §1.4 grow-objects.
8. **Nikon Instruments (2020)** — *NIS-Elements General Analysis 3 User
   Manual*. Vendor source for the parameter names and their qualitative
   meaning. Not citable as a primary reference but pinned in
   `Research/2026-05-06_bright_dark_spots.md` for parameter parity.
9. **Olivo-Marin, J.-C. (2002)** — "Extraction of spots in biological images
   using multiscale products", *Pattern Recognition* 35(9), 1989–1996.
   Wavelet-based alternative used as a sanity-check baseline in Smal (2010).
10. **scikit-image** — `skimage.feature.blob_log`, `blob_dog`, `peak_local_max`;
    `skimage.morphology.h_maxima`, `h_minima`, `reconstruction`,
    `watershed`. We build on these.

### 4.2 `scale_space.py`

```python
def resolve_sigma(typical_diameter_px: float) -> tuple[float, float]:
    """Return (sigma_inner, sigma_outer) for DoG given the typical diameter.

    Uses sigma_inner = d / (2*sqrt(2)*sqrt(ln 2)) (FWHM-matched) and
    sigma_outer = 1.6 * sigma_inner (Marr–Hildreth ratio).
    """
    sigma_in = typical_diameter_px / (2.0 * np.sqrt(2.0 * np.log(2.0)))
    return sigma_in, 1.6 * sigma_in


def log_response(image, sigma):
    """Return σ²-normalised Laplacian of Gaussian response (float32)."""

def dog_response(image, sigma_in, sigma_out):
    """Return Difference-of-Gaussians band-pass response (float32)."""
```

Performance note: prefer DoG (two `gaussian_filter` calls) over true LoG for
larger images; expose the choice via `SpotsConfig.kernel = "log" | "dog"`
with `dog` as the default.

### 4.3 `detection.py`

```python
def find_extrema(
    response: np.ndarray,
    *,
    polarity: Literal["bright", "dark"],
    min_distance: int,
    contrast: float,
) -> np.ndarray:
    """Return (N, 2) array of (row, col) extrema in the response map.

    `min_distance` is set to ≈ typical_diameter / 2 so two adjacent spots
    are not double-counted.
    """

def h_transform_seeds(
    image: np.ndarray,
    *,
    polarity: Literal["bright", "dark"],
    h: float,
) -> np.ndarray:
    """h-maxima (bright) / h-minima (dark) transform — returns a marker mask
    where each connected component is one spot seed. Used as an alternative
    to peak_local_max + DoG; included for cross-validation."""
```

Implements `peak_local_max` on the LoG/DoG map for bright; on `−response` for
dark. The contrast threshold is applied as `abs(response[peaks]) >= contrast`
in normalised units (the response map is scaled to [0, 1] across the frame
before the gate so `contrast` is bit-depth-independent — same robustness
choice as `tear_detection`'s rank normalisation).

SYMMETRY_FLOOR = {"all": 0.0, "more": 0.45, "medium": 0.65, "less": 0.80}

### 4.6 `config.py`

```python
@dataclass
class SpotsConfig:
    polarity: Literal["bright", "dark"] = "bright"
    typical_diameter_um: float = 5.0
    contrast: float = 0.05            # normalised LoG/DoG response threshold
    symmetry: Literal["all", "more", "medium", "less"] = "medium"

    # LUT-histogram-based intensity gate (delegates to histothresh.histogram)
    intensity_percentile: float | None = 50.0   # bright: floor; dark: ceiling
    bit_depth: int = 12

    # Grow objects
    grow_radius_um: float = 0.0       # 0 = no grow
    grow_method: Literal["dilation", "watershed", "none"] = "none"

    # Output mode
    output_mode: Literal["circular", "region"] = "region"

    # Engine
    kernel: Literal["log", "dog"] = "dog"
    bit_depth_strict: bool = False    # match histothresh default

    def __post_init__(self) -> None:
        if self.typical_diameter_um <= 0:
            raise ValueError("typical_diameter_um must be > 0")
        if not (0.0 <= self.contrast <= 1.0):
            raise ValueError("contrast must be in [0, 1] (normalised units)")
        if self.symmetry not in ("all", "more", "medium", "less"):
            raise ValueError(f"unknown symmetry setting {self.symmetry!r}")
        if self.intensity_percentile is not None and not (
            0.0 <= self.intensity_percentile <= 100.0
        ):
            raise ValueError("intensity_percentile must be in [0, 100]")
        if self.grow_method != "none" and self.grow_radius_um < 0:
            raise ValueError("grow_radius_um must be >= 0")
```

### 4.7 `identifier.py`

```python
@dataclass
class SpotsResult:
    mask: np.ndarray            # bool (H, W)
    labels: np.ndarray          # int32 (H, W)
    centroids: np.ndarray       # (N, 2) float — (row, col)
    diameters_px: np.ndarray    # (N,) float — fitted FWHM diameter per spot
    contrast_scores: np.ndarray # (N,) float — normalised LoG/DoG magnitude
    circularity_scores: np.ndarray  # (N,) float
    regions: list[dict[str, Any]]
    config: SpotsConfig
    provenance: dict[str, Any]


class BrightDarkSpotsSegmenter:
    """Single-2D-frame spot detector. The pipeline adapter loops over T."""

    def __init__(self, config: SpotsConfig) -> None:
        self.config = config

    def run(
        self,
        image: np.ndarray,
        *,
        pixel_size_um: float | None = None,
        boundary_mask: np.ndarray | None = None,
    ) -> SpotsResult:
        ...
```

The orchestrator:

1. `validate_bit_depth(image, cfg.bit_depth, strict=cfg.bit_depth_strict)`.
2. Convert `typical_diameter_um → typical_diameter_px` via `pixel_size_um`
   (fallback: 1 µm/px when `pixel_size_um` is None or 0).
3. `sigma_in, sigma_out = resolve_sigma(d_px)`.
4. Compute LoG or DoG response.
5. Normalise the response to [-1, 1] (divide by `np.max(np.abs(response))`).
6. Apply LUT-histogram intensity gate using
   `histothresh.histogram.compute_histogram(image, bit_depth=cfg.bit_depth)` →
   `floor = hist.percentile(cfg.intensity_percentile)` (bright) or
   `ceiling = hist.percentile(cfg.intensity_percentile)` (dark). Build a
   global `intensity_mask`; `peak_local_max` is restricted to its True region
   via the `labels` parameter.
7. `centroids = find_extrema(response, polarity=cfg.polarity,
   min_distance=int(d_px / 2), contrast=cfg.contrast)`.
8. **Build the spot mask depending on `output_mode`:**
   * `region`: build seed labels at the centroids and call
     `grow_seeds_watershed(image, seed_labels, polarity=cfg.polarity,
     boundary_mask=boundary_mask)`. The watershed implicitly produces the
     true blob extent.
   * `circular`: rasterise a disk of radius `d_px / 2` at each centroid
     (using `skimage.draw.disk`) into an int32 label image.
9. Apply the symmetry gate (`filter_by_symmetry`) on the mask.
10. Optional grow-objects step (`grow_seeds_dilation` or
    `grow_seeds_watershed` depending on `cfg.grow_method`).
11. Re-label with `skimage.measure.label`, run `regionprops_table` to fill
    `regions`, including `area`, `mean_intensity`, `centroid`, and the
    custom `circularity` and `contrast_score` we computed at step 7.
12. Stamp `provenance = {timestamp, input_shape, input_dtype, input_hash}`
    (matches histothresh).

## 7. Cross-validation procedures

The detector is classical and the literature gives us strong baselines, so
cross-validation is tractable and important. Five complementary procedures:

### 7.1 Synthetic ground-truth (`tests/spots/test_synthetic.py`)

Generate `(H, W)` 12-bit images with Gaussian blobs at known
`(row, col, diameter, peak_intensity)`. Vary:

* **Diameter**: 3, 5, 8, 12, 20 px (against a `typical_diameter_px = 5`).
* **SNR**: 2, 3, 5, 10 (peak-over-σ_background).
* **Density**: 5, 25, 100, 400 spots per 512×512 frame.
* **Background**: uniform; gradient (linear); striped (sinusoidal).

Acceptance criteria, per (diameter, SNR, density) cell:

| Metric              | Target on `polarity = bright`         |
|---------------------|---------------------------------------|
| Recall              | ≥ 0.95 at SNR ≥ 3 and diameter within 0.7×–1.4× typical |
| Precision           | ≥ 0.90 at SNR ≥ 3                    |
| Centroid error      | ≤ 1 px (median) at SNR ≥ 5           |
| Diameter estimate   | within 20 % of ground truth          |

A full grid is small (5 × 4 × 4 × 3 = 240 cells) so the entire run finishes
in well under a minute. Store results as a CSV in `tests/spots/_artifacts/`
and assert the median over the grid meets the targets.

### 7.2 Reference-implementation parity (`tests/spots/test_reference_parity.py`)

Compare against `skimage.feature.blob_log` / `blob_dog` on the same synthetic
images. The matching test:

* Accept a synthetic image, run our detector with `kernel="log"` and
  scikit-image's `blob_log` with the *same* sigma.
* Compute a Hungarian-matching between the two centroid lists with a
  cost = pixel distance, gating at `d/2`.
* Assert ≥ 95 % matched at SNR ≥ 5 and that median centroid distance ≤ 1 px.

This parity test is the most important one — it pins the geometry of our
detector to a peer-reviewed reference, so any drift introduced by future
edits is caught immediately.

### 7.3 Polarity symmetry (`tests/spots/test_polarity.py`)

Take a synthetic bright-spot image `I_bright`, build `I_dark = I.max() − I_bright`.
Run the detector on `I_bright` with `polarity="bright"`, on `I_dark` with
`polarity="dark"`. Assert:

* Same number of detections, same centroids (within 1 px).
* `circularity_scores` and `contrast_scores` agree within 5 %.

This catches sign errors in the LoG-on-inverted-image path.

### 7.4 Symmetry-bin monotonicity (`tests/spots/test_symmetry.py`)

For a fixed image, sweep `symmetry ∈ {"all", "more", "medium", "less"}`. The
number of detected spots must be **monotonically non-increasing** as we
tighten the gate. Hardcoded:

```python
counts = [run(setting=s).total_objects for s in ("all", "more", "medium", "less")]
assert counts == sorted(counts, reverse=True)
```

### 7.5 Round-trip on real data (manual, `Research/2026-05-06_bright_dark_spots.md`)

Pick three real ND2 files from `~/Documents/MEBP-Paper/data/` (or whichever
directory the user designates) representing the dataset variability — small
puncta, large nuclei, low-contrast vesicles. For each:

1. Run the new pipeline at default parameters; record `total_objects` and
   median spot diameter.
2. If GA3 ground-truth is available (export from NIS-Elements as CSV with
   centroid columns), run a Hungarian match against our output and report
   precision, recall, centroid error.
3. If GA3 truth is not available, manually count spots in three randomly
   chosen 256×256 patches and compare to our detector's count in the same
   patches. Acceptable agreement: ≥ 90 % within ±10 % count.

Document the procedure and observed metrics in
`Research/2026-05-06_bright_dark_spots.md` using the template at
`Research/templates/literature_review.md`. The validation step is a manual
artefact — *not* a CI test — but the pipeline is not "done" until the
literature review captures these numbers.

### 7.6 Determinism & provenance (`tests/spots/test_determinism.py`)

* Two consecutive `run()` calls on the same image return identical labels,
  centroids, and `provenance.input_hash`.
* Provenance hash is sensitive to input perturbations: a 1-pixel intensity
  bump at one location changes `input_hash`.

This is verbatim from the histothresh test pattern.

## 11. Open questions / explicit non-goals

* **3-D spots are out of scope for V1.21.** GA3 supports them but ND2Studios'
  Analysis tab currently runs frame-by-frame. Add a `SpotsConfig.is_3d` flag
  in V1.22 once the Analysis tab grows volume support.
* **Sub-pixel centroid refinement** (parabolic fit on the LoG response) is
  not implemented. Users who need sub-pixel localisation should turn to
  the V1.22 follow-up (`refine_centroids: bool = False`).
* **Multi-scale detection** (the spot diameter is unknown a priori) is not
  exposed. The current single-σ design matches GA3's "typical diameter"
  parameter exactly. A future `typical_diameter_range_um: (lo, hi)` field
  would enable scale-space pyramid search; deliberately deferred.
* **GPU acceleration**: deferred. The detector is fast enough on CPU at the
  resolutions we typically work with (≤ 4096²).
* **Persistence in `.nd2s` sessions**: matches V1.19/V1.20 behaviour —
  `analysis_results` are not serialised; users export label masks/CSV
  explicitly. `analysis_config` (the param dict) *is* persisted via the
  existing `save_to_experiment()` hook.

## 12. Quick sanity checklist against the existing codebase

For Claude Code's first pass — verify these statements before writing code,
so the integration assumptions are still true:

* `AnalysisPipeline.register` is a class-decorator that mutates the class
  registry; it is **not** an instance decorator. Use exactly the same
  `@AnalysisPipeline.register / class XYZPipeline(AnalysisPipeline):` form
  as the three existing pipelines.
* `ParamSpec` lives in `nd2studios.core.plugin_registry` and supports
  `param_type` ∈ `{"float", "int", "bool", "choice", "str"}`.
* `analysis_page._load_params()` already injects live channel names into a
  `ParamSpec` named exactly `channel_name`. Use that exact name; do not
  rename.
* The page reads `progress_cb(int 0–100)` via `worker.progress`. Emit
  integer percentages, not floats.
* `BaseWorker.cancel()` flips a flag the page passes through as the
  `cancelled_cb` lambda; check it between frames *and* between expensive
  steps within a frame for large images.
* `AnalysisResult.label_masks` must use **int32** (the page's
  `_overlay_labels` casts to int when indexing into `_LABEL_PALETTE`).
* `metadata` dict contains `pixel_size_um` (added by the page from
  `exp.pixel_size_um`). Treat `0.0` and `None` as "no pixel size known"
  and fall back to per-pixel measurements.
* The `histothresh` subpackage is the structural template — when in doubt,
  copy its layout, naming, and dataclass conventions exactly.
