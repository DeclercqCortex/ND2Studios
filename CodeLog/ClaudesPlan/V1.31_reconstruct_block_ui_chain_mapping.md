# V1.31 — Reconstruct block UI + per-slice chain mapping

## Context

V1.28 introduced the **Reconstruct from multiple files…** dialog where
the user picks N files and chains them along a chosen axis. The
ordering was fixed: files concatenated in basename order, each file
contributing its native size on the chain axis contiguously.

The McGhee Lab needs to **arrange T positions between files** when
the natural order doesn't match the desired output. Pure filename
sorting isn't enough — sometimes the user wants file 4 to be T=0 or
to interleave Z planes across files. So V1.31 extends V1.28 with:

1. **Per-slice chain mapping.** Backend volumes accept an optional
   ``chain_mapping: list[tuple[int, int]]`` where entry *i* is the
   ``(file_idx, local_idx_in_file)`` for output slice *i*. With the
   mapping in place, the user can interleave / reverse / repeat
   slices from any file on the chain axis.
2. **Drag-reorderable T / M / Z block rows in the dialog.** Each axis
   gets a colored block strip; the chain-axis row is drag-and-drop
   reorderable, the other two are read-only context. Blocks are
   colored per source file (HSV-distributed palette) and tooltips
   show `<filename>\nSource: <axis>=<n>\nOutput <axis>=<i>`.

## Approach

### Backend

`LazyMultiFileND2Volume(filepaths, chain_axis, chain_mapping=None)`:
- ``chain_mapping=None`` → natural mapping `[(0,0), …, (0,n0-1), (1,0), …]`
  (V1.28 behavior, regression-safe).
- Else → stored as `self._chain_mapping`. `_lookup_chain(idx)` is now a
  direct list index instead of `bisect.bisect_right` on cumulative
  sums.
- ``_validate_chain_mapping()`` ensures every `(fi, li)` pair lies in
  range; raises with the bad entry on failure.
- ``reopen()`` round-trips the mapping for the prefetch worker.
- ``file_z_coords_um()`` returns Z coords in **mapped output order**
  (so the metadata reader's `stage_z_um` matches the visible Z axis).
  A new private `_raw_file_z_coords_um()` keeps the raw per-file probe.

`LazyMultiFileTIFFVolume` gets the same `chain_mapping` parameter and
`_validate_chain_mapping` helper.

`read_nd2_metadata_extended_multi(filepaths, chain_axis, chain_mapping=None)`
walks the mapping for each axis-specific override:
- chain=`Z` → `stage_z_um`/`z_step_um` ordered by mapping.
- chain=`T` → `frame_timestamps_s` indexed `(fi, li)` per output slot.
- chain=`M` → `stage_xy_um` indexed `(fi, li)` per output slot.
- chain=`C` → channel name / exposure / emission / excitation /
  color lists indexed `(fi, li)`.

The metadata reader probes every file once (not just file 0) so any
mapping that pulls slices from any file gets the right per-slice
metadata.

### Worker

`LoadWorker` accepts `chain_mapping: list[tuple[int, int]] | None` and
threads it into both `read_nd2_metadata_extended_multi` and the
`LazyMultiFile{ND2,TIFF}Volume` constructors. Single-file imports
ignore the parameter (existing path).

### Dialog

`AxisBlocksWidget(QListWidget)` — one horizontal row of blocks:
- `setFlow(LeftToRight)`, `setWrapping(True)`, max 160 px tall.
- One `QListWidgetItem` per slice. `Qt.UserRole` carries the
  `(file_idx, local_idx)` payload; tooltip carries the source-frame
  string; background brush = per-file color when chain axis, neutral
  gray when not.
- When `draggable=True`: `setDragDropMode(InternalMove)` and we hook
  the model's `rowsMoved` to emit a `reordered` signal so the dialog
  can refresh its preview.

`file_color_palette(n)` — `QColor.fromHsv(360*i/n, 180, 220)` per file,
tuned to read on the Dracula dark theme with black foreground text.

`ReconstructDialog` now hosts three `AxisBlocksWidget` rows (T, M, Z)
beneath the file table. `_rebuild_blocks()` runs on:
- file added / removed / reordered,
- chain-axis combo change.

`_rebuild_blocks` flips drag enable on the right row each time so the
chain-axis row is always the only one accepting drops.

New `chain_mapping()` accessor reads back the current chain-axis row's
display order as `list[tuple[int, int]]`. Empty list signals "use the
natural default" so the worker still works if no files have been
added yet (defensive).

### ImportPage

`_on_reconstruct` reads `dialog.chain_mapping()` and forwards it to
`_start_load_worker` → `LoadWorker(chain_mapping=…)`. No other page
needs changes — the composite volume keeps the existing public
surface.

## Verification

End-to-end smoke (all without GUI):

1. **Default mapping unchanged.**
   ```python
   vol = LazyMultiFileND2Volume(paths, chain_axis='T')
   assert vol._chain_mapping == [(0,0),(1,0),(2,0),(3,0),(4,0)]
   ```
2. **Reversed mapping swaps reads.**
   ```python
   vol_r = LazyMultiFileND2Volume(paths, chain_axis='T',
                                   chain_mapping=[(4,0),(3,0),(2,0),(1,0),(0,0)])
   assert np.array_equal(vol_r.get_frame(c=0,m=0,t=0,z=0,z_mode='none'),
                          vol.get_frame(c=0,m=0,t=4,z=0,z_mode='none'))
   ```
3. **Metadata respects mapping.**
   ```python
   meta = read_nd2_metadata_extended_multi(paths, 'T',
            chain_mapping=[(0,0),(2,0),(4,0),(1,0),(3,0)])
   assert meta['frame_timestamps_s'] == [t0, t2, t4, t1, t3]
   ```
4. **`reopen()` preserves the mapping.**
5. **Dialog drag-reorder flows through.**
   - Build dialog with offscreen Qt.
   - Move item-4 to position 0 on the T row.
   - `dialog.chain_mapping()` returns `[(4,0), (0,0), (1,0), (2,0), (3,0)]`.
   - Build a volume with that mapping; read T=0; assert byte-equal
     with the natural volume's T=4. ✓ verified.
6. **Chain-axis flip toggles drag on the right row.**
   - T draggable when chain=T; switch combo to Z; Z row becomes
     draggable, T/M rows go read-only. ✓ verified.
