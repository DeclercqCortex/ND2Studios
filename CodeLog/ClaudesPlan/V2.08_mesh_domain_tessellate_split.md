# V2.08 — The MESH domain + splitting `tessellate_volume` into tessellate → rasterize

> **Status: LOCKED + BUILT 2026-07-28.** Addendum to canonical `V2.00`. Un-defers the mesh
> domain that `V2.07 §2` postponed, and restores v1's tessellate/mask split in v2 with a
> real mesh on the wire between them.

## 0. The request (user, 2026-07-28)

> "I need the embedded tesselation workflow in one of the analysis nodes relevant to a
> granule workflow in v1 to be its own intermediate node. This means that we need to create
> a MESH domain. This tesselation node can have points and labels as input to draw the mesh."

**v1 already had the split.** `special:granule_tessellate` → `special:granule_mask` are two
nodes, and `granule_ops.py:7` draws the chain. The fusion is a **v2** regression:
`_compute_tessellate_volume` merged both halves because no v2 domain could carry a mesh
across a wire (V2.06 / V2.07 §2). So this is a restoration, with v1 as the reference design.

## 1. Decisions (grilled, user-locked)

| Fork | Chosen | Why |
|---|---|---|
| Vertex coordinate space | **voxel `(z,y,x)`** | every other v2 structure table's `z,y,x` are voxel and `COORD_COLUMNS` carries no unit tag, so a µm mesh would be the only geometry whose *meaning* depends on calibration not captured in the layer. Keeps the µm↔voxel flip inside computes behind `ctx.calib`, where the memo fence already lives, and makes a vertex row Point-schema-compatible. |
| Concave rasterization | **fix it, inherited from provenance** | `alpha_shape` used to fill its **convex hull** (see §4) while reporting concave `volume_um3`. Now the interior test is derived from the mesh's stamped provenance — no user lever (the `rasterize_field` §7b precedent). |
| Old `analysis.tessellate_volume` | **deleted** | two clean primitives; a saved graph containing it no longer loads. |
| Viewer | **a real Mesh overlay, now** | the intermediate wire is meaningful on screen by itself. |

Judgement calls not escalated: **triangles only** (a face row is `v0,v1,v2`; every producer
in the repo emits `(Nf,3)`, and the layer sub-key convention keeps an n-gon `L/corner`
stratum purely additive later); element `id` **dense per `(m,t,c)`** matching `_label_table`
plus a global `element_uid` foreign key; **no transfer bridge** registered.

## 2. Storage — three flat CSR strata under one domain

`Domain.MESH = "mesh"` is the **eleventh** domain: non-lattice (absent from `_LATTICE_AXES`
— the omission *is* the declaration) and a member of `STRUCTURE_DOMAINS`, which is the single
edit that unlocks `is_structure`, the Spreadsheet panel and CSV/Arrow export with zero GUI code.

Blender splits mesh data across POINT/EDGE/FACE/CORNER because a mesh has several array
**lengths**. One domain was the requirement, so the lengths ride the second axis the store
already provides — the `layer` string in `LayerKey = (Domain, layer, name)`:

```
(MESH, "L",      *)  → K   rows, one per ELEMENT (one closed surface)
(MESH, "L/vert", *)  → Nv  rows, the vertex pool
(MESH, "L/face", *)  → Nf  rows, the triangle pool
```

Verified prerequisite: nothing in `nodegraph/` or `nodelab_v2/` splits, prefixes or
path-parses a `.layer` string, so `/` is free as a reserved separator (`validate()` refuses a
base name containing it). Each bucket is internally uniform-length, so `StructureTable.n`
stays meaningful, `to_arrow()` works per bucket, and the Spreadsheet renders three clean
tables instead of one ragged one.

- **element**: `id, element_uid, m, t, c, z, y, x, src_label, vert_start, vert_count,
  face_start, face_count, volume_um3, surface_area_um2, density, n_points, closed`
- **vert**: `id, element, m, t, c, z, y, x` (voxel coords — Point-schema-compatible)
- **face**: `id, element, m, t, c, v0, v1, v2` (**global** vertex indices; no centroid — a
  face row is topology, the one documented `COORD_COLUMNS` exception)

`start`+`count` rather than a Blender-style `(K+1)` offsets array precisely so *every*
element column is length K; `np.concatenate([[0], np.cumsum(vert_count)])` recovers Blender's
offsets in one line. `src_label` preserves the original upstream cluster/region id, which the
fused node destroyed when it densified.

**Flat fixed-width arrays are a correctness requirement, not tidiness.** `memo._canon` hashed
an ndarray via `ascontiguousarray(...).tobytes()`, which for **object dtype** is `PyObject*`
pointer bytes — reproduced in this repo: two identical-content object arrays digest
differently (a permanent memo miss), and distinct content can collide once CPython reuses a
freed pointer slot (a wrong payload served). `_canon` now **raises `TypeError`** on object
dtype, which is what makes the flat-column contract enforceable rather than prose. It also
protects `payload_bytes`, which reports 8 bytes/element for object dtype and would let a mesh
evade the GUI's 1 GiB memo cap.

`nodegraph/mesh.py` owns the domain: `MeshElement` (producer value type) → `build_mesh_tables`
(concatenation, global-index rebasing, CSR bookkeeping, derived `closed`) → `with_mesh` (the
**only** sanctioned write path; calls `validate()` unconditionally) → `read_mesh` /
`mesh_element`. `validate()` is the *entire* enforcement mechanism, because
`Dataset.with_attribute` gates its only shape check on `is_lattice` and therefore gives a
non-lattice layer zero validation (two layers of different lengths coexist on one layer key
without complaint — asserted in the selftest).

## 3. The two nodes

**`analysis.tessellate`** (analysis; adds MESH; WHOLE_VOLUME, `kernel_axes={z,y,x}`, `z<2`
raises). One four-choice `boundary` lever selects source *and* algorithm: `convex_hull` /
`alpha_shape` (finite `alpha_um`) / `voronoi` consume the `points` layer's `cluster` column;
`label_surface` marching-cubes the `labels` Voxel raster. One mode rather than a
`source` × `boundary` pair because `available_in` gates *sockets* on modes but nothing gates a
*mode* on another mode — a separate source lever would leave three selectable-but-meaningless
combinations. This is how "points **and** labels as input" lands. `merge_tol=0` keeps the
general-primitive contract (one element per input label). `reads_domains` is empty on purpose
(POINT in three modes, VOXEL in the fourth, and `reads_domains` has no per-mode form — the
`track.objects` / `boundary_band` precedent); the compute raises naming the exact layer to wire.

**`transform.rasterize_mesh`** (transform, beside `rasterize_field`; reads MESH+VOXEL, adds
VOXEL+LABEL — the same output contract the fused node had, so `boundary_band` / `measure`
chains are unchanged). Params `smooth_um, min_voxels, fill_holes, name` moved here;
`alpha_um, min_points` went to tessellate. ids are painted **verbatim**, so an element that
voxelizes empty leaves a gap instead of shifting every id after it, and the Label table gains
`voxel_count` (the realized volume, next to the analytic `volume_um3`).

`analysis.tessellate_volume` is **deleted** — a saved `*.nd2graph.json` containing it will
fail to load.

## 4. The latent bug this fixes

`granule_tessellate.py:211` stores the **unfiltered** `Delaunay`: the alpha filter `keep` is
applied only to `volume` and `faces`. The union of a Delaunay triangulation's simplices is
exactly the convex hull of its points, so the downstream `find_simplex(...) >= 0` has always
been a **convex-hull membership test in every mode** — `alpha_shape` reported concave
`volume_um3`/`surface_area_um2` and rasterized to the convex hull. Both kernel `.md` docs
claim the opposite.

Corollary: dropping the live Qhull object at the node boundary costs **nothing but one
re-triangulation** — `_build_delaunay(verts)` calls `Delaunay` on the identical point set.

`kernels/mesh_raster.py` fixes it. Both interior tests go through the **vendored**
`build_granule_masks`, which is duck-typed on `.boundaries`/`.vertices_um`/`.delaunay`/
`.density` — so a one-method `find_simplex` shim drops in with **zero kernel edits** and
inherits the bbox walk, µm SDF smoothing, hole filling and small-component removal. That also
avoids re-deriving the kernel's index rule (voxel `(z,y,x)` has world centre
`(x*dx, y*dy, z*dz)`, `_Z0_UM = 0`, **no half-voxel offset**) — the easiest place to ship a
half-voxel shift.

- `mode="convex"` → `delaunay=None`, kernel builds its own: bit-for-bit the old behaviour.
- `mode="watertight"` → `FaceParity`, an even-odd ray-cast along +x over the **faces**.

Even-odd parity is **orientation-independent**, which is required: `_boundary_faces` keys on a
sorted vertex triple but stores the raw unsorted one, and `ConvexHull.equations` is discarded,
so winding is arbitrary — a signed/generalized winding number would silently mis-fill without
an orientation-repair pass first.

**Three epsilons, not two.** Mesh vertices routinely sit on integer grid lines (marching cubes
puts them there) while the sample points *are* the integer lattice, so exact hits are the
common case: in `(z,y)` a ray through a shared edge is counted by both triangles and flips
parity for the rest of the row, and along `x` a sample exactly on a face is decided by float
noise (a face at x=6 interpolates to `6.000000000000001`). Nudging all three axes by mutually
incommensurate offsets makes every such case unreachable. The resulting convention is
**half-open** at surfaces — inherent to parity, which cannot include both the near and far
face of one solid — and differs from the convex path's closed test by at most one voxel layer
on lattice-aligned faces.

Interior test selection is **derived, not asked**: `interior_test_for(provenance, closed)`
reads the `__mesh_provenance__` stamp (`boundary`, `source`, `src_layer`, `voxel_size_um`) and
falls back to the mesh's own derived `closed` column, so a hand-built mesh still resolves.

## 5. GUI

`nodelab_v2/overlays.py` already had a **reserved `mesh` tab** (`implemented=False`,
"v2 has no mesh domain yet"). It is now live:

- A 3-D surface has no single 2-D picture, so the overlay draws its **cross-section at the
  viewed Z** — `mesh_section()` intersects each triangle with the plane and `_chain_segments()`
  chains the segments into loops (endpoints matched on a *quantized* key, because the two
  triangles sharing an edge can compute the same crossing in a different operand order and
  differ in the last bit). Styles: outline / filled (closed loops only — filling an open
  polyline would invent an edge the mesh lacks) / vertices-near-Z.
- `viewer._mesh_sections()` walks the store directly rather than via `read_mesh`, so a
  partially-written or foreign mesh can never raise inside a paint call.
- **`nodelab_v2/theme.py:67` hardened**: it was `{d: c(DOMAIN_COLOR[d]) for d in Domain}` —
  the only site in the GUI that iterates the whole enum, and it subscripted. A new member
  without a `DOMAIN_COLOR` entry raised `KeyError` at *import*, taking the whole window down
  before it could draw. Now `domain_color(d)` (Global-grey fallback). The `DOMAIN_COLOR` entry
  (`#b06ad8`, closing the warm structure arc orange→red→magenta→violet) is added anyway.

Everything domain-generic — socket rail, wire tint/stripes, tooltips, missing-domain chips,
palette, inspector, save/load, Spreadsheet, CSV/Arrow — works untouched.

## 6. Deliberate non-edits

`dataset.py`, `structure.py`, `registry.py`, `graph.py`, `engine.py`, `provider.py`,
`streaming.py`, `serialize.py`, `field.py`, `bridges.py`, `metadata.py` — **zero changes**.
Reasons worth recording so nobody "helpfully" adds a MESH branch:

- `dataset.py` / `structure.py`: `StructureTable` is generic over its domain; `_zkind_key`
  keys on domain+layer, so three `with_structure` calls stamp three independent
  `__struct_zkind__` entries for free.
- `serialize.py`: `Domain` round-trips by `.value`; a new member needs nothing.
- `field.py`: already raises for any non-lattice→non-lattice transfer.
- **`transfer.py` / `bridges.py`: NO bridge is registered.** `_neighbours(MESH)` stays `[]`,
  so `plan_transfer` raises a clean plan-time `ValueError` in both directions rather than
  routing through the lattice mega-edge into a hop the chained executor cannot run. Same
  locked precedent as `boundary.fill_boundary` (V2.03 §4 C4 decision 6: a constructive
  geometric op is an explicit data-layer node, never an auto-routed routing edge). The one
  `transfer.py` edit is unrelated hygiene: `d is FRAME and s in (LABEL, POINT, TRACK)` →
  `is_structure(s)`, removing a hardcoded member list from a catch-all.

## 7. Known costs

1. `Domain.MESH` no longer answers "how long is an array on this domain?" — the length depends
   on the layer sub-string, and that invariant lives in `MeshTables.validate()` plus a naming
   convention rather than in the type system.
2. `SocketSpec.domain` names a single Domain, so a future mesh-*field* consumer cannot
   distinguish per-vertex from per-face without a `part` Mode. Moot today.
3. A single `(MESH, VOXEL)` `_BRIDGES` key could not express "faces→voxels" vs
   "verts→voxels" — another reason not to register one.
4. The Spreadsheet's Domain combo shows three rows per mesh (`mesh · L`, `mesh · L/vert`,
   `mesh · L/face`) rather than one mesh with a part sub-picker.
5. `Dataset.reshaped_axes` revalidates only lattice layers, so a crop/resample downstream of
   tessellate leaves vertex coordinates stale in voxel space with no error. Shared with POINT
   and LABEL — but a mesh *looks* geometric, so users will assume it follows the image.
6. A `label_surface` mesh of a real segmentation is large (marching cubes on a 512³ label
   volume ⇒ 10⁵–10⁶ vertices per region) and `payload_bytes` now counts every byte honestly,
   so the 1 GiB GUI memo cap will evict. `decimate` is the mitigation.

A later split into four enum members (`MESH`/`MESH_VERT`/`MESH_FACE`/`MESH_CORNER`) fixes 1, 2
and 4 and is a mechanical rename — `(MESH,"L/vert",*)` → `(MESH_VERT,"L",*)` — with no change
to any producer's array layout. Keeping the sub-layer strings is what holds that door open.

## 10. Addendum 2026-07-28 — `analysis.extract_boundary` socket + domain-rail fix

Chasing the (now-retracted) §9 mesh bullet turned up two real defects in that node. Both
are fixed; the mesh output was deliberately **not** built.

**Defect 1 — params the compute reads but no socket exposes.** `_compute_extract_boundary`
had always read a `labels` (source Voxel layer) param and an output-name param, but
`register_node` declared **only** `InDataset()`. The engine does not filter params against
the socket list, so this was invisible headlessly — but the GUI builds its widgets from
`inputs`, so both were permanently pinned to their defaults and the node could not outline
a Label raster that wasn't named `labels`. Now `InString("labels", …, default="labels")`
and `InString("name", …, default="")`, the latter following the `analysis.accumulate_field`
convention where **empty means auto-derive**, so the default output layer stays
`f"{labels}_boundary"` and existing graphs are unaffected. The output param was renamed
`out` → `name` (the catalog-wide convention, 16 other nodes) with no fallback: `out` had no
socket, so nothing in this system could ever have written it.

**Defect 2 — empty domain rail.** `reads_domains`/`adds_domains` were both `frozenset()`
though the node hard-requires a Voxel raster and adds POINT — an identical contract to
`detect.spots`, which declares them. The GUI therefore drew no domain chips and no red
missing-domain validation on this node. Now `reads={VOXEL}`, `adds={POINT}`.

**Coverage.** The node's only test was one all-defaults 2D pull (`selftest.py`, `catalog
(batch 2)`) — which is exactly how this survived. Extended with the 3D surface-vertex path
(never exercised before), both socket redirects, the auto-derive fallback, a re-key check,
and the rail/socket-set assertions. **Measured which of those actually guard the fix** by
re-running each against a re-registered pre-fix node: the behavioural pulls all *pass*
against the old code (undeclared params still reach `ctx.params`), so only the `name`
rename, the domain rail, and the socket-set assertion are real guards. The test says so in
a comment, because a guard that passes against the bug it names is worse than none.

**Systemic finding (NOT fixed — needs a scoping decision).** An AST sweep of all 55 node
types for the defect-1 pattern (`ctx.params.get("X")` with no socket `X`) flags **20**.
Two verified-benign categories: **machine-set** params (`channel.select`'s `channels`, set
by `nodelab_v2/ops.py:102` when materializing per-channel taps — by design) and
**back-compat aliases** (`util.resample`'s `scale`, read only as a fallback inside
`scale_xy`'s lookup). The rest look like the same real defect, the worst being
**`transform.transfer_domain`, whose four functional params — `from_domain`, `to_domain`,
`attr`, `reducer` — have no sockets at all**, so from the GUI it can only ever transfer
`mask` from voxel→frame with `mean`. Others of note: `analysis.label` (`mask`, `name`),
`analysis.measure` (`labels`, `stats` — the multi-stat selector), `analysis.watershed`
(`mask`, `name`), `track.link` (`labels`, `points`, `name`). Audit script:
`scratchpad/param_socket_audit.py`. Worth a dedicated pass; each node needs its own
by-design-vs-defect judgement, so this was not swept up here.
