# V1.13 — Row-flush, center-aligned layout

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.13

## Goal

V1.12's pure physical layout placed tiles at their exact stage-XY
pixel offsets. That's faithful to metadata, but the user's Well3
scan steps in X by **3519 µm = 2 tile widths** within each row, so
consecutive tiles in a row leave a tile-sized empty column between
them — visible as "horizontal spacing" in the stitched output.

The user wants tiles **flush against each other** while still
respecting the row structure (Y) and the overall ROI shape.

## What's actually in the file

`Well3_ChannelCy5,TD_Seq0000.nd2` is a hex-staggered scan. Row 5 has
tiles at columns `{1, 3, 5, 7, 9, 11}` (every odd col), row 4 at
`{2, 4, 6, 8, 10}` (every even col), and so on. Within each row,
adjacent tiles are 2 tile widths apart in X. The pattern overall
forms a 13-row diamond with row widths [2, 3, 5, 5, 6, 6, 7, 6, 6,
5, 5, 3, 2] = 61 tiles.

V1.12 honors those X positions literally → 7×13 = 91 visible cells
with 30 empty cells between tiles. V1.13 collapses each row's
tiles flush, eliminating the internal gaps but keeping row
membership and ROI shape.

## Approach

### 1) Cluster Y into rows

Reuse V1.6's `_cluster_axis()` with a per-axis sanity cap of
half the tile size in µm. Y clustering picks up the row structure
even if individual tiles within a row have ±sub-µm Y jitter.

### 2) Within each row, sort tiles by stage X (left-to-right physically)

```python
rows = defaultdict(list)
for i, m in enumerate(m_indices):
    rows[row_idx[i]].append(i)
for r in rows:
    rows[r].sort(key=lambda i: (xs[i], m_indices[i]))
```

Tiebreak by M index — keeps revisits at identical (x, y) in scan
order.

### 3) Place tiles flush within each row, center the row

```python
max_per_row = max(len(rows[r]) for r in rows)
canvas_w = max_per_row * tile_w
canvas_h = n_rows * tile_h

for row_idx, m_list in rows.items():
    n_in_row = len(m_list)
    leading = (max_per_row - n_in_row) // 2     # center
    for col_in_row, i in enumerate(m_list):
        offsets[i] = (row_idx * tile_h,
                      (leading + col_in_row) * tile_w)
```

Each row centered → diamond / oval ROI shapes look symmetric.
Y still flipped: highest stage Y → row 0 (top of image).

### 4) Stay tolerant of partial metadata, fall back to grid if no XY

V1.11's `m_indices = m_indices[:len(stage_xy_um)]` truncation is
preserved. Empty stage_xy → grid_fallback as before.

## What V1.13 does for each real case

- **Well3 (61 multipoints, hex-staggered)**: 7 cols × 13 rows
  canvas. Row 6 (widest, 7 tiles) fills full width. Rows above/
  below progressively narrower, centered. No internal gaps. ROI
  diamond shape preserved.
- **Well2 (68 multipoints, 17 unique Y × 4 visits)**: 17 row
  clusters. Each row contains 4 multipoints at identical (X, Y),
  sorted by `(X, M)`. Tiebreak places visits in M order. Layout =
  4 × 17, centered (= same as full width since every row has 4).
- **Diagonal scan (M=0..N at increasing X *and* Y)**: each M lands
  in its own Y cluster → 1 tile per row → 1-col layout per row.
  Diagonal pattern shows up as the natural row structure.
- **Dense regular mosaic** (4×17 with every column populated):
  every row already has the same number of tiles → row-flush =
  V1.12 placement. No regression.

## Key Decisions

1. **Sort within row by stage X** rather than M index. Serpentine
   scans (alternating direction per row) get a consistent
   left-to-right layout regardless of scan direction.
2. **Tiebreak by M index.** Identical-XY revisits stay in scan
   order, which is the most useful arrangement for stepping through
   them with the M slider.
3. **Center each row** instead of left-aligning. ROI shapes
   (diamond, oval, irregular) are visually symmetric, which is what
   the metadata implies.
4. **Half-tile-height Y tolerance.** Avoids merging adjacent rows
   while absorbing sub-µm stage jitter — same proven heuristic V1.6
   used for clustering.
5. **`source = "row_flush"`.** Distinct label so the GUI diagnostic
   can communicate the algorithm being used.

## Validation

Synthetic tests for each representative case:
- Well3's exact 61 (X, Y) values — confirm 7 × 13 layout, 61 unique
  offsets, row widths [2,3,5,5,6,6,7,6,6,5,5,3,2], centering.
- Well2 (17 cells × 4 visits) — confirm 4 × 17, 68 offsets,
  visits in M order within each row.
- Diagonal 9-tile scan — 9 rows × 1 col.
- Dense regular 4 × 17 — 4 cols × 17 rows, identical to V1.12.
