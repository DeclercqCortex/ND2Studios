## 2. Mesh vs existing domains — the decision (user Q, my analysis)

**Is a mesh more efficient, and how does it differ from existing domains?**
- A mesh (vertices + **faces**) is compact + carries exact geometry (analytic
  `enclosed_volume_um3`, `density`, surface `faces`) that voxel rasterization quantizes. But
  everything downstream today is raster/label-based (boundary bands, per-region intensity,
  overlap all need the Voxel Label volume), so you rasterize + store it regardless — the
  mesh's win only lands if the *products* are geometric (surface area, 3-D surface render,
  mesh export), and v2 has **no 3-D surface viewer** (the 2-D plane compositor can't show it).
- **The irreducible new thing a mesh adds is FACE/topology** — no v2 domain
  (VOXEL/LABEL/POINT/TRACK) encodes it. vertices≈POINT, "which vertices→which region"≈a
  Label-over-Points grouping, the filled region≈Voxel Label — all exist. So "labels with
  centroids" captures *where* + members but not the surface; recovering volume/area needs
  re-tessellation. A mesh domain would also need memo/fingerprint over vertex+face arrays, an
  (x,y,z)-µm convention (kernel vertices are x,y,z vs v2's z,y,x), dropping the live scipy
  `Delaunay`, mesh→voxel + mesh-measure nodes, bridges.

**Chosen (user):** keep existing domains — the fused node emits a **Voxel Label raster + a
Label geometry table** carrying the mesh's ANALYTIC attributes as columns (no quantization
loss on those numbers), mesh stays internal to the compute. **Defer a real MESH domain** until
a geometric consumer (3-D surface viewer / mesh export) needs the faces — then it's a clean,
self-contained addition.

## 3. `analysis.tessellate_volume` — the fused node (V2.06 §3.B closed)

Fuses the vendored `granule_tessellate` + `granule_volume_mask` (the mesh intermediate is not
a v2 domain, so it never leaves the compute — §2). **General:** consumes ANY labeled Point
cloud; the granule density-**merge is OFF** (`merge_tol=0`) so input labels map one-to-one.

- **In:** the `source` Point layer + its `labels` per-point cluster-id column. **Out:** a
  Voxel **Label raster** (`name`, default `labels`) + a per-label **Label table**
  (`id,m,t,c` + centroid `z,y,x` voxels + analytic `volume_um3, density, n_points,
  surface_area_um2`). reads POINT, adds VOXEL+LABEL.
- **Boundary** mode: `convex_hull` (default; alpha=∞) / `alpha_shape` (finite `alpha_um`,
  concave) / `voronoi`. Params: `alpha_um, smooth_um, min_points, min_voxels, fill_holes`.
- **3D-only** (tessellation is volumetric): `WHOLE_VOLUME`, `kernel_axes={z,y,x}`, `z<2` is a
  hard error. `voxel_size_um=(z_step_um, pixel_size_um, pixel_size_um)` via `ctx.calib`
  (fenced). Per-boundary voxelization (reuses the vendored inside-test) → raster + table share
  **dense 1..K ids** by construction (ascending-original-label order, raster-canonical);
  overlap painted higher-density-wins.
- **Chain:** `detect.particles → cluster_points → tessellate_volume → boundary_band / measure`.
  Testable NOW with synthetic Points+labels (cluster_points is sklearn-gated — labels can come
  from anywhere). z_kind stamped subpixel (§7b).

## 5. `analysis.cluster_points` wired — the granule chain is fully live (2026-07-26)

**scikit-learn was already installed (1.9.0)** — the handoff's "ABSENT" note was stale. So the
gated `cluster_points` stub was replaced with the **real compute** (ports `granule_cluster`):
an unlabeled 3-D Point cloud → a per-point **cluster-id column** via a full-covariance
GaussianMixture (`gmm`, keeps anisotropic clusters whole) or spherical `kmeans`, model order
`k` chosen by a **BIC sweep** over `n_clusters ± relax_pct%`. Points scaled to µm
(`voxel_size_um` via `ctx.calib`, fenced) so anisotropic Z doesn't bias the fit; clusters each
`(m,t,c)` group independently (ids `0..k-1` per group — the natural key for `tessellate_volume`,
which also groups by `(m,t,c)`). Adds the column with `with_layer(POINT, name, …, layer=source)`
so the source's z_kind provenance is untouched (no clobber). reads POINT, adds POINT; footprint
WHOLE_VOLUME / `kernel_axes` empty (no image access). The only remaining dep-gated stub is
`analysis.dic_correlate` (needs `al-dic`).

**The whole granule chain now runs end-to-end:** `detect.particles → cluster_points →
tessellate_volume → boundary_band / measure`. Selftest group **`cluster points (V2.07)`**
(recovers 2 planted clusters, relax=0⇒k=2; z_kind kept; calib fenced; gmm≠kmeans re-keys; chains
into tessellate_volume) — **46 groups**; parity clean; GUI ALL PASS; catalog **52** (cluster_points
moved stub→real, no count change).
