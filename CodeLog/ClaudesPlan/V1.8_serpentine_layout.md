# V1.8 — Serpentine layout for multi-cycle acquisitions

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.8

## Goal

When an ND2 file's M axis encodes "visits / cycles" of the same
physical positions (V1.7 detected this), the V1.7 horizontal-expansion
layout was misleading: it kept the (wrong) spatial X axis with only
2 unique values and put M=0 at the bottom because of the Y flip.

The user's expectation — and the McGhee-Lab convention for these
acquisitions — is a **serpentine** scan: M=0 at the top-left, row 0
goes left-to-right, row 1 goes right-to-left, alternating to the
bottom. V1.8 switches to that layout when revisits are detected, and
keeps V1.7's physical layout for unique-position mosaics.

## Approach

### 1) `_serpentine_layout(n_tiles, tile_h, tile_w, n_rows_hint)` helper

```python
def _serpentine_layout(n_tiles, tile_h, tile_w, n_rows_hint):
    n_rows = max(1, int(n_rows_hint))
    n_cols = (n_tiles + n_rows - 1) // n_rows  # ceil
    offsets = []
    for m in range(n_tiles):
        row = m // n_cols
        col_in_row = m % n_cols
        col = col_in_row if (row % 2 == 0) else (n_cols - 1 - col_in_row)
        offsets.append((row * tile_h, col * tile_w))
    return StitchLayout(...)
```

- **Rows = number of physical Y clusters** from V1.6's clustering.
  For the user's file: 17 distinct Y values → 17 rows.
- **Cols = ceil(N / rows)**. For 68 tiles in 17 rows: 4 cols. Matches
  the user's mental model of 4 visits to a 17-position scan path.
- **M=0 at row=0, col=0** (top-left).
- **Even rows L→R, odd rows R→L** (boustrophedon).

### 2) Plug into `compute_tile_layout`

After clustering and assigning M's to `(col_idx, row_idx)`, count
duplicates per cell. **If `max_dup > 1`, invoke `_serpentine_layout`
with `n_rows_hint = n_phys_rows`** instead of V1.7's horizontal
expansion. Source label becomes `"serpentine"`.

For files where every M is unique (true mosaic), keep V1.7's
physical layout — `source = "stage_xy"`.

### 3) Diagnostic update

Import-page "Tile source" row gains a serpentine variant:

- `"68 of 68 from stage XY"` — physical layout, every M unique.
- `"68 multipoints → 17 unique cells × 4 visits → serpentine 4 × 17 layout (M=0 top-left)"` — revisit case.
- `"grid fallback (no stage XY metadata)"` — no XY data.

## Why serpentine, not horizontal expansion

- V1.7's expansion keeps the (often degenerate) X axis. For the user's
  file there are only 2 X positions but 4 visit cycles — the expanded
  layout was 8 visual cols with 4 of them empty per row, which made
  the zigzag look like the "real" structure when it wasn't.
- The user's intent for navigation/preview is "see all 68 tiles in
  scan order with M=0 at top-left." Serpentine matches that exactly.
- A genuine mosaic (every M unique) still benefits from the V1.7
  physical layout because there's real spatial structure to show.

## Key Decisions

1. **Trigger serpentine on `max_dup > 1`.** That's the unambiguous
   signal that the file has revisits and the M-axis encodes scan
   order rather than independent positions.
2. **Use n_phys_rows as the row count.** Reflects the file's actual
   Y structure; falls back to `ceil(sqrt(N))` if Y clustering is
   degenerate.
3. **M=0 at top-left.** Convention from the user's scan setup;
   matches typical microscope-acquisition UIs.
4. **Same serpentine drives stitch export.** A scan-order contact
   sheet is the most useful artifact when you've got revisits.

## Validation

Synthetic test against the exact user file:

- 17 stage XY positions × 4 cycles = 68 multipoints.
- After V1.8: layout is 4 cols × 17 rows, source = `"serpentine"`.
- M=0 at (row=0, col=0): `offset = (0, 0)`.
- M=3 at (row=0, col=3): `offset = (0, 3 × tile_w)`.
- M=4 at (row=1, col=3): `offset = (tile_h, 3 × tile_w)` (right end of
  reversed row).
- M=7 at (row=1, col=0): `offset = (tile_h, 0)` (left end).
- M=8 at (row=2, col=0): `offset = (2 × tile_h, 0)`.

Regression: regular 4×17 mosaic with all unique positions still uses
V1.7 physical layout, source = `"stage_xy"`.
