# V1.27 — Multi-file Z-stack import

## Goal

Allow the Import page to load **multiple ND2 files together** when each
file contributes the full M (multipoint) range for a **single Z plane**.
The result is a virtual `(M, T, Z=n_files, H, W)` volume that the viewer,
recipe pipeline, and exporters see as if it were one file.

Motivating dataset (`F:\ELISA_in_LLS_Density_Test\20260515_112707_675\`):

- 76 files named `WellA1_ZStack0000_ChannelCy5_Seq0000.nd2 … ZStack0075_…`
- Each file: `sizes = {P: 77, Y: 2048, X: 2048}`, dtype uint16, channel Cy5.
- One Z plane per file. Z-coord in the per-event metadata advances ~8 µm
  between files (5640.14 → 5648.18 → …), giving the combined Z step.
- Stage XY (per-P) is identical across files — the same physical tile
  grid, sampled at successive Z planes.

The user described the input as "TIFFs" but the actual files are ND2.
This plan covers the ND2 case; the same shape applies if/when the lab
delivers TIFF-per-Z and can be added as a separate path later.

## Approach

### New classes (`backend/nd2_volume.py`)

`LazyMultiFileND2Volume`
- Wraps a sorted list of single-Z `LazyND2Volume` objects (one per file).
- File ordering = `sorted(paths, key=os.path.basename)` — matches the
  `ZStack####` filename convention.
- Validates that `(M, T, C, H, W)` matches across files; raises with a
  clear diff if not.
- `n_zslices = len(files)` (each child volume contributes one Z plane).
- Mirrors the `LazyND2Volume` public surface used by the viewer,
  prefetch worker, exporters, and recipe pipeline:
  `shape`, `n_multipoints`, `n_timepoints`, `n_zslices`, `n_channels`,
  `height`, `width`, `dtype`, `pixel_size_um`, `z_step_um`,
  `channel_names`, `filepath`, `get_frame(...)`, `to_lazy_channel(...)`,
  `all_channels_as_lazy(...)`, `close()`, `reopen()`.
- Adds `filepaths: list[str]` so consumers that need to rebuild a fresh
  volume on a worker thread can do so without losing the multi-file
  identity (prefetch factory, batch worker).

`MultiFileLazyZChannel`
- Same `(T, H, W)` numpy-protocol surface as `LazyND2Channel`
  (`shape`, `dtype`, `ndim`, `__len__`, `__getitem__`, `__array__`,
  `materialize`, `copy`, `crop`, `close`).
- For `z_mode='none'`: returns frames from one specific file by
  delegating to that file's `LazyND2Channel`.
- For `z_mode in {max, mean, min}`: reads `(c, m, t, z=0)` from every
  file at the chosen T and reduces across the file axis. This is the
  "max-project across the Z-stack" the user wants on Confirm Import.

### `reopen()` on both volume types

Add `reopen()` returning a *new* volume that wraps the same file(s).
Use it in:
- `MultiAxisViewer.set_volume()` prefetch factory (currently
  `LazyND2Volume(volume.filepath)`).
- Any future worker that needs an isolated read handle.

This makes the prefetch worker format-agnostic — it doesn't need to
know whether the source is one file or many.

### `backend/nd2_loader.py` — collage metadata reader

`read_nd2_metadata_extended_multi(filepaths)`
1. Run the existing `read_nd2_metadata_extended` on the first file.
2. Override:
   - `n_zslices = len(filepaths)`
   - `z_step_um = mean(diff(file_z_coords))` where `file_z_coords[i]` is
     `events[0]['Z Coord [µm]']` from file `i`. Falls back to file 0's
     `z_step_um` if the events lookup fails.
   - `stage_z_um = [file_z_coords[i] for each file]`
   - `filepath = first_path` (kept for compatibility with code that
     reads `meta["filepath"]`).
   - `source_filepaths = sorted_paths` (new key; consumers that care
     about the multi-file nature can read this).
3. Other metadata (stage XY, channel names, exposures, pixel size,
   objective, camera) inherits from file 0 — these are physically
   identical for a Z-stack acquired in one run.

### `workers/load_worker.py`

- Add `filepaths: Optional[list[str]] = None` to `__init__`. When set
  and `len(filepaths) > 1`, the worker takes the multi-file path:
  - Build `LazyMultiFileND2Volume(filepaths)`.
  - Pull metadata via `read_nd2_metadata_extended_multi(filepaths)`.
  - Build channel proxies via `volume.to_lazy_channel(...)` (which uses
    the multi-file projector).
- The single-file branch keeps using `LazyND2Volume(filepath)` and the
  existing per-channel `load_nd2_timeseries_lazy`. No behavior change
  for single-file imports.

### `pages/import_page.py`

- Replace `QFileDialog.getOpenFileName` with `getOpenFileNames`.
- When `len(paths) > 1`:
  - Show `"N files: <first_basename>, …"` in the path label.
  - Pass the list to `LoadWorker(filepaths=paths, ...)`.
- When `len(paths) == 1`: unchanged — single-file path.
- The Confirm/Stitch handling needs no changes — `exp._raw_volume`
  exposes the same interface either way.

### `widgets/multi_axis_viewer.py`

- Switch the prefetch reader factory from
  `lambda fp=volume.filepath: LazyND2Volume(fp)` to
  `lambda v=volume: v.reopen()`.

## Key decisions

- **Ordering:** sorted by basename. Robust for `ZStack####` and any
  zero-padded numeric scheme. No regex parsing — keep it dumb and
  predictable.
- **Consistency check is strict:** if files disagree on `(M, T, C, H, W)`
  the worker fails the import. Better than silently truncating.
- **Z step from events:** we read `f.events()[0]['Z Coord [µm]']` per
  file (one cheap call). If it's missing or non-numeric, fall back to
  file 0's voxel-size Z. Either way the user sees a real number.
- **No mutation of source files.** Multi-file mode is read-only; the
  composite volume holds independent handles per file.
- **Channel names from file 0.** If a downstream file has differing
  names, we don't try to align — the strict consistency check has
  already rejected that scenario.
