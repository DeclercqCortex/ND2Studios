# V1.32 — Export preview dialog + image-sequence exporter

## Goal

Add a live preview to the Movie export flow that lets the user scrub T
and tweak brightness / contrast / saturation / hue / fade before the
encoder runs, and add a parallel **Image Sequence** export tab that
writes one PNG per frame with the same preview + adjustment workflow.
Filename naming must encode whichever of `T`, `M`, `Z` actually vary in
the loaded file (`name_T01_M02_Z03.png`), and only those.

## Approach

1. **Shared adjustment pipeline**. Add a single
   :class:`ImageAdjustments` dataclass and an
   :func:`apply_image_adjustments` numpy helper to
   `backend/exporters/composite_exporter.py`. Apply order is contrast →
   brightness → hue → saturation → fade so the result matches how
   typical photo editors describe these sliders. Plumb it through
   `_composite_frame`, `export_movie`, `export_rgb_composite_tiff` so
   every export path can apply the same adjustments uniformly.

2. **Image-sequence backend**. New
   `backend/exporters/image_sequence_exporter.py` with:
   - `format_frame_name(basename, t, m, z, n_t, n_m, n_z, ext)` —
     pure function, exactly the naming rule the user asked for.
     Suffix is included only when an axis has more than one frame;
     digit width tracks each axis's max index.
   - `ImageSequenceRequest` dataclass.
   - `export_image_sequence(request, progress_cb, status_cb)` —
     side-effecting writer. Iterates `T` from the in-memory channels
     OR `(M, T, Z)` from a `LazyND2Volume`. Composite + adjustments +
     overlays per frame, then `PIL.Image.fromarray(...).save(path)`.

3. **Worker mode**. Extend `ExportWorker` / `ExportRequest` with a
   new `"image_sequence"` mode. `ExportRequest` gains
   `image_adjustments`, `basename`, `iterate_volume`, `raw_volume`,
   `z_mode`, `z_view_index`. Default-None adjustments keep every
   existing export call site behaviour-identical.

4. **Preview dialog**. New
   `widgets/export_preview_dialog.py` :: :class:`ExportPreviewDialog`.
   QDialog with:
   - Left pane: :class:`ImageCanvas` + :class:`ZoomToolbar` + T slider +
     T spin box + **▶ Play / ⏸ Pause toggle** + per-dialog **FPS spin
     box**. The play button drives a second `QTimer` that wraps T at
     the chosen FPS; manually grabbing the slider pauses playback;
     `closeEvent` and `done()` stop the timer so it can't outlive the
     dialog.
   - Right pane: five `_LabeledSlider` rows (brightness ±100, contrast
     ±100, saturation ±100, hue ±180°, fade 0–100%), a "Reset
     adjustments" button, and a "Show overlays in preview" toggle.
   - Footer: standard `QDialogButtonBox` with the OK button relabelled
     to "Export".
   - Internal `QTimer.setSingleShot(True)` debounces slider drags by
     30 ms so we don't recomposite per pixel-step on huge images;
     during playback the tick path renders directly (no debounce) so
     the frame rate stays close to the requested FPS.
   - The dialog never runs the export itself — it only returns
     :class:`ImageAdjustments`. The caller passes those into the
     :class:`ExportRequest` so the actual write stays on the worker.

5. **Export page changes**. `pages/export_page.py`:
   - "Export Movie…" now: open file dialog → build `MovieOptions` from
     the existing widgets → open :class:`ExportPreviewDialog` → run
     worker with the chosen adjustments.
   - New "Image Sequence" tab: "Base name" `QLineEdit` (auto-populated
     from `import_config["filepath"]`), "Iterate all M / Z positions"
     checkbox (auto-disabled when the file has no extra M/Z), live
     summary label, "Preview & Export Image Sequence…" button.
   - Shared helpers: `_movie_options_from_ui`, `_frame_timestamps`,
     `_run_preview_dialog` reused by both flows.

## Key decisions

- **Brightness is per-channel and multiplicative.** The user asked
  for brightness to be "relative to the channel colour" (so a red-
  only channel stays red, not pink) *and* to "enhance signal, not
  background". The composite loop calls
  `_apply_brightness_to_gray(gray, brightness)` *before* mixing the
  channel colour LUT in, implemented as multiplicative gain
  (`gain = 1 + brightness/100`). Gain is the right semantic for
  fluorescence: a background pixel near zero stays near zero
  regardless of the slider, while signal pixels scale up until they
  clip — exactly the "enhance signal" behaviour the user wants. An
  additive offset (the first attempt) lifted the noise floor as
  much as the peaks and washed images out. Contrast, saturation, hue,
  and fade stay on the final RGB because they're "photo look" knobs
  that only make sense on the merged image.
  `ImageAdjustments.is_identity_post_composite()` lets the composite
  pass skip the post-RGB pass when only brightness is dialled in.

- **Fade = blend toward black.** The user chose this over
  vignette/temporal-fade. Implemented as
  `rgb *= (1 - fade/100)` after the HSV adjustments, so it works
  uniformly across movie, image-sequence, and composite TIFF.

- **Image sequence: T-only by default, opt-in to iterate M/Z.** The
  recipe is tuned for one specific (M, Z) view. Re-running the recipe
  per M/Z slice is out of scope for V1.0 of this feature; instead the
  multi-axis path pulls raw frames straight off `LazyND2Volume` and
  documents the trade-off in the checkbox tooltip and changelog. T
  always iterates over current channels (so the recipe is preserved
  in the common path).

- **PNG only.** The user picked PNG over TIFF/JPEG; we use Pillow's
  `Image.fromarray(...).save(...)` rather than tifffile so the per-
  frame writer stays trivial. ND2Studios already depends on Pillow
  transitively via `imageio`.

- **Naming width tracks max axis size.** `format_frame_name` computes
  zero-padding from `len(str(n_axis))` so a 9-frame stack stays at
  `T1..T9` and a 100-frame stack jumps to `T001..T100`. This is a
  pure function so the naming logic is unit-testable in isolation if
  needed later.

- **Preview shares the movie tab's overlay widgets.** The user picked
  the "shared with movie tab" option, so the image-sequence tab does
  not duplicate scale-bar / timestamp / channel-label controls — it
  reads them off the movie tab when building the export request. A
  later iteration can split them if needed.

## Risk / follow-ups

- HSV conversion in `apply_image_adjustments` is a vectorised
  numpy implementation; if profiling later shows it dominating
  preview latency, drop in `cv2.cvtColor` (already a dependency).
- The multi-axis image-sequence path can write a huge number of files
  for big multipoint experiments (M × T × Z). The dialog summary label
  ("Will write N PNG files…") gives the user a heads-up before they
  commit.
- A future V1.33 could let the user pre-apply the recipe to every M
  position before iteration so the multi-axis sequence stays
  recipe-consistent; that requires re-running the recipe per-M and is
  intentionally deferred here.
