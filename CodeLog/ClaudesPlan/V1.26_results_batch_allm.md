# V1.26 — Results & Batch: All-M Position Support

## Goal

Extend the multi-M analysis run introduced in V1.25 to propagate through the
Results tab and the Batch pipeline so that every downstream step sees the full
file, not just position M=0.

## Changes

### Results page (`pages/results_page.py`)

**`_on_compute`** — replaces the single-M `_get_result` call with a full
iteration over every M in `exp.analysis_results[pipeline_name]`:

1. Unwrap the stored value into `results_by_m: Dict[int, AnalysisResult]`
   (handles both old bare-`AnalysisResult` format and new `Dict[int, …]`).
2. For each `(m, result)` pair, call the new `_channels_for_m(exp, m)` helper
   to get the correct per-M channel arrays and pass them to
   `compute_measurements`.
3. When multiple M positions are present, stamp each measurement row with a
   `m_position` column.
4. Aggregate all rows and display in the table.

**`_channels_for_m(exp, m)`** — new helper that:
- If `exp._raw_volume` exists and no recipe has been applied: loads the
  channel for the requested M from the volume using the session's Z mode/index.
- Otherwise falls back to materialising the flat processed/raw channels (M=0).

**`_on_export_masks` / `_on_export_images`** — both now iterate over all M
positions in the stored result dict.  For single-M results the output directory
is unchanged; for multi-M results each position is written into a `M00/`,
`M01/`, … sub-directory so frames don't collide.

### Batch worker (`workers/batch_worker.py`)

**`_process_one`** — after loading M=0 channels with `LoadWorker`, tries to
open a `LazyND2Volume` for ND2 files.  If the volume has more than one
multipoint position, builds a `m_positions` list and loops:

- For M=0: uses the already-materialised `channels_m0` (preserving any
  `t_stride` subsetting that `LoadWorker` applied).
- For M>0: materialises channels directly from the volume and applies
  `t_stride` subsetting manually.
- The recipe is re-applied independently for each M (recipe operates on flat
  `(T, H, W)` data — one application per M is correct).
- Analysis and `compute_measurements` run per M with the correct `m_index`.
- Measurement rows get a `m_position` column for multi-M files.
- Image export subdirectories are suffixed `_M00`, `_M01`, … for multi-M.

## Key Decisions

- **Lazy volume re-use across M in batch**: the `LazyND2Volume` is opened once
  per file and reused across all M iterations — avoids redundant file probing.
- **Recipe re-applied per M**: recipe transforms `(T, H, W)` arrays; sharing
  one processed result across M positions would be wrong for most plugins
  (e.g., normalisation, thresholding).
- **Backward compat**: `_channels_for_m` falls back to flat channels when no
  volume is available, so TIFF files and single-M ND2 files are unaffected.
- **Export dir layout**: sub-directories are only created when there are
  multiple M positions; single-M exports write directly to the chosen directory
  as before.
