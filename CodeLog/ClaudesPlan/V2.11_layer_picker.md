# V2.11 — The layer picker: an edit-time layer catalog + a suggesting socket (2026-07-29)

> **Status: BUILT + all gates green.** Finishes the multi-layer keying UX
> (`CONTEXT_v2_remaining` §6.4) that [`V2.10`](V2.10_param_socket_contract.md) half-solved.

## 0. What was asked, and the correction that reshaped it

V2.10 gave every consuming node a **source-layer socket**, but as **free text** — the user
had to remember and retype `labels`, `mask`, `spots`. The ask was to make those sockets
offer the layers actually present.

V2.10 §5 called that "purely a GUI change" because `propagate_meta` already carried the
layer catalog. **That was wrong, and both docs are now corrected.** `MetaEnvelope.layers`
is declared and never populated — the pass accumulates `domains` only, and the field's one
consumer (`engine.py:501`) just copies it. `CONTEXT_v2_remaining` had it right all along:
it is a stub. The picker needed the catalog **built**, which is core work.

## 1. Two design blockers found before any code was written

**(a) `(domain, layer)` is the wrong key — a Voxel picker would have been permanently
empty.** `LayerKey = (domain, layer, name)`, but the user-facing name sits in a *different
slot per domain family*: `with_layer` leaves `layer=None`, so a lattice layer is
`(VOXEL, None, "mask")` — the name is slot 2 — while `with_structure` files each COLUMN
separately as `(POINT, "spots", "y")` — the layer is slot 1. Keying on
`(domain, LayerKey[1])` collapses every Voxel layer in the graph to `(VOXEL, None)`, and
**Voxel sockets are 10 of the 18 readers**. The new field therefore stores the user-facing
name *per domain* directly, so the projection never arises.

**(b) The layer set is NOT monotone.** `Dataset.reshaped_axes(drop_stale=True)` silently
discards any lattice layer whose array no longer matches the new axes, and five nodes rely
on it (`channel.select`, `util.zproject`, `util.crop`, `util.resample`, `util.stack`). A
naive "input's set plus my writes" rule would offer a `mask` that a downstream Crop had
already destroyed, and the compute would then raise.

The drop rule needed **no per-node declaration**: `reshaped_axes`' condition is exactly
"the shape for this domain changed", and a domain's shape is built from `axes_of`, so
comparing the envelope's own before/after axes reproduces it catalog-wide. Verified both
directions in one graph — a crop drops the Voxel layers (y/x changed) and keeps
`align.drift`'s Frame layers (m/t untouched) in the same pass.

## 2. What was built

**Core (`nodegraph/`).**
* `SocketSpec.layer_in` / `layer_in_mode` / `layer_out` — a STRING socket declares that it
  *selects* a layer in a domain, or *names* one this node creates. `layer_out` is a
  **tuple** because several nodes write one name into two domains (`analysis.label` emits
  both a Voxel raster and a Label table called `labels`). `layer_in_mode` covers
  `transform.transfer_domain`, whose source domain is its `from_domain` lever.
* `NodeSpec.extra_layers(params, modes)` — the escape hatch for the five producers no
  socket can describe: `align.drift`/`registration.stabilize` write the literals
  `drift_y`/`drift_x` with no socket at all; `extract_boundary`/`accumulate_field` derive
  the name from another param; `measure` writes into the layer its READ socket names.
* `MetaEnvelope.layer_names` + `layers_in(domain)`, populated by `propagate_meta` via
  `_layer_names_out`: pass through, drop by axis delta, add this node's writes, de-dup.

**Declarations: 18 read sockets, 19 write sockets, 5 hooks** — the whole catalog.

**GUI (`nodelab_v2/`).**
* `GraphDocument.layer_choices(node_id, socket)` — follows the **primary** Dataset edge
  only. Deliberately not modelled on `input_domains`, which unions every predecessor:
  three nodes take a second Dataset input whose layers must never be offered
  (`measure.raw`, `dvc_field.reference`, `dic_correlate.reference`), and `propagate_meta`
  itself builds the envelope from `dataset_preds[0]`. It never falls back to the node's own
  envelope, which would offer a node the layer it writes itself.
* `InspectorPanel._layer_box` — an **editable** `QComboBox` for `layer_in` sockets.

**Why editable and not a closed dropdown.** The suggestion list is honest but incomplete:
`transform.rasterize_field` invents one Voxel layer per field component from a prefix, and
a consumer can be configured before its producer is wired. A closed list would make those
names unreachable; suggestions-plus-free-text strictly improves on the line edit it
replaces and can never block a valid name. Also worth stating plainly: **on a fresh graph
the picker adds little** — the defaults already line up. It earns its keep on renamed
layers, two instances of the same producer, and staleness across a crop.

## 3. A real bug found on the way: the wheel silently rewrites params

Measured on PySide6 6.10.2: **one** wheel notch delivered to an unfocused `QComboBox`
fires `currentTextChanged`/`textActivated` *and* accepts the event. The inspector is a
fixed-height `QScrollArea`, so scrolling toward a lower row drags the pointer across every
combo above it — each notch rewriting and **pinning** a param the user never touched,
while the panel does not scroll because the event was eaten.

This **pre-dates the picker**: the existing Mode dropdowns (`_mode_row`) have had it since
they were written. `_NoWheelCombo` (ignore the wheel unless focused) now backs both, so the
fix lands on the Mode dropdowns too. Confirmed against a plain `QComboBox` that the bug is
real, not theoretical.

Signal choice also mattered: `currentTextChanged`/`currentIndexChanged` fire while the list
is repopulated and while the user types, so only `activated` (a genuine user pick, never
programmatic) and the line edit's `editingFinished` commit. The completer uses
`PopupCompletion`, not `InlineCompletion` — inline would type-ahead-fill the edit, so
tabbing away would commit a name the user never chose.

## 4. Verification

New selftest group **`layer catalog (V2.11)`**. Its core assertion is not that the rule
looks right but that **the prediction matches reality**: it pulls a fully renamed chain
through the real Engine and asserts every predicted `(domain, name)` is actually on the
payload. That matters because the prediction is a **third copy** of every output-layer
default — the socket default, the compute's inline fallback, and now the envelope rule —
and `propagate_meta` sees RAW params (the engine never default-fills them, which is exactly
why each compute repeats its default inline). Nothing structural keeps the three in step,
so the test does.

Also covered: one socket → two domains; derived and socket-less producers; the
non-monotone drop with Frame surviving the same crop that dropped Voxel; and **totality** —
junk params (`None`, an int, a list) degrade instead of raising, because `propagate_meta`
runs on every keystroke and `document.propagate()` catches only `ValueError`; anything else
would take the window down, and even a caught error blanks every envelope graph-wide.

GUI probe gained **P1**: suggestions from upstream, commit by pick *and* by free text,
never offering a node its own output, and three wheel notches over an unfocused picker
leaving the value untouched and the event unaccepted.

**Gates:** `nodegraph.selftest` ALL PASSED, 52 → **53 groups** (54 → 55 `[ok]`) · parity no
drift · catalog **55** (unchanged) · phase-5 GUI probe ALL PASSED.

## 5. Forward

* `analysis.tessellate.cluster` picks a **column** on the chosen Point layer, not a layer —
  a second picker flavour (the envelope would need per-layer column names). Left free text.
* `rasterize_field`'s component layers stay unpredictable; that is the standing argument for
  keeping the combo editable.
* The picker suggests but does not **validate**: typing a layer that will not exist is still
  only caught at pull time. The envelope now holds everything a red edit-time badge would
  need, alongside the existing missing-domain validation.

## 6. Addendum 2026-07-29 — unification: one resolver, one law, one place to read it

V2.10 and V2.11 each added socket machinery in its own corner. This pass folds them into a
single system so the rules are universal for present and future nodes.

### 6.1 One resolver kills the "third copy of every default"

`registry.layer_value(sock, params)` is now the ONLY place a layer-name socket is resolved
(override → `SocketSpec.default`, `""` counts as unset). Both callers route through it:
`EvalContext.layer(name)` at pull time and `metadata._layer_names_out` at edit time.

All **31 call sites across 24 computes** were migrated from `ctx.params.get("mask", "mask")`
to `ctx.layer("mask")`, so a default now exists in exactly one place — the declaration.
Behaviour is identical (the full suite passed unchanged after the migration). One deliberate
non-migration: `analysis.cluster_points`' `name` is a **column** name, not a layer, and has
no `layer_out` — it keeps the plain read.

### 6.2 One law, seven enforced clauses

`test_param_socket_contract` absorbed the layer checks and gained cross-declaration ones, so
there is a single gate rather than rules scattered over two test groups:

1. every param a compute reads has a socket · 2. every socket is read ·
3. `available_in` names real modes **and real values** · 4. a layer socket is STRING ·
5. `layer_in_mode` names a real mode · 6. **`layer_in` ⊆ `reads_domains`** (exempt when
mode-gated — the requirement is conditional and `reads_domains` has no per-mode form) and
**`layer_out` ⊆ `adds_domains`** (unconditional) · 7. **the default is declared once** — a
compute that still spells its fallback inline is rejected.

**Each clause was verified to bite** by violating it against a re-registered spec and
watching the guard fail — 7/7, restoring clean. A guard that cannot fail is decoration.

Clauses 3, 6 and 7 are new, and clause 6 immediately found a real defect:
**`detect.stardist_nuclei` declared `adds_domains={LABEL}` while writing a Voxel raster
too** — under-declared since it was ported, invisible until the socket's `layer_out` was
compared against it. Now `{VOXEL, LABEL}`, matching `analysis.label`/`watershed`.

The guard also caught the migration itself mid-flight: `ctx.layer(...)` was a read form the
resolver did not know, so all 37 layer sockets briefly read as dead. That is the intended
behaviour of clause 2 and confirms it is live.

### 6.3 The specifications are in the skills

* **`wire-node-v2` §4b "THE SOCKET CONTRACT"** — the five authoring rules, the root hazard
  (params are overrides; the engine never default-fills, so a socket-less param is
  GUI-invisible), and the ordered remedies for a dead control (gate → refuse → delete).
* **`wire-node-v2` §4c "Layer-name sockets"** — `layer_in`/`layer_out`/`layer_in_mode`,
  why `layer_out` is a tuple, the domain-consistency rule and its mode-gated exemption,
  `extra_layers`, and the two traps for anyone touching the catalog (the `LayerKey` slot
  asymmetry; the non-monotone drop).
* **`build-node-v2`** — socket reachability is now part of the §0 grill; the contract is a
  hard §2 gate clause; §3 gained the two migration rules (adding a socket for an
  already-read param is safe; converting a param to a Mode is **not** transparent and must
  refuse the legacy form); the done-checklist and see-also point at §4b/§4c.
* Both skills gained discovery triggers (`socket contract`, `layer_in`, `layer_out`,
  `ctx.layer`, `unreachable param`, `dead socket`).
