## 1. What was wrong

Two complaints, one root cause and one gap.

**(a) Labels were hard to see, and got *thicker* as you zoomed in.** The Viewer had two
overlay painters — one for the GPU surface (widget space) and one for the CPU surface that
**painted onto the image pixmap**. A pixmap-baked overlay is in *image* pixels, so the
view transform magnifies it: a 1 px contour at fit becomes a 16 px slab at 16×, and the
label id under it disappears. The GPU path had the mirror-image problem: it stamped **one
`drawPoint` per boundary pixel**, so zooming pulled those dots apart into a dotted
outline with gaps as wide as the magnification. Colour made it worse — every region was
outlined in the same `theme.INK`, so touching labels read as one blob.

**(b) There was nothing to tune.** Three checkboxes (Points / Labels / Tracks), no size,
no opacity, no colour, no look. Every visual constant was a literal in `viewer.py`
(`4.0`, `1.6`, `T.ACCENT`), duplicated between the two painters, and each new domain would
have added a fourth checkbox to a strip that has ~200 px in the mini-map.

## 2. What was built

### 2.1 One renderer, in widget space (`overlays.py`)

`OverlayRenderer.paint(painter, settings, frame)` is now the **only** overlay painter, and
both surfaces feed it the same contract:

| surface | overlay hook | mapping |
|---|---|---|
| `glview.GLImageView` | `overlay_cb(painter)` after `paintGL` | `plane_to_widget` |
| `viewer._ImageView` (CPU) | `drawForeground` with `setTransform(QTransform())` | `plane_to_widget` = `viewportTransform().map` |

`_ImageView` gained `overlay_cb` / `plane_to_widget` / `refresh` so it is API-identical to
the GL widget. Resetting the world transform inside `drawForeground` puts the painter in
**viewport pixels**, which is what makes every size in the settings a *screen* size.

Two consequences worth stating:

* **`FullViewportUpdate` is now mandatory on the CPU view.** With the default minimal
  update a pan only repaints the scrolled band, while a viewport-space foreground covers
  the whole widget — you would get overlay tearing.
* **`_repaint()` got cheap.** It pushes the composite and asks for a redraw; it no longer
  copies the pixmap and re-draws geometry into it. Toggling an overlay or editing its look
  never re-composites the channels, and `_display` no longer bakes anything.

**Label outlines are segments, not pixels.** A vertical boundary between `lab[i,j]` and
`lab[i,j+1]` is the unit segment `(j+1, i) → (j+1, i+1)` in label-pixel space. Extraction
is vectorized, segments are grouped by colour key (`max` of the two sides, so a
label/background edge takes the label's colour and a shared edge is drawn once,
deterministically), and each group is one `drawLines` batch with a fixed-width pen. The
contour is therefore *continuous at any zoom* and *constant width at any zoom*.

**Sizes: what scales and what does not.** Strokes, glyphs, vertex dots and id text are
screen px and never scale. Region **fills** do scale — a fill *is* the region — and are
drawn as a nearest-neighbour RGBA image so a zoomed label mask stays pixel-crisp
(interpolating distinct label colours would invent regions that are not there).

### 2.2 The looks the user asked for

* **Points — golden star (default).** A bright centre pixel exactly on the detection plus
  arms stepping out in 8 directions, `spread` ∈ 1..5 steps of `unit_px` screen pixels each,
  with a brightness gradient `1 − k/(spread+1)` per step and a white-blended centre
  (`center_boost`). Rendered **once into a cached pixmap** and stamped per point — which is
  both what keeps a 10 000-point overlay cheap and what makes the size zoom-invariant.
  Alternatives: `cross` (+), `diag` (×), `circle`, `ring`, `square`.
* **Points — a different colour per point** (`color_mode="per_point"`, keyed on the layer's
  `id` column so a detection keeps its colour across frames), plus `per_layer`.
* **Labels — a different colour per label** (default), with `outline` / `fill` /
  `outline+fill`, outline width, opacity, fill opacity, and optional id text at each
  centroid.
* **Tracks — a different colour per track, kept over every T frame.** Deterministic
  golden-angle hue from `track_id`, which is *literally the same rule* as labels (§2.3),
  plus width, opacity, vertex/current-T marker radii, `trail` (whole / up-to-T / a window
  of N frames), fade, and id text.
* **Voxels / Mesh tabs** exist, serialize and spread. **Voxels is reserved** — its controls
  are disabled behind a banner rather than presented as live knobs nothing reads, the same
  charter the node catalog holds itself to. (Mesh was promoted to a real tab by the
  concurrent V2.08 mesh-domain work — see §5.)

### 2.3 One palette, one hue→rgb

`_hues_to_rgb` is the single vectorized HSV→RGB used by `distinct_color()` (outlines,
points, tracks) **and** by the per-label fill LUT. A label's fill can therefore never
disagree with its outline about what colour it is, and "each label a different colour" /
"each track a different colour" are the same code path with the same `sat`/`val` knobs.
`viewer._track_color()` survives as a thin delegate (callers/tests).

### 2.4 The popup, and why it is spec-driven

`FIELDS: {tab: (FieldSpec, …)}` describes every setting — kind, range, unit, tooltip,
`enable_if` dependency, and a cross-domain **`role`**. `OverlayDialog` builds all 51
controls from that; there is no hand-written per-tab form to keep in sync. Consequences:

* **`enable_if` greys out rows the chosen mode ignores** (the single `color` swatch under
  `per_point`, `window` under a non-window trail). `_ColorButton` needed its own
  `:disabled` rule — a swatch carries its own stylesheet, so without it a colour the
  renderer ignores would still look live. `theme.controls_qss()` gained `:disabled` rules
  for combos/spins/edits/checkboxes, which improves every panel.
* **"Spread this tab's look to the others" copies by ROLE, not by key** — `opacity`,
  single `colour`, colour-by mode, `line_width`, palette `sat`/`val`, `show_ids`. That is
  what lets width travel from `labels.width` to `tracks.width` **and** `points.thickness`,
  while `labels.style` / `tracks.trail` / `points.spread` are left alone. `color_mode`
  travels as the *notion* "one colour" vs "a colour per item", each tab keeping its own
  spelling (`per_label` / `per_track` / `per_point` / `per_object`). It **reports every
  value it moved**, and says so when a role had nowhere applicable to go.
* **The preview strip is the real renderer.** Each tab previews via
  `overlays.render_preview`, which drives the same `OverlayRenderer` over synthetic
  geometry on a checker (so opacity is readable). If the preview and the image disagreed,
  one of them would be lying.

Non-modal, live: every edit bumps `viewer._ovl_rev`, invalidates the caches and repaints —
no re-pull. Reachable from the **◈ Overlays** button in the display strip (glyph-only in
the mini-map) or **View → Overlays… (Ctrl+Shift+O)**.

### 2.5 Persistence — three layers, later wins

```
built-in dataclass defaults
  → nodelab_v2/overlay_defaults.json   (PROJECT_FILE — commit it to share the look)
    → ~/.nd2studios/overlays.json      (USER_FILE — "Make default" on this machine)
```
`NODELAB_OVERLAYS=<path>` replaces the stack with one explicit file (tests / a lab config).
Files merge as **partial dicts** — an older or hand-edited file only overrides the keys it
names, unknown keys are ignored, and a bad file is reported rather than fatal.
`load_defaults()` returns the list of files it applied, which the popup shows so the
current look always has a stated provenance. Buttons: *Load… / Save… / Make default /
Save to project / Reset tab / Reset all*.

### 2.6 Geometry extraction is cached

A pan repaints continuously and must not re-walk the attribute tables. `viewer.
_ensure_geometry()` caches points / tracks / label plane per
`(id(dataset), coords, ref-plane shape, settings revision)`; `_display` invalidates on
every frame delivery. The fill image and the glyph pixmaps are cached inside the renderer
on top of that, so a pure pan/zoom rebuilds nothing.

## 3. API changes (recorded — the probe depended on the old names)

| before | after |
|---|---|
| `viewer._overlay` / `_label_overlay` / `_track_overlay` (QCheckBox) | `viewer.overlays.<tab>.enabled`, or `overlay_enabled(tab)` / `set_overlay_enabled(tab, on)` |
| `viewer._overlay.text()` == `"Points"` / `"P"` | `viewer._ovl_btn.text()` == `"◈ Overlays"` / `"◈"` |
| `_tracks_here() → (id, path, cur)` | `→ (id, path, cur, times)`; `_track_paths()` returns `TrackPath` objects |
| `_points_here() → [(y, x)]` | unchanged (derived from `_point_marks() → [PointMark]`) |
| `_paint_gl_overlays` | `_paint_overlays` (both backends) |

Deliberately **one** source of truth: the checkbox proxies were dropped rather than kept
in sync with the settings.

## 4. Verification

* `PYTHONUTF8=1 python -m nodegraph.selftest` → ALL PASS (core untouched).
* `python scripts/_pipeline_kit_parity.py --check` → no drift.
* `scripts/_nodelab_v2_phase5_probe.py` → ALL PASS, new **O1–O9**:
  O1 tabs + all spec-driven controls exist + reserved tabs inert (driven off
  `TAB_INFO.implemented`, so promoting a domain needs no probe edit) · O2 `enable_if`
  greying · O3 an edit bumps the revision and repaints without a re-pull · **O4
  zoom-invariance** (same settings at 1× and 4× keeps the ink bounded — 577→1729, not
  16× — and the glyph pixmap byte-identical) · O5 the golden star (monotonic arm gradient
  `[255,191,128,64]`, 8 directions, bright centre) · O6 the palette is distinct, stable
  across T, and fill hue == outline hue · O7 spread copies by role and leaves domain-only
  settings alone, idempotently · O8 file round-trip, partial merge, `NODELAB_OVERLAYS`
  override · O9 dialog save / reset-tab / reset-all.
* **Real windowed run, GPU path** (`[glview] GL ready — OpenGL 3.3`): `overlay_cb` wired
  on `GLImageView`, overlays painted at fit and after an 8× zoom, `grabFramebuffer()`
  showing four per-label-coloured regions with outline+fill, the golden star on its point
  and both track polylines with the current-T vertex enlarged; the popup edits applied to
  the live image; `_gl` still alive afterwards (no `gl_failed` fallback).
  *Gotcha:* grab the GL surface with **`grabFramebuffer()`**, not `QWidget.grab()` — the
  latter can hand back a stale composited backing store and made an early check look like
  the overlays were missing. The process still ends in the known `os._exit` GL-teardown
  segfault, after all output.

**Disclosed limits.** Label outlines are uniformly decimated above
`MAX_OUTLINE_SEGMENTS = 250_000` boundary segments (stated in the Labels tab tooltip and
warned once on stderr); id text is skipped above 400 regions on a plane (hundreds of
numbers is noise, not information); the per-point glyph cache clears past 512 entries.

## 5. Interaction with the concurrent V2.08 mesh work

The **Mesh** tab was created here as a reserved placeholder, per the request ("we will
implement voxels and mesh later, but keep a tab for them"). While this was being built, a
concurrent session landed `Domain.MESH` in `nodegraph/domains.py` and promoted the tab to
`implemented=True`, adding `MeshSection` / `mesh_section()` / `_paint_mesh` to
`overlays.py` and `_mesh_sections()` to `viewer.py` on top of this design. That work is
**not** part of V2.09 and is not reviewed here; the O1 assertion was rewritten to derive
"which tabs are reserved" from `TAB_INFO.implemented` so the two can land independently.
