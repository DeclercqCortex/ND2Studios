# V1.19 — General Analysis Tab

## Goal

Add a 4th page ("Analysis") that provides an extensible framework for running
analysis pipelines on loaded/processed microscopy data. The first pipeline is
nuclei instance segmentation using Cellpose 3.

## Approach

Build a minimal but complete v1: `AnalysisPipeline` ABC + registry,
`AnalysisWorker`, `NucleiSegmentationPipeline` (Cellpose 3), and `AnalysisPage`
with label overlay preview and CSV/TIFF export. No StarDist (TF conflict), no
3D, no cross-validation — those are future work.

## Key Decisions

1. **Separate registry** — `AnalysisPipeline._registry` is distinct from
   `PluginBase._registry`. Pipelines and enhancement plugins are different
   abstractions; mixing them would pollute the Recipe page's plugin list.

2. **`cancelled_cb: Callable[[], bool]`** — passed to `pipeline.run()` so the
   backend can check cancellation between frames without any Qt dependency.

3. **`ParamSpec` reused** — imported from `plugin_registry.py`. The Analysis
   page passes a fresh `get_params()` list into the existing `ParamEditor`
   widget every time the pipeline or channel list changes.

4. **Cellpose optional** — `importlib.util.find_spec("cellpose")` at module
   load. `run()` raises `ImportError` with install instructions; the page
   catches it and shows a `QMessageBox`.

5. **Overlay compositing in the page** — pipelines return raw int32 masks; the
   page colorizes them with a fixed 20-color palette at render time.

6. **`analysis_results` not serialized** — label masks can be hundreds of MB.
   Users export them explicitly. Re-running is fast enough.
