# V1.25 — Analysis: All-M Run, Per-M Overlay, Hide Toggle

## Goal

Three related improvements to the Analysis page:

1. **Run Analysis covers the whole file** — pressing "Run Analysis" now iterates
   over every M position (multipoint) in sequence rather than only the position
   currently visible in the viewer.

2. **Overlays appear on all frames after running** — when navigating between
   frames (T) or positions (M) after a completed run, the binary/label overlay
   is visible for every M that was analyzed, not just the one that was in view
   at run time.

3. **"Hide Overlays" toggle** — a checkable button above the viewer lets the
   user instantly show/hide all overlays (both full-run and screen results)
   without having to change the pipeline or re-run analysis.

## Approach

### Multi-M sequential run

Replace the single-M worker launch with a queue-based sequential pattern:

- `_run_queue: List[int]` holds M indices waiting to be analyzed.
- `_run_total: int` records the initial queue length for progress scaling.
- `_current_run_m: int` tracks which M the currently running worker belongs to.
- `_run_pipeline_cls` and `_run_params` are stored at the start of a run so
  each chained worker gets identical config.
- `_start_next_m_run()` pops the next M, builds channels via the new helper
  `_build_channels_for_m(exp, m, params)`, and launches an `AnalysisWorker`.
- `_on_m_progress(p)` scales the single-worker 0–100 signal into an overall
  `(n_done * 100 + p) / total` value shown in the progress bar.
- `_on_finished` stores the result, updates the overlay immediately so partial
  results appear as each M completes, then either starts the next M or
  finalizes the UI.

### Per-M result storage

Replace `self._result` (single `AnalysisResult`) + `self._result_m` (int)
with:

- `self._results_per_m: Dict[int, AnalysisResult]` — keyed by M index.
- `self._result` is kept as a convenience pointer to the last completed result
  (used by the export functions which always export one stack).

`exp.analysis_results[pipeline_name]` now stores `Dict[int, AnalysisResult]`
instead of a bare `AnalysisResult`.  `_restore_results_from_exp` handles both
formats for backward compatibility.

### Composite overlay change

`_composite_overlay(rgb, t, m)` now does `self._results_per_m.get(m)` instead
of `self._result if m == self._result_m`.  This makes the overlay available for
every M that has been analyzed, automatically.

### Hide Overlays toggle

A `QPushButton("Hide Overlays", checkable=True)` is placed right-aligned above
the `MultiAxisViewer` in the right panel — outside the Pipeline / Parameters /
Run / Screen group boxes.  When checked:

- `self._overlay_visible = False`
- button text changes to "Show Overlays"
- `_composite_overlay` short-circuits to `return rgb` immediately

| `nd2studios/pages/analysis_page.py` | All logic described above |

## Key Decisions

- **Sequential, not parallel**: M positions are analyzed one after another.
  Parallel workers would require either a merge step or per-M result signals,
  adding complexity with no user-visible benefit for typical file sizes.
- **Overlay updates mid-run**: `_update_overlay()` is called after each M
  completes so the user can see partial results while the rest processes.
- **Export unchanged**: Export functions still operate on `self._result` (last
  completed M).  Multi-M TIFF export is future work.
- **Screening unchanged**: The "Screen frame" and "Auto-screen" paths are
  untouched — they remain single-frame only.
