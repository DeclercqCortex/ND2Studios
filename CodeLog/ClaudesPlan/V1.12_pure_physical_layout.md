# V1.12 — Pure physical tile layout (no clustering, no serpentine)

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.12

## Goal

Replace the cluster-based grid layout (V1.6) and all the
serpentine-fallback paths (V1.8 / V1.10 / V1.11 partial-metadata) with
**pure physical pixel placement** keyed on each M's stage XY
centroid. The user spelled out the algorithm:

> Load all M files, record their centroid, identify tile landscape
> based on mapping of centroids, then, establish tile size via image
> size, then generate the tile layout. Some M files are diagonal
> from each other when going from row to row, and sometimes M files
> are uneven, and I need your tile layout to be accurate in relation
> to the metadata.

## Why

Every previous version snapped tiles to discrete column/row centroids
inferred from the data. That works for clean rectangular mosaics but
breaks for:

- **Diagonal scans** — row N and row N+1 have different X positions;
  clustering merges them onto the wrong row or invents extra columns.
- **Uneven spacing** — irregular step sizes get rounded to a uniform
  grid, losing information.
- **Sparse / revisit acquisitions** — V1.7/V1.8/V1.10 introduced
  serpentine fallbacks that fabricate a tidy layout instead of showing
  the actual scan geometry.

The user has explicitly asked for the layout to be **accurate in
relation to the metadata** — i.e. faithful to whatever the stage XY
positions say.

## Approach

### 1) The core algorithm

```python
xs = np.array([stage_xy_um[m][0] for m in m_indices])
ys = np.array([stage_xy_um[m][1] for m in m_indices])

px = ((xs - xs.min()) / pixel_size_um).round().astype(int)
py = ((ys.max() - ys) / pixel_size_um).round().astype(int)   # Y flipped

canvas_w = int(px.max() + tile_w)
canvas_h = int(py.max() + tile_h)
offsets  = [(int(py[i]), int(px[i])) for i in range(len(m_indices))]
```

That's it. No clustering. No tolerance estimation. No bimodal-gap
detection. No serpentine substitution.

### 2) `StitchLayout.source = "physical"`

A single source label for the stage-XY path. The accumulated
sub-modes from V1.6 onwards (`stage_xy`, `stage_xy_expanded`,
`serpentine` with three reasons) all collapse into this one.

`grid_fallback` stays for the case where there's no stage XY data at
all — it's a last-resort behavior, not part of the normal path.

### 3) Y orientation unchanged

`py = (max_y - y) / pixel_size_um` keeps "highest stage Y → row 0"
semantics, which is correct for typical microscope conventions
(stage Y grows up, image rows grow down).

### 4) V1.11's partial-metadata truncation stays

```python
if len(stage_xy_um) < len(m_indices):
    m_indices = m_indices[:len(stage_xy_um)]
```

Files like the user's Well3 (where `f.sizes['P'] = 121` but only 61
multipoints have valid `frame_metadata`) still work — the layout uses
only the 61 with metadata.

### 5) What happens to revisits and sparse cases

They render *as the metadata says*:

- **Revisits at the same (x, y)** (e.g. Well2's 4 visits to 17
  positions) → 4 tiles draw at the same pixel offset. Clicks return
  the topmost; the M slider can step between them.
- **Sparse / irregular ROI scans** → tiles appear at their actual
  stage positions with empty pixels between them where the acquisition
  didn't visit. No fabricated tight layout.
- **Diagonal scans** → tiles lie along the diagonal, not snapped to
  rectangular cells.

This is exactly what the user asked for: "accurate in relation to
the metadata."

## Files Modified

- `nd2studios/backend/exporters/stitch_exporter.py` — replace the
  cluster + serpentine path with the pure physical algorithm. Keep
  `_cluster_axis`, `_assign_index`, `_serpentine_layout` as orphan
  helpers (no longer called) — leaving them in place avoids touching
  any other module's imports and lets us bring them back if the
  user changes their mind. Strip the `serpentine_reason`,
  `n_phys_cells`, etc. handling from the active code path; the
  fields stay on `StitchLayout` for backward compat with already-
  written callers but default to "no clustering happened" values.
- `nd2studios/pages/import_page.py` — simplify
  `_tile_source_summary()` to two cases (physical vs grid fallback).
- `CodeLog/Updates/CHANGELOG.md`,
  `CodeLog/Architecture/ARCHITECTURE.md`

## Key Decisions

1. **Single layout algorithm.** "Physical" or "grid fallback".
   Nothing else. Easier to reason about, easier to debug.
2. **Keep V1.11's partial-metadata truncation.** Files where
   `len(stage_xy_um) < len(m_indices)` still work.
3. **Don't try to "fix" revisits or sparse cases.** Show them as
   the metadata says. If the user wants a serpentine reordering of
   sparse data, that's a different feature ("re-pack the tile widget
   in M-index order") and will be its own version.
4. **Keep helper functions in place** (`_cluster_axis`,
   `_assign_index`, `_serpentine_layout`) even though they're no
   longer called. Reverting if the user changes their mind is then a
   one-line change in `compute_tile_layout`.

## Validation

Both real-file synthetic tests:

- **Well3** (61 valid stage XY positions on a 13×13 grid, no overlap,
  pixel_size = 1.7183 µm/px, tile = 1024 px → 1759.5 µm): canvas
  ≈ 13312 × 13312 px, 61 unique offsets. Diagonal-stepping rows
  preserved.
- **Well2** (17 unique XY positions × 4 visits = 68, pixel_size =
  0.8613 µm/px, tile = 1024 px → 882 µm): canvas ≈ 3072 × 16384 px,
  68 offsets where 4 sets of 4 each share the same pixel position
  (revisits stack as expected).
- Regular 4×17 dense mosaic: every M lands at its correct
  `(row × tile_h, col × tile_w)` position.
