# V2.05 — Phase 7: capability matrix + scoped-coexistence retirement plan

> ## ⚠️ SUPERSEDED 2026-07-29 — v1 IS REMOVED. See **§6** (appended at the end of this
> document) for what was deleted, what capability was declared obsolete, and the one code
> dependency that had to be vendored first. §0–§5 below are the 2026-07-22 coexistence
> record, preserved as history: `--legacy`, the `pipeline_kit` parity gate, and the
> vendored `nd2studios/` tree they describe **no longer exist**.

> **Status: LOCKED 2026-07-22 (user chose "scoped coexistence").** Phase 7 of the
> nodegraph v2 effort was "retire `pipeline_kit` from NodeLab **once v2 reaches
> capability parity**; keep v1 runnable until then." This document is the parity
> assessment that gates that retirement, and the coexistence plan that was adopted
> **because v2 is NOT yet at full parity** — a hard retirement would delete real
> capability.

## 0. Decision

**v2 is the default editor; v1 stays runnable via `--legacy`; nothing is deleted.**
`run.py` now launches NodeLab v2 (the `nodegraph` engine) by default and NodeLab v1
(the vendored `nd2studios`/`pipeline_kit` backend) under `python run.py --legacy`. The
`pipeline_kit` parity gate (`scripts/_pipeline_kit_parity.py --check`) stays green — v1
is untouched. This delivers Phase-7's intent (v2 is the go-to editor for the workflows
it covers) without destroying the ~30 specialized capabilities v2 has not yet ported.

A full `pipeline_kit` removal is deferred until the §2 gap list is closed (or the user
decides specific gaps are obsolete). That is a multi-phase effort, not a single pass —
several gaps are large subsystems and some are dependency-gated.

## 2. What v1 has that v2 does NOT (the parity gaps) — keep on `--legacy`

**Update 2026-07-23 — a first wave of gap kernels PORTED into the v2 catalog.** The
ND2Studios team supplied 14 self-contained pure-compute analysis kernels
(`pure_analysis/`, byte-verbatim from v1.45); they are vendored into
`nodegraph/kernels/` (lazily imported by the relevant node compute) and wired as v2
nodes following the `build-node-v2` skill. **6 landed as working nodes + 2 as honest
dep-gated stubs**, all in the `nodegraph.selftest` group `catalog (v1 kernel ports)`:

| v2 op_key | v1 gap | kernel | notes |
|---|---|---|---|
| `detect.beads` | bead_detect | `bead_detect` | Point cloud; LoG / component centroids; 2D/3D lever; sub-voxel |
| `analysis.histogram_threshold` | Histogram Threshold Segmenter | `histogram_threshold` | mask + Label raster + region table; 4 methods × 4 directions (2D) |
| `registration.stabilize` | Registration | `registration` | register-once (ref channel) / apply-to-all; translation/euclidean/affine/feature |
| `analysis.granule_boundary` | granule_boundary | `granule_boundary` | outward band per granule label (dilation/EDT), 3D |
| `detect.stardist_nuclei` | StarDist Segmentation | `stardist_segment` | DL star-convex CNN → Label + regions; TF/stardist **present** |
| `analysis.dic_roi_mask` | DIC Mesh Region/Refinement (mask half) | `dic_mesh_region` | shape-list → boolean ROI Voxel mask |
| `analysis.granule_cluster` *(gated)* | granule_cluster | `granule_cluster` | registered stub → raises "install scikit-learn" |
| `analysis.dic_correlate` *(gated)* | DIC (pyALDIC) | `dic_correlate` | registered stub → raises "install al-dic" |

Catalog is now **47 node types** (was 39). v1 parity gate stays green (kernels are
independent files under `nodegraph/`).

**Still on `--legacy` (unported / deferred), grouped by remaining reason:**

**A. Needs a design decision before porting (worth a grill):**
- **DVC / ALDVC** (`aldvc_field` kernel, vendored + import-OK): the output is a
  per-voxel **displacement vector field + strain**, and the input is a **ref+def volume
  pair** — v2 needs a decision on (i) how DVC consumes ref/def (consecutive timepoints?
  a reference param?) and (ii) how to represent a voxel vector field (3 Voxel scalar
  layers `disp_z/y/x` µm + strain layers, or a new field type). Kernel is ready; the
  wiring is a design choice, not a mechanical port.

**B. Structure-chain (blocked behind a gated upstream):**
- **Granule mask** (`granule_tessellate` + `granule_volume_mask`, both import-OK): a
  Points+per-point-labels → Label-raster node (tessellate → voxelize, fusing the two
  kernels since the mesh intermediate isn't a v2 domain). Its natural upstream —
  `granule_cluster` — is **sklearn-gated**, so the full granule chain can't run
  end-to-end here yet. Port when sklearn is present (or feed labels from CCL).

**C. Already covered in v2 (lower priority):**
- **Track Objects** (`track_objects` kernel, 5.3k lines, import-OK): v2 already ships
  **`track.link`** (frame-to-frame linking → `TrackMembership`). The v1 kernel is a
  fuller 5-method tracker; port it as a richer alternative only if `track.link` proves
  insufficient.

**D. Dependency-gated (blocked on absent packages/models):**
- `analysis.granule_cluster` (scikit-learn — stub registered), `analysis.dic_correlate`
  + DIC mesh **refinement policy** (al-dic — stub / fail-soft), Nuclei/Cellpose
  (cellpose absent).

**E. Not in the supplied kernel set (still legacy-only):**
- Cell-tracker spatial maps (`ct_fields`/`ct_metrics`/`interp_map`), DIC mesh
  refinement/region distinct nodes (`dic_refine`/`dic_roi`/`register`), enhancement
  extras (bleach/blob-subtract/spatial-flatness/temporal-fold), interaction/workflow
  IO (`mask3d`/`review`/`exclude`/`dismiss`/`pause`/`prism`/`send_to_results`/
  `save_data`/`export`/`checkpoint`), `logic:if_else`.

## 3. What changed for Phase 7 (this pass)

- **`run.py`** — unified launcher: v2 default, `--legacy`/`--v1` → v1.
- **NodeLab v2 Help menu** — "Capability vs legacy…" surfaces the §1/§2 summary in-app
  and points at `python run.py --legacy` for the gap workflows.
- **`README.md`** — documents both launch paths.
- **Parity gate untouched** — `pipeline_kit` and `nd2studios` are not modified; v1
  remains byte-for-byte the golden.

## 4. Migration reality (unchanged from V2.00 §16)

v2 is greenfield: it does **not** open old `.nd2s_pipeline.json` files (v1's format).
v2 saves/loads its own `*.nd2graph.json`. A one-way importer (v1 doc → v2 graph, for the
covered nodes only) is a possible future convenience, not built here. Confirm no
important saved v1 pipelines are stranded before any hard v1 removal.

## 5. Exit criterion for a future full retirement

Retire `pipeline_kit` entirely only when: (a) every §2 gap is either ported to v2 or
declared obsolete by the user; (b) a v1→v2 pipeline importer exists (or migration is
declared unnecessary); (c) `run.py --legacy` has been unused/deprecated for a release.
Until then, coexistence is the stable state.

## 6. ADDENDUM 2026-07-29 — v1 REMOVED (coexistence ended)

**Decision (user, 2026-07-29): remove all of v1.** The §5 exit criteria were met by
declaration rather than by completion — the user reviewed the unported list below and
**declared it obsolete**, and declared migration of old `.nd2s_pipeline.json` files
unnecessary (no importer was ever built, and none will be). Criterion (c) was not formally
tracked; v2 had been the default editor since 2026-07-22 and is the only editor the user
runs.

| Path | Was |

| `.claude/skills/build-node`, `.claude/skills/wire-node` | the legacy-v1 node skills (`*-v2` remain) |

Also stripped: `run.py`'s `--legacy`/`--v1` branch (the launcher is now a one-liner into
`nodelab_v2.app.run`), the v1 half of `README.md`, and the Help → "Capability vs legacy
NodeLab…" dialog (rewritten as Help → "Capabilities…"; its gap list had gone stale anyway —
it still claimed DIC/DVC/granule/StarDist were legacy-only long after they landed).

Everything went to the **Recycle Bin**, not a hard delete — this tree's own history records
`nd2studios/` being deleted once and recovered from there. The surviving git history for
branch `Blender` starts *after* the removal (single-commit orphan branch, user's choice), so
the Recycle Bin and that fact are the only recovery paths.

### 6.2 The one blocker that had to be fixed first

`nodelab_v2/ingest.py` imported **`nd2studios.backend.nd2_loader.read_nd2_metadata_extended`**
— the only live v1→v2 code dependency in the tree (every other `nd2studios` mention under
`nodegraph/` is a comment recording an import that was *removed* during kernel vendoring).
It fed both `read_calibration` (pixel size, z step, NA, magnification, per-channel emission)
and `read_channel_display` (channel names/colours/excitation). Deleting `nd2studios/` without
acting would have silently degraded every ND2 load to "no calibration, no channel tints".

Fixed by vendoring `read_nd2_metadata_extended` + its `_safe` helper **verbatim** into new
**`nodelab_v2/nd2_meta.py`** (~210 lines, numpy + lazy `nd2` only; the v1 `ND2Metadata`
dataclass, pixel loaders, `z_project`, and the JSON sidecar cache were left behind — v2 reads
pixels via `nd2.to_dask()` and caches through the engine memo). Its docstring carries the
"don't re-derive this" warning: the `nd2` SDK exposes optics inconsistently across versions,
which is why every field read goes through `_safe`.

**Verified before deletion:** old and new readers produce `==`-identical 32-key dicts on both
real sample files (`7.10.26_NileBlue_52-75.nd2`, `Well2_ChannelCy5,TD_Seq0000.nd2`), and
`read_calibration` / `read_channel_display` / `read_meta_only` all return through the new path.

### 6.3 Capability declared obsolete (v1's 57 nodes vs v2's 55)

v2 covers the rest, in most cases as a *general* primitive rather than v1's
workflow-specific node (see `V2.07`). These had no v2 equivalent and are now **gone**:

- **Enhancement extras** — `Bleach Correction`, `Blob Subtract`, `Spatial Flatness`,
  `Temporal Fold Correction`
- **Analysis** — `Nuclei Segmentation` (Cellpose; the dependency was absent here anyway),
  `Tear / Dark Region Detection`
- **Cell-tracker spatial maps** — `ct_fields`, `ct_metrics`, `interp_map`
- **DIC extras** — `dic_refine` (mesh refinement; `dic_correlate` + `roi_mask` did port)
- **Workflow / interaction IO** — `mask3d` (3-D mask drawing), `review_object`, `exclude`,
  `dismiss`, `pause`, `prism`, `send_to_results`, `save_data`, `checkpoint`,
  `dvc_checkpoint`, `results:Summary`
- **`logic:if_else`** — v2 has zones/groups but still no conditional-branch node

Several of the workflow-IO entries were v1-GUI interaction concepts with no v2 analogue
(`pause`, `review_object`, `dismiss`), and `export`/`save_data`/`send_to_results` are already
covered *better* by v2's live Viewer, Spreadsheet, and CSV/Parquet/Arrow export — those are
features now, not nodes. The genuine losses worth remembering are the **four enhancement
extras**, the **cell-tracker spatial maps**, **DIC mesh refinement**, and **if/else**. The
vendored kernels for some of these still sit in `nodegraph/kernels/` with their `.md`
contracts, so a future port starts from the contract, not from archaeology.

**Stranded files:** three saved v1 pipelines exist on this machine
(`~/Downloads/{Cell-Tracker, If-else test, Test}.nd2s_pipeline.json`). v2 cannot open them
and now never will. Accepted by the user.

### 6.4 Gate change

The `pipeline_kit` parity gate **is gone by design** — it existed to prove the vendored v1
backend was untouched, which is meaningless once the backend is. The surviving gates are:

```bash
PYTHONUTF8=1 python -m nodegraph.selftest                         # headless core
PYTHONUTF8=1 python scripts/_nodelab_v2_phase5_probe.py out.png   # driven GUI probe
```

Any handoff or design doc telling you to run `scripts/_pipeline_kit_parity.py --check`, or
that "parity stays green", is describing the pre-2026-07-29 tree. Ignore that instruction;
the rest of those documents remains accurate.
