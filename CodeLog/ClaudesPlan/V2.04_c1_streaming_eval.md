## 0. The problem, concretely

Every catalog compute today allocates `np.zeros((M,T,Z,C,Y,X))`, loops planes/volumes
through `provider.get_region(_volume)`, and wraps the result in `ArrayProvider`
(`nodes.py::_map_image` and hand-rolled equivalents). On the real 6554² NileBlue sample a
single float64 plane is ~344 MB; a 3-node enhancement chain realizes the whole series
three times over even when the viewer wants one 512² tile of one plane. The provider
layer (benchmark-settled TILED, planar blocks), `PartialReducer` (monoid tree-reduce),
and the field memo namespace (`field_key`, disjoint from tile keys) all exist but are
not engine-driven.

Two lazy **precedents already ship and flow through the memo**: `_ChannelView` and
`_FrameView` (nodes.py) — pure index-remap `TileProvider` wrappers with cheap structural
`fingerprint()`s. C1 generalizes that pattern to *computing* wrappers.

## 1. Fork A — execution model: what a compute returns instead of `ArrayProvider`

**Recommended: (A1) lazy provider-chaining — "the provider IS the stream."**

A node whose resolved granularity is `TILEABLE`/`WHOLE_PLANE` returns
`ds.with_image(<ComputeProvider>)`; nothing is computed at pull time. A
`ComputeProvider` subclasses `TileProvider` and serves `read_region` on demand by
reading the needed window (+halo) from its **base** provider (itself possibly lazy →
the chain is the dataflow), applying the node's kernel, and cropping:

- `TileComputeProvider(base, plane_fn, halo_px)` — `TILEABLE`: canonical 512-aligned
  output tiles; window+halo read; exact iff halo ≥ influence radius (Fork B).
- `PlaneComputeProvider(base, plane_fn)` — `WHOLE_PLANE`: first read touching plane
  `(m,t,z,c)` computes + caches the whole plane, windows served as slices. Per-plane
  laziness is the win (a viewer showing 1 of 400 planes computes 1).
- `VolumeComputeProvider(base, volume_fn)` — `WHOLE_VOLUME`: same, per-`(m,t,c)`
  volume unit (today these realize ALL of 6-D; per-volume laziness is strictly better).
- `ReduceComputeProvider(base, axis, reducer)` — axis-collapsing (`zproject`, `stack`)
  with a **monoid** reducer: output tile `(iy,ix)` = `PartialReducer` fold over the
  base's tiles at the same `(iy,ix)` across the reduced axis (the engine-driven
  tree-reduce C1 promises). Non-monoid reducers (`median`, `sigma_clip`,
  `trimmed_mean`) gather the unit whole (V2.02 §7b fallback).
- `WHOLE_SERIES` / `MULTI_VIEW` / structure producers (CCL, watershed, measure, spots,
  drift, track) stay eager — unchanged this pass.

The **engine's node-level pull/memo logic does not change**: the memo `Entry` payload is
the `Dataset` carrying the lazy provider. Realization happens only at true sinks (viewer
tile pulls, export, `assert_zone_pure`), at `WHOLE_*` gathers, and at the depth fence
(§5). `_map_image` remains the single choke point — it grows a `halo=` argument and
builds the right provider from `ctx.granularity`; most catalog nodes change only by
passing their already-computed kernel window as the halo.

*Rejected:* (A2) engine-executed tile plans / task graphs (dask-style) — a second
scheduler + a new compute contract for all 39 nodes, versus reusing the proven
`TileProvider` seam that `WHOLE_*` consumers and the viewer already read through; (A3)
per-tile pull at the engine API (`pull(node, tile)`) — forces tile addressing into every
node interface incl. structure nodes where it is meaningless.

## 2. Fork B — halo policy for small-stencil ops

**Recommended: (B1) overlap-recompute (dask `map_overlap` style), compute-supplied halo.**

To produce output window `W`, read `W` expanded by `h` px per side from the base,
**clipped at true plane edges**, apply `plane_fn`, crop back to `W`. Border pixels are
recomputed by up to 2 tiles (≈13% redundant compute at h=32, tile=512) — accepted for
zero cross-tile coordination, trivially correct cancellation, and no seam state.

- `h` is supplied by the compute at provider-construction time (it already derives
  kernel sizes in px from params + `ctx.calib`): gaussian `h=ceil(4σ_px)` (scipy
  `truncate=4.0` default), median/morphology/tophat `h=w//2`, DoG `h=ceil(4·σ_hi)`,
  unsharp from its σ. No registry/NodeSpec change — halo is an eval-time value, not a
  static declaration (µm→px needs calibration anyway).
- Edge-clipping reproduces scipy `mode='reflect'` behavior at *real* plane edges;
  interior seams vanish when `h` ≥ influence radius. Ops with unbounded/global
  influence stay `WHOLE_PLANE` (plane unit) — that's the honest declaration, enforced
  by audit (§6).
- Exactness invariant (selftest gate): tiled output ≡ whole-plane output bytes for
  every streaming node, across tile seams and edges, 2D and 3D.
- **Empirically verified 2026-07-22** (direct probe, scipy 1.17.1, 700² random plane,
  256-tiles): bytes-exact for gaussian at `h=int(4σ+0.5)` (h−1 fails → the bound is
  tight), median at `h=w//2` (odd AND even windows), open/close/tophat/gradient at
  `h=w` (two-pass morphology), DoG at `h=ceil` of the larger σ, unsharp at its σ's
  halo. Edge-clipping reproduced `mode='reflect'` at true plane edges in all cases.

*Rejected:* (B2) exact interior exchange (compute once, share borders) — cross-tile
dependency graph + partial-result plumbing for ~13% compute; revisit only if profiling
says borders dominate.

## 3. Fork C — memo granularity: per-tile vs whole-output

**Recommended: (C1) two-level — node-level memo unchanged + one engine-owned
byte-budget LRU tile/unit cache.**

- **Node level (unchanged):** `recipe_hash` lookup + declared-reads revalidation as
  today; payload = lazy `Dataset`. A `ComputeProvider` carries a **cheap structural
  fingerprint** `("compute", op_key, digest(baked params incl. resolved calibration),
  base.fingerprint())` — constant-time, *stable across re-pulls of the same recipe*
  and distinct whenever params/calibration/upstream data differ (the `_ChannelView`
  precedent, now with baked-param identity). `output_fingerprint(Dataset)` stays cheap.
- **Unit level (new):** `TileCache` — engine-owned LRU keyed
  `(provider_fp_digest, level, m, t, z, c, iy, ix)` for tiles; plane/volume-addressed
  for plane/volume units. This *is* the V2.02 §9 "image tile key (recipe_hash,
  tile_id)" made concrete (provider fp is recipe-derived). Byte-budget (default 512 MB,
  configurable), entries frozen (`writeable=False`), eviction = plain LRU. Providers
  hold a weak/late-bound reference to the cache so a memoized Dataset doesn't pin it.
- **Accepted trade:** the Salsa content-cutoff (`changed` flag) degrades to structural
  for lazy image outputs (a param change always reads as changed). Content cutoff still
  operates at realized boundaries (structure tables, `WHOLE_SERIES` outputs). Noted in
  memo.py docs.
- **Consequence:** `assert_zone_pure` double-compute compares fingerprints — structural
  fp's are equal by construction, so the check would go vacuous. Fix in the same pass:
  a `realize(dataset)` helper (gather → `ArrayProvider`) used by debug-verify + export;
  `assert_zone_pure` realizes before fingerprinting.

*Rejected:* (C2) per-tile entries in the main `Memo` table — mixes bounded pixel blobs
into the unbounded structural table and puts tile addressing into `Entry`; (C3) no tile
cache at all — every halo/view read recomputes the full upstream chain per touch;
interactive panning would re-run the pipeline per repaint.

## 4. Fork D — field wiring (`FieldCache` / `field_key` into the engine)

**Recommended: (D1) minimal VOXEL-window evaluation, engine-owned cache, flagship on
`analysis.threshold`.**

Today no compute consumes a Field (FieldCache is selftest-only), so this is greenfield:

- The `Engine` owns one `FieldCache`; `EvalContext` exposes it.
- `EvalContext` gains an **inputs-by-socket-name map** (the engine already sorts preds
  into canonical socket order; today computes only ever use `inputs[0]`, so a value
  payload arriving on a named socket is unreachable — `ctx.input("threshold")` closes
  that).
- A value-socket input that arrives as Field IR (via `ctx.inputs` in canonical socket
  order) is carried into the `ComputeProvider`; the tiled path evaluates it **per unit
  window**: VOXEL-domain `Attr` layers are sliced to the window, `token =
  (provider_fp, level, unit addr)`, `kernel_axes` folded (V2.03 §4 C2) — the disjoint
  §9 namespace exactly as spec'd. `Const`/broadcast stays `VirtualArray` (free per tile).
- Flagship end-to-end: `analysis.threshold` accepting a per-voxel Field threshold
  (its socket is already `is_field=True`), proven in selftest per-tile == whole-plane.
- Deferred (unchanged from V2.00 §16 "start minimal"): structure-domain field transfer,
  `Sample`/`Nearest` ops, field-driven zone N.

## 5. Secondary defaults (will take these unless objected)

1. **Computed providers expose `levels=1`.** Pyramid semantics for *computed* results
   (exact-downsample vs compute-on-downsampled preview) is a Viewer (G4) decision;
   pure views (`_ChannelView`) keep passing levels through.
2. **Depth fence:** `depth = base.depth + 1`; a provider constructed past a threshold
   (default 32) realizes its whole unit into the cache on first read — guards unrolled
   Sim chains (T≈1000) against Python recursion limits and O(depth)-per-read cliffs,
   while keeping incremental invalidation (the fence is per-unit cache, not memo).
3. **Plane-stat traps get the plane unit, not silent tiles:** `enhance.gamma`
   (normalizes by `plane.max()`) is NOT tile-safe despite its TILEABLE declaration —
   it streams at plane granularity. The audit (§6) reclassifies every such node;
   declared `Granularity` stays the *scheduling* signal and must be honest.
4. **Histogram-threshold methods:** eager stat pass (whole-image histogram — later a
   per-tile histogram monoid), then lazy pointwise apply.
5. **Axis-changing lazy ops** (`crop`, `resample`, `zproject`): output tile grid is
   canonical over the OUTPUT geometry; `crop` becomes a pure offset view (like
   `_ChannelView`), `resample` stays eager this pass (interpolation footprint ≠ simple
   halo), `zproject`/`stack` use `ReduceComputeProvider` (§1).
6. **No async/threads in C1.** The engine stays synchronous; the tile cache is designed
   lock-friendly for the G7 scheduler but C1 lands single-threaded.

## 6. Verification gate (extends the build-node-v2 gate)

- New selftest group `streaming eval`: for every converted node, tiled ≡ whole-plane
  bytes (seams + edges, 2D + 3D lever states); pull-one-tile computes ≤ the touched
  window+halo upstream (compute-count / provider read-count instrumentation); memo
  re-pull is cache-hit; param/calibration edit re-keys the provider fp (no stale tile
  served); field-threshold flagship per-tile ≡ whole; `assert_zone_pure` still detects
  an impure body through `realize()`; depth fence keeps a T=1000 unrolled Sim chain
  under the recursion limit.
- Whole-catalog audit table (which node → which unit, halo derivation, hidden global
  stats) recorded in this doc's appendix before implementation.
- Gates stay green: 38 existing groups + parity no-drift.

## 6b. Adversarial-review amendments (4-lens fan-out, 2026-07-22 — all folded in)

The design above stands, amended by the confirmed findings:

**Fingerprint (Fork C hardening — three independent staleness holes closed):**
- `ComputeProvider.fingerprint()` = a **flat digest string cached at construction**:
  `digest("compute", op_key, params_digest, reads_digest, field_hashes, base_fp_digest)`.
  Nested-tuple fps (the `_ChannelView` pattern) recurse in `_canon` → RecursionError at
  unroll depth ~350 and O(N²) hashing; fix `_ChannelView`/`_FrameView` the same way, and
  memoize `fingerprint()` on ALL providers (in-memory `B2ndProvider` currently
  decompresses+hashes its full level-0 **per call**).
- `reads_digest` folds `rc.declared_reads()` — the calibration the closure baked in.
  Without it, `reseed_meta(pixel_size_um=…)` correctly re-computes the node but the new
  provider fp collides with the old → the TileCache serves tiles blurred with the STALE
  σ. The node-level reads fence does not protect the tile cache; this does.
- `field_hashes` = `field_expr_hash(f, dataset)` per bound Field (folds referenced layer
  **revisions**) — an attribute-layer change never touches the image chain, so base fp
  alone would serve stale field-driven tiles.
- The fp path REJECTS `_canon`'s repr-fallback types (id-bearing reprs → silent
  cache-cold + `changed` always true); selftest asserts fp equality across two
  constructions.
- `ReadContext` freezes when compute returns — a late `ctx.calib` from inside a lazy
  closure raises instead of silently escaping the memo fence.

**Cache mechanics (Fork C):**
- `ComputeProvider.read_region` **decomposes into canonical tiles of its own grid**,
  computes/caches each (tile+halo read from base), stitches, crops. Only canonical tiles
  enter the cache; halo reads and `WHOLE_*` stat passes are assembled from them — this
  is what gives intermediate chain levels cache reuse.
- **Pin-while-hot + oversize bypass:** units are pinned for the duration of a dependent
  read (in practice: local references during a stitch — eviction never invalidates
  handed-out immutable arrays); a unit estimated > **half** the budget bypasses the
  LRU path at `_map_image` and realizes eagerly into the node memo as an
  `ArrayProvider` (pre-C1 behavior — a 10 GB deconvolved volume must not recompute per
  tile pull). The estimate is sized by the **effective unit** (tile+halo for an
  unfenced TILEABLE op, plane/volume otherwise — impl-review fix). Volumes cache as
  per-z planar slabs (the keystone verdict), never one monolith.
- Uniform freeze: every array leaving a provider/cache path is `writeable=False`
  (cold path included); windows served from cached planes are **copied** when small
  relative to the base (view-pinning makes LRU byte accounting fictional otherwise).
- `FieldCache` shares the same byte-budget LRU (keys already namespace-disjoint).
- `Memo._blobs` stays unbounded (pre-existing); documented constraint: eager
  full-raster attribute nodes (threshold/label) inside high-T zones remain a memory
  hazard until a Memo GC lands (deferred, noted in §C follow-ups).
  **✅ DONE 2026-07-26 — Memo GC landed.** `Memo(budget_bytes=…)` makes the table a
  byte-budget **LRU**: when retained realized bytes (`memo.payload_bytes` — a Dataset's
  in-memory `ArrayProvider` image + attribute-layer arrays; lazy/disk providers count 0)
  exceed the budget, least-recently-used entries evict until it fits. Accounting is keyed
  by the **unique deduped blob** (an `fp → refcount`), so a shared blob is counted once
  and freed only at its last referencing entry. Eviction is **correctness-safe** — it only
  forces a later recompute (deterministic output fp; identity rides the monotonic
  `revision`), so **no pinning** is needed; `_last_fp` (the Salsa cutoff signal) is never
  GC'd, so an evict-then-recompute of identical bytes still reports `changed=False`.
  `budget_bytes=None` (the headless default) is byte-identical to pre-GC behavior;
  `Engine(memo_bytes=…)` plumbs it, and the **persistent GUI memo** (`nodelab_v2.runner`,
  the flagged hazard) opts into a 1 GiB budget. Note the re-pull consequence for a chain
  with **evicted ancestors**: an evicted upstream recomputes with a fresh revision, so every
  descendant's `recipe_hash` changes → the chain recomputes (the honest memory/recompute
  trade); a budget that fits the graph never evicts and re-pulls fully memoized. Selftest
  group `memo GC` (byte-budget LRU, per-blob refcount, recency, cutoff-safe, end-to-end
  bounded 41-node chain: evict-recompute vs fits-fully-memoized).

**Fence (Fork A/§5-2 correction):** the fence trips on **accumulated halo**
(`cum_halo = base.cum_halo + halo`; realize the unit when `2·cum_halo ≥ tile`), not on
depth — halo-0 pointwise chains tile cheaply at any depth, while a σ_px=5 gaussian chain
is already worse than realization at depth ~12. Depth alone doesn't even bound recursion:
the fenced realize is **iterative** (walk bases to the nearest cached/shallow level, then
realize bottom-up in a loop), and `Engine.pull` gets a scoped recursion-limit raise
proportional to graph size as the C1 stopgap (the recursive `_entry` at T=1000 is a
pre-existing overflow; an explicit-stack `_entry` is its own follow-up item).

**Halo table refinements (Fork B):** open/close/tophat = `2·(w//2)` (two-pass reach —
verified: `r` leaves real errors, `2r` exact); DoG with `high_sigma=0` uses skimage's
implicit `1.6·low`; a **kernel-influencing param bound to a non-Const Field forces the
plane unit** (spatially-varying σ breaks translation invariance and halo sizing;
kernel-param sockets are flagged in the registry).

**Fields (Fork D scope corrections):**
- `field.py` gains **windowed evaluation**: `FieldContext` carries a window origin +
  extent; `Attr` slices its layer to the window, `Const`/`VirtualArray` take the window
  extent (today `Const` materializes the FULL lattice shape on contact with a real
  array — multi-GB per tile), coarser-domain `Attr` indexes the origin's `(m,t,z)`.
- The field token = the **full unit address** `(provider_fp, level, m, t, z, c, iy, ix)`
  — the drafted `(fp, level, tile)` token would serve z=0's field slice to every other
  plane.
- `EvalContext` gains `ctx.input(name)` (socket-name → wired payload; positional
  `ctx.inputs` has gaps for unwired sockets and computes can't tell slots apart).
- **Flagship re-scoped:** `analysis.threshold`'s mask output is an eager Voxel attribute
  layer (no lazy-layer concept exists), so it demonstrates *windowed field consumption +
  fp folding* on its per-plane stat/apply path — the *per-tile lazy* field demo runs on
  an image-in/image-out selftest fixture node (`test.*` op). Lazy attribute layers are
  explicitly out of C1 scope.

**Reduce path (§5-5 correction):** `PartialReducer.lift` casts tiles to float first so
tiled ≡ eager bytes (eager path does `astype(float)`); `util.stack` (WHOLE_SERIES,
fusion reducers mostly non-monoid) stays **eager** this pass — only `util.zproject`
gets `ReduceComputeProvider`; stack's tree-reduce is a follow-up.
