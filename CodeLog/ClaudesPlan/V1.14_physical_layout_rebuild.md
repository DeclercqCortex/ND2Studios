# V1.14 — Physical tile layout rebuild

**Date:** 2026-05-02
**Author:** Gabriel Declercq (with Claude)
**Status:** complete
**Branch:** Version-1.0

## Goal

Replace the V1.13 row-flush, center-aligned layout with a pure physical
coordinate layout that places tiles at their true stage positions — as if
the multipoint file were reconstituted into one image. Also switch to
`f.experiment` (XYPosLoop) as the primary source for per-M stage XY,
which is more reliable than per-frame `frame_metadata()` readback.

## Problem with V1.13

V1.13 compressed tiles flush within each Y-row, eliminating physical gaps
between tiles that are not spatially adjacent. This was introduced for a
specific hex-staggered scan where adjacent tiles in a row had a 2×
tile-width X step. The row-flush approach loses the true spatial
relationships between tiles and cannot faithfully represent the acquisition
footprint.

## Approach

### 1. nd2_loader.py — experiment reader

Added `_read_xy_from_experiment()` inner function that walks `f.experiment`
looking for a loop with `type` containing `"XYPos"`, then reads
`loop.parameters.points[i].stagePositionUm.{x,y}`. Returns the full list
if found, empty list otherwise.

The stage XY extraction now:
1. Calls `_read_xy_from_experiment()` first.
2. Falls back to per-M `frame_metadata()` loop only if step 1 returns nothing.
3. Falls back to single-M frame 0 if no m_axis.

`stage_layout_source` now includes the method: `"stage_xy:experiment"`,
`"stage_xy:frame_metadata"`, `"partial:N/M:experiment"`, etc.

### 2. stitch_exporter.py — physical layout

Replaced the row-flush algorithm with:

```python
min_x = xs.min();  max_y = ys.max()
for each m:
    px_x = round((sx - min_x) / pixel_size_um)
    px_y = round((max_y - sy) / pixel_size_um)   # Y flipped

canvas_w = max(px_x) + tile_w
canvas_h = max(px_y) + tile_h
source = "physical"
```

Physical gaps between non-adjacent tiles appear as empty (black) pixels.
`_cluster_axis`, `_assign_index`, `_serpentine_layout` kept for potential
future use but are no longer in the main layout path.

### 3. import_page.py — diagnostic label

Updated `_tile_layout_source_label()` to:
- Handle `"stage_xy:*"` format (uses `startswith("stage_xy")` instead of `== "stage_xy"`).
- Primary path is `layout.source == "physical"`, showing cols × rows and
  canvas pixel dimensions plus the source method.

## Key Decisions

1. **f.experiment primary** — planned positions are more authoritative than
   per-frame readback; frame_metadata fallback covers files without an
   XYPosLoop.
2. **No gap compression** — physical spacing must be preserved so the tile
   layout and stitched output match the true acquisition footprint.
3. **Y flipped** — `max_y - sy` maps highest stage Y to row 0 (top),
   consistent with image-coordinate convention.
4. **Integer rounding** — sub-pixel error ≤ 0.5 px, acceptable for display.
5. **Helpers retained** — `_cluster_axis` etc. are non-trivial utilities;
   removing them would be premature.

## Verification

1. `python scripts/inspect_nd2.py <file.nd2>` — confirm `layout source: physical`,
   canvas dimensions match physical footprint, unique offsets = valid positions.
2. `python run.py` — load multipoint ND2, tile layout widget shows physical
   spacing with visible gaps for sparse/hex-staggered scans.
3. Stitch dialog — stitch one timepoint, confirm TIFF has black gaps between
   non-adjacent tiles.
