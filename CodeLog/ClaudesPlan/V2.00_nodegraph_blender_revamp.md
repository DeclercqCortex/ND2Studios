# V2.00 — `nodegraph`: a Blender-faithful node system for ND2Studios

> Status: **design spec** (agreed via grilling session, 2026-07-20). Greenfield —
> a new model built clean, not a migration of `pipeline_kit`. No code yet; this is
> the blueprint the build follows.

## 1. Vision

Rebuild the ND2Studios node system so wiring, data flow, and composition are as
powerful and legible as **Blender geometry nodes**, adapted to microscope image
analysis. One typed **Dataset** flows on the main wire carrying image + masks +
labels + points + tracks + measurements as **named attribute layers over domains**; a
separate **value/field** layer feeds node inputs; evaluation is **lazy and
demand-driven**. The result: analyses compose like geometry-node trees, adapt to
the image's metadata, and only compute what you look at.

## 3. Core model

### 3.1 The `Dataset` payload (the "Geometry" analog)

A `Dataset` is the single thing that flows on the main (thick) wire. It is a
lazy, immutable-by-convention bundle:

```
Dataset
├── axes:        M (multipoint) · T (time) · Z · C (channel) · Y · X
├── calibration: pixel_size_um, z_step_um, dt_s, + the full metadata dict
├── image:       the voxel intensities (lazy — a get_frame/get_volume provider)
└── attributes:  { (domain, name) -> AttributeLayer }   ← the named-attribute store
```

Nodes take a `Dataset` and return a **new** `Dataset` that shares the upstream
data and adds/replaces attribute layers (structural sharing — cheap to derive).
Masks, labels, points, measurements are **not separate socket types**: they are
attribute layers inside the Dataset, extracted/added by nodes.

### 3.2 Domains & attributes

An **attribute** is a named array of values living on one **domain**. There are
**ten** domains, in two families.

**(a) The acquisition lattice** — coarsenings of the image hypercube, each the finer
one with an axis aggregated away. Their pairwise transfers are *generated* (coarsen =
reduce, refine = broadcast), not hand-written:

```
Voxel (m,t,z,c,y,x) → Plane (m,t,z) → Frame (m,t) ─┬─ Multipoint (m) ─┐
                                                   └─ Timepoint (t) ──┴─ Global ()
Channel (c) is a lattice axis-domain, orthogonal to the spatial/temporal chain.
```

> **Amendment (V2.01 §H, implemented in `nodegraph/domains.py`):** ``c`` is now a
> first-class store/tile/memo axis, so **Voxel = {m,t,z,c,y,x}** and **Channel = {c}
> is a lattice domain** (Voxel↔Channel transfers are generated, not hand-registered).
> Because Channel is orthogonal to the spatial/temporal chain, ``meet`` with it is
> always named but ``join`` across ``c`` is not (``join`` is *partial*). Coarsening
> Voxel→Plane/Frame reduces over ``c`` by default (channel-mean); per-channel results
> transfer to Channel or select a channel at read time.

| Domain | Indexed by | Example attributes |
|---|---|---|
| **Voxel** | (m,t,z,y,x) | intensity, distance-to-boundary, local density (as fields) |
| **Plane** | (m,t,z) | focus score, slice mean, best-focus flag |
| **Frame** | (m,t) | label_count, point_count, frame_mean, drift, timestamp |
| **Timepoint** | (t) | elapsed time, count(t) over all m, condition-at-t |
| **Multipoint** | (m) | well id, condition, QC score, tile origin |
| **Channel** | (c) | emission_nm, gain, name |
| **Global** | singleton (one element) | dataset-wide stats, thresholds |

**(b) Detected structures** — not coarsenings; defined by analysis:

| Domain | Indexed by | Example attributes |
|---|---|---|
| **Label** | label id (per m,t, per mask) | area_um2, mean_intensity, eccentricity, centroid |
| **Point** | point id (per m,t, per set) | position (sub-pixel), displacement, velocity |
| **Track** | track id (per source; over t) | lifetime, net_displacement, mean_velocity |

The **Voxel → Label/Point → Track** spine: a **label mask** (an integer Voxel-domain
attribute, 0 = background) *defines* the Label domain (one element per region); a
**point set** (sub-pixel positions, each optionally carrying a vector) *defines* the
Point domain; **tracks** link Labels *or* Points frame-to-frame into persistent
identities.

**Track lives over the Timepoint domain.** A track is a temporal identity — a
function `t → member` (its label/point at each timepoint). It keeps its own per-track
attributes (lifetime, velocity) but is *defined by* its extent across timepoints:
`Label/Point → Track` = gather over `t`; `Track → Timepoint` = reduce (e.g. active
tracks at `t`); `Track → Label/Point` = broadcast. So Track is its own domain but
runs *along* the time axis, not beside it.

**Points ↔ Label is constructive, not just a lookup.** An ordered/cyclic Point set
is a **boundary** — a contour (2D) or surface (3D) — that **fills to a Label region**
(`Fill Boundary`), and a Label's outline **extracts back to Points** (`Extract
Boundary`). This is the granule pipeline (extract boundary vertices → voxelize to a
mask). Attribute *transfer* between an independent point set and a mask still uses
containment (§6).

**Instance-ness.** Because a dataset may hold several masks (nuclei + cells) or point
sets (beads + spots), **Label, Point and Track are multi-instance — keyed by their
source layer** (a node picks which mask / point set / tracking). The seven lattice +
Channel domains (Voxel, Plane, Frame, Timepoint, Multipoint, Channel, Global) are
**single-instance** (one per dataset).

**Multipoint is wired.** How many / which M flow through a branch is a graph choice,
not a fixed axis: the source node exposes a **Multipoint selection** (a boolean field
over the Multipoint domain, default = all), and a **Select Multipoints** node subsets
it. A Repeat/Simulation zone can **iterate per-M**. Per-well/per-multipoint
aggregation (Frame→Multipoint, Voxel/Label/Point→Multipoint) is thus first-class.

### 3.3 Fields

A **field** is a value socket carrying a *deferred function* rather than a
concrete value — evaluated per-element on the **consuming node's domain**, only
where consumed (lazy). Fields reference attributes by name (anonymous attributes
flow implicitly through field sockets; named ones via explicit `Store Attribute` /
`Read Attribute` nodes, as in Blender).

Example: `distance_to_boundary` is a Voxel field; feeding it into a `Threshold`
node evaluates it per voxel; feeding it into a per-Label node evaluates it and
transfers Voxel→Label by the default rule (mean-in-mask) — **with that rule shown
on the wire** (§6).

## 4. Socket type system

**Data socket:** `Dataset` (one type; thick wire).

**Value/field sockets** (thin wires; each may carry a single value **or** a field):

| Type | Widget | Notes |
|---|---|---|
| Float | spin (+ unit) | metadata-adaptive via `unit`/`derive` (§11) |
| Int | spin | |
| Bool | checkbox | |
| Vector | 2/3 spins | coordinates / sizes (µm or px) |
| Color | swatch | LUT / display / label color |
| String | line edit | names, attribute keys |
| Menu | dropdown | enum *as a socket* only when it must be wireable; otherwise use an in-body mode (§5) |

**Implicit conversion (values only):** `Bool→Int→Float` widen; `Float→Vector`
broadcast; `Float→Color` grayscale; `Int→Bool` nonzero. Inserted automatically and
shown as a small conversion pip on the wire. **Data-layer** transforms
(Mask ↔ Labels ↔ Points ↔ Measurements ↔ Field) are **never** implicit — they are
explicit nodes (`Label Mask`, `Detect Points`, `Rasterize Labels`, `Fill Boundary`
(Points→Label), `Extract Boundary` (Label→Points), `Measure`, `Attribute → Field`).

Socket colors follow type (Blender convention): Dataset = green, Float = grey,
Int = green-grey, Bool = pink, Vector = blue, Color = yellow, String = purple,
Menu = teal. Field sockets render as a **diamond**, single-value as a **circle**.

## 5. Node anatomy

```
        ┌───────── Detect Spots ─────────┐
Dataset ◇┤                               ├◇ Dataset (adds Point layer)
 radius ◇┤ [0.51 px]   ← socket + inline  │
thresh. ◇┤ [ auto  ]     widget (field-able)
        │  polarity: [ Bright ▾ ]  ← in-body mode (not a socket)
        └────────────────────────────────┘
```

- **Value inputs are sockets** with an inline widget shown when unconnected;
  connected → widget hidden, value/field comes from the wire. Field-able inputs
  show a diamond.
- **Mode/enum options are in-body dropdowns**, not sockets. They may change the
  node's socket topology (Blender's `update()`): e.g. choosing "Per-track" adds a
  Track output. Not fields, not wireable.
- **Multi-input sockets** (Merge Datasets, Join Measurements, Combine Masks) accept
  many wires in connection order.
- The **Properties panel** is an expanded mirror of the card's sockets/modes for
  nodes with many inputs — never the source of truth.
- **Mute** (M) = skip + pass the primary Dataset input through to the output.

## 6. Field domain-transfer (default rules, always visible)

When a field on domain **A** is consumed on domain **B**, a default rule applies and
is **shown on the wire** (`⊙ A→B (rule)`), overridable inline or via a
`Transfer Domain` node. Reductions available everywhere: mean · median · max · min ·
sum · count · first · nearest.

**Lattice transfers are generated, not listed.** Between acquisition-lattice domains
(Voxel · Plane · Frame · Timepoint · Multipoint · Global), transfer is automatic:
moving to a **coarser** domain **reduces** over the dropped axis (default mean); moving
to a **finer** domain **broadcasts**. E.g. Voxel→Plane reduces y,x; Plane→Frame reduces
z; Frame→Multipoint reduces t; Frame→Timepoint reduces m; anything→Global reduces all —
and each reverse broadcasts. Channel is orthogonal: Channel→X broadcasts a per-channel
value; Voxel→Channel groups voxels by channel and reduces.

**Explicit bridges** — the detected-structure edges the lattice can't generate:

| Bridge | Default rule |
|---|---|
| Voxel → Label | group voxels by label id, **mean-in-mask** (or sum / max / median) |
| Label → Voxel | **paint-by-label** — broadcast a label's value to its region's voxels |
| Voxel → Point | **sample-at-position** — interpolate the voxel field at the point |
| Point → Voxel | **splat** to the nearest voxel (or a kernel) |
| Point → Label | **points-in-label** — reduce the points inside each region |
| Label → Point | **containing label** — the region a point falls in |
| Label / Point → Track | **gather-by-track** — a track's members over `t`, then reduce |
| Track → Label / Point | **broadcast** — a track value onto its per-frame members |
| Track → Timepoint | **reduce** — over the tracks active at each `t` (e.g. count) |
| Timepoint → Track | **broadcast** — a per-`t` value onto each track's member at `t` |

**Indirect pairs route through the spine + lattice** — e.g. Voxel → Track =
Voxel → (Label | Point) → Track; Label → Multipoint = Label → Frame → Multipoint —
using each hop's default (all shown on the wire). No transfer is ever silent; a red
pip warns when a reduction discards information the user may not intend.

## 7. Bridging & wiring UX

- **Link-drag search** — drag from a socket into empty space → a menu filtered to
  type-compatible nodes; pick → node is created and auto-connected.
- **Splice-on-wire** (exists) — drop a node onto a link to insert it.
- **Multi-input sockets** (§5).
- **Mute-with-passthrough** (§5).
- **Reroute** dots for wire organization; **Frames** (labeled boxes) for visual
  grouping (annotation only, no execution effect).
- Connection validity = type match OR an available implicit value-conversion (§4);
  cycles rejected except across zone back-edges (§8).

## 8. Abstraction & iteration

- **Node groups** — select a subgraph → collapse into one node. The group's
  unconnected boundary sockets become the group node's interface (Group Input /
  Group Output nodes inside). Nestable; reusable across pipelines; a group library.
- **Repeat zone** — paired `Repeat In`/`Repeat Out` nodes bound a region run **N
  times** (iteration count is itself a value socket → can be a field/metadata-
  derived). For iterative algorithms (active contours, watershed passes). The old
  single `loop` back-edge maps here.
- **Simulation zone** — paired `Sim In`/`Sim Out` bound a region whose outputs
  **feed back as inputs on the next frame** (state persists across T, re-initialized
  at t₀). This is the native home for **tracking**, temporal accumulation, and
  iterative-across-time refinement — a first-class upgrade over today's ad-hoc
  tracking node.

## 9. Evaluation engine (lazy pull + memoization)

- **Pull, don't push.** An output — a Viewer, the Spreadsheet, an Export node —
  *requests* a specific (domain, attribute[, frame]). The engine walks **backward**,
  computing only the nodes and fields needed for that request. Unviewed branches
  never run.
- **Fields evaluate only where consumed**, on the requested domain, over only the
  requested elements/frames.
- **Memoization = automatic checkpointing.** Each node's output is keyed by a
  content hash of `(op, in-body options, resolved input hashes, calibration)`.
  Editing a downstream param never re-runs unchanged upstream segmentation/tracking.
  The old explicit Checkpoint node becomes unnecessary (a pin/keep hint at most).
- Long compute runs off the UI thread (as today); the pull scheduler drives
  progress per node.

## 10. Inspection

- **Viewer node** — attach to any wire → renders that Dataset/field in the image
  viewport, **domain-aware**: Voxel field → heatmap overlay; Label field → colored
  regions/outlines; Point field → markers (sized/colored by value); Track field →
  colored trajectories; Frame/Global → numeric readout. Generalizes today's
  view-only (dotted) edges.
- **Spreadsheet** — pick any wire → a table of its attributes for a chosen domain
  (`domain [Label ▾]` → rows = label ids, columns = attributes). Generalizes the
  results panel; the export path reads from here.

## 11. Node definition API (proposed)

A node declares typed sockets, in-body modes, and an `evaluate` that receives an
evaluation **context** (metadata, requested domain, pull handles) and returns a new
`Dataset` and/or field outputs. Metadata-intelligence (units/derive) rides on value
sockets — the framework built in V1.91 (`metadata_adapt`) is **reused**.

```python
@node("detect.spots", category="detection", label="Detect Spots")
class DetectSpots:
    data      = InDataset()
    radius    = InFloat("Radius", unit="um", field=True,
                        derive="0.61*(emission_nm or 520)/(na or 1.4)/1000")
    threshold = InFloat("Threshold", field=True, default=None)  # None → Otsu
    polarity  = Mode("Polarity", ["Bright", "Dark"])            # in-body, not a socket
    out       = OutDataset()                                    # adds a Point layer

    def evaluate(self, ctx):
        img = ctx.image(channel=ctx.channel)          # lazy voxel provider
        r   = ctx.to_px(ctx.value(self.radius), "um") # value or field → px
        thr = ctx.value(self.threshold) or ctx.otsu(img)
        points, attrs = detect_spots(img, r, thr, self.polarity)  # sub-pixel centroids
        return ctx.dataset.with_point_layer(points, attributes=attrs)
```

`In*/Out*` declare sockets (type, widget, `field=`, `unit=`, `derive=`,
`multi=`); `Mode` declares an in-body dropdown that may reconfigure sockets;
`ctx.value()` resolves a socket to a concrete value or evaluates a field on the
current domain; `ctx.to_px` reuses `metadata_adapt`.

## 12. Serialization (greenfield v2)

New format `*.nd2graph.json` (no v1 importer). Records: nodes (op, in-body option
values, socket default values, position, mute/collapse), links (src socket → dst
socket, with multi-input order index and the transfer-rule override if any), node
groups (nested subgraphs + interface), zones (paired node ids + config), frames,
and the format version. Field/attribute references are by name. Value-socket
`unit`/`derive` live on the node op (spec), not the file — so files store resolved
values + the `__locked__` sticky set (as in V1.91).

## 13. Metadata-intelligence carry-over

The V1.91 framework generalizes cleanly: every **value socket** gains `unit`/`derive`;
`metadata_adapt.adapt_defaults` seeds unconnected socket widgets on load;
`to_pixels` is called in `evaluate` via `ctx`; sticky-override (`__locked__`) applies
per socket. `metadata_adapt.py` is **model-agnostic and reused as-is**.

## 16. Open questions / risks

- ~~**Point ↔ Label association**~~ — **resolved**: the primary bridge is
  *constructive* — Points form a boundary that fills to a Label (`Fill Boundary`),
  and `Extract Boundary` inverts it. Attribute *transfer* between an independent
  point set and a mask still uses containment; a *nearest* reducer covers stray
  background points.
- ~~**Multipoint / Z / Timepoint**~~ — **resolved**: the acquisition axes M, Z, T
  are all first-class domains (Multipoint, Plane, Timepoint), forming a coarsening
  lattice with Voxel/Frame/Global (§3.2). M-flow is wired (source selection +
  `Select Multipoints`; zones iterate per-M). Track is its own domain but runs *over*
  the Timepoint axis.
- **Multi-layer keying UX** — Label/Point/Track are keyed by source layer, so nodes
  that consume them need a clean "which mask / which point set / which tracking"
  selector (an in-body layer dropdown); default = the most-recently-added layer.
- **Field IR depth** — how expressive is the field expression graph (arithmetic +
  comparisons + attribute reads + a `Sample`/`Nearest` op)? Start minimal, grow.
- **Voxel-field cost** — lazy per-voxel fields on 6.5k² images must tile/stream;
  the memo + pull engine must be tile-aware, not whole-frame.
- **Simulation-zone determinism** — cross-frame state + memoization interaction
  (invalidation when an earlier frame changes).
- **Group/zone serialization** round-trip + nesting depth.
- **Migration reality** — greenfield means existing `.nd2s_pipeline.json` files are
  not opened by v2; confirm no important saved pipelines are stranded.
