# V1.17 — Frame Prefetch Cache

## Goal

Remove the main-thread disk I/O stall that freezes the GUI whenever the
user drags the T, Z, or M slider.  For 100+ GB ND2/TIFF files on slow
storage, a single `np.asarray(dask_slice)` call can take hundreds of
milliseconds — enough to make the slider feel completely unresponsive.

## Approach

Three complementary strategies that compound on each other:

1. **Frame cache** (`FrameCache`) — once a `(H, W)` frame has been read
   it is held in a thread-safe LRU dictionary keyed by
   `(c, m, t, z, z_mode)`.  Revisiting the same coordinate is instant.

2. **Background prefetch** (`PrefetchManager`) — after each frame render
   a background `QThread` queues ±5 nearest-neighbor timepoints (or Z
   slices for single-timepoint volumes) and fills the cache ahead of the
   next drag.  The prefetch thread opens its **own** `LazyND2Volume`
   handle so the main thread's nd2 file descriptor is never shared.

3. **Debounce** — on rapid slider drags the display handler first checks
   the cache (instant display if hit), otherwise starts a 50 ms
   single-shot timer.  Only after the timer fires does a disk read
   happen, so frames are skipped during fast sweeps rather than queuing
   up behind each other.

4. **TIFF handle fix** — `LazyTIFFChannel._read_frame` was calling
   `tifffile.imread(path, key=page)` which opens and closes the file on
   every single frame.  Now caches a `tifffile.TiffFile` handle on first
   use, mirroring the existing ND2 pattern.

## Key Decisions

- **Single prefetch thread, not a pool.** nd2 file handles are not
  thread-safe.  One thread with its own file descriptor is simpler and
  safe.  Multiple concurrent reads on different threads would require a
  handle pool or per-thread locks.

- **Cache normalized 2D frames, not raw.** `_compose_current_frame`
  calls `_normalize_to_2d` after every `get_frame`.  Caching the
  post-normalize `(H, W)` array means cache hits skip both the disk read
  *and* the normalize call.  The prefetch worker also normalizes before
  storing (applies `np.squeeze` to match `_normalize_to_2d`'s typical
  output for standard ND2 frames).

- **Histogram cache per `(m, z_mode)`.**  The M-slider previously re-ran
  `_populate_lut_samples_from_volume` (8 frames × n_channels per visit)
  on every M change.  Now it records which (m, z_mode) pairs have been
  sampled and skips the resample on revisits.  Cache is cleared on
  `set_volume` and `set_channels`.

- **Separate debounce timers from playback timers.** `_m_timer`,
  `_t_timer`, `_z_timer` already drive the ▶/⏸ animation.  New
  `_m_debounce`, `_t_debounce`, `_z_debounce` are independent
  single-shot timers so the two mechanisms don't interfere.

- **TIFF prefetch deferred.** TIFF files reach `MultiAxisViewer` via
  `set_channels()` (flat `Dict[name, array]`), not via a `LazyND2Volume`
  — there is no `get_frame(c, m, t, z)` API to call from the prefetch
  thread.  The TIFF handle-caching fix removes the dominant per-frame
  open/close cost; prefetch for TIFF is deferred to a later version.

## Thread Safety

| Risk | Mitigation |
|---|---|
| nd2 handle shared between threads | Prefetch opens its own `LazyND2Volume(filepath)` inside `run()` |
| FrameCache concurrent read/write | `threading.Lock` on every `get` / `put` / `contains` |
| `frame_ready` signal from background | Qt queued-connection delivers it to the main thread automatically |
| Queue replacement mid-read | `_queue_lock` makes clear+extend atomic; in-flight read stores its result harmlessly |
| `PrefetchManager.stop()` race | Sets `_stop_flag`, wakes event, calls `self.wait(2000)` |
