# Manual Mask Drawing Pipeline + Per-Frame ΔArea

Target version: **V1.28** (next after V1.27 multi-file Z work)

## Context

The Analysis tab currently has three registered pipelines (Nuclei, Histogram Threshold, Bright/Dark Spots), all of which produce automated label masks. There is **no way for the user to manually draw a binary mask** — useful when a region is hard to segment automatically (e.g., ad-hoc ROIs, ground-truth annotations, gel boundaries, irregular tissue outlines). This change adds a `ManualMaskPipeline` plus drawing tools on the viewer (rectangle, ellipse, free-polygon with auto-close), and a per-frame ΔArea column in the Results tab that applies to **all** mask-producing pipelines, not just manual masks. The Results tab schema is built by [results_engine.py:19-115](nd2studios/backend/results_engine.py#L19-L115) — adding columns there benefits every pipeline automatically.

Volume/ΔVolume support is out of scope for V1.28 (current data is `(T,H,W)` after Z-projection per [CLAUDE.md](CLAUDE.md)). Schema-extending columns are noted as TODO for when V1.27 multi-file-Z lands.

[nd2studios/widgets/image_viewer.py:174-408](nd2studios/widgets/image_viewer.py#L174-L408)

- New signal `shape_drawn(str, list)` emitting `(mode, vertices_image_space)` where `vertices` is a list of `(iy, ix)` floats:
  - rect: `[(y0, x0), (y1, x1)]` (corner pair)
  - ellipse: `[(y0, x0), (y1, x1)]` (bounding box corner pair)
  - polygon: arbitrary length `[(y, x), ...]` (last vertex auto-connects to first)

Mouse-event integration (extends the existing pattern at lines 323–400):
- **Rect / ellipse**: identical to current crop — press → start, drag → update end, release → emit `shape_drawn`.
- **Polygon (free-draw with auto-connect)**: press → start polygon, drag → append a vertex every N pixels (e.g. when the move distance from last vertex > 2 image pixels — keeps memory bounded), release → emit `shape_drawn` (caller closes the loop by reusing vertex 0). This matches the user's "drawn and automatically connecting the vertices" requirement.

Painting in `paintEvent` (lines 287–316): after the existing crop overlay, paint the in-progress draw using `QPainter.drawRect`, `drawEllipse`, or `drawPolyline` based on `_draw_mode`. Use a distinct color (e.g. cyan dashed) to differentiate from the yellow crop rectangle.

Coordinate transforms `widget_to_image` / `image_to_widget` (lines 402–408) already exist and work for any tool — reuse as-is.

### 3. New backend pipeline: `ManualMaskPipeline`

**New file**: `nd2studios/backend/analysis/manual_mask.py`

Registers via `@AnalysisPipeline.register` (pattern from [histogram_threshold_pipeline.py:21](nd2studios/backend/analysis/histogram_threshold_pipeline.py#L21)). Conforms to the same `AnalysisResult` contract that [results_engine.py:54-65](nd2studios/backend/results_engine.py#L54-L65) consumes.

```python
@AnalysisPipeline.register
class ManualMaskPipeline(AnalysisPipeline):
    name = "Manual Mask"
    description = "User-drawn binary masks. Draw rectangles, ellipses, or " \
                  "free-polygons on each frame; the pipeline rasterizes them " \
                  "to a label stack. Each shape becomes its own label_id."

    def get_params(self) -> List[ParamSpec]:
        return [
            ParamSpec("channel_name", "Channel", "choice", "", choices=[]),
            # Internal-state param — not rendered by ParamEditor (page strips it
            # from the param spec list before set_params(); injects fresh at runtime).
            # Shape: {frame_idx: [{"type": str, "vertices": [[y, x], ...]}, ...]}
            ParamSpec("frame_shapes", "", "hidden", {}),
        ]

    def run(self, channels, metadata, params, progress_cb=None, cancelled_cb=None):
        ch_name = params["channel_name"] or next(iter(channels))
        T, H, W = channels[ch_name].shape
        frame_shapes: dict = params.get("frame_shapes") or {}

        label_stack = np.zeros((T, H, W), dtype=np.int32)
        for t_str, shapes in frame_shapes.items():
            t = int(t_str)
            if t >= T:
                continue
            for label_id, shape in enumerate(shapes, start=1):
                self._rasterize_into(label_stack[t], shape, label_id, H, W)
            if progress_cb:
                progress_cb(int(100 * (t + 1) / max(T, 1)))

        return AnalysisResult(
            label_masks={ch_name: label_stack},
            measurements=[],   # results_engine recomputes via regionprops
            summary={},        # filled by page after run from label_stack
            overlay_color=(255, 220, 0),  # yellow — distinct from auto pipelines
            overlay_alpha=0.45,
        )

    @staticmethod
    def _rasterize_into(frame, shape, label_id, H, W):
        from skimage.draw import polygon, ellipse, rectangle
        s_type = shape["type"]
        verts = np.array(shape["vertices"], dtype=float)
        if s_type == "rect":
            (y0, x0), (y1, x1) = verts
            rr, cc = rectangle((min(y0,y1), min(x0,x1)),
                               extent=(abs(y1-y0)+1, abs(x1-x0)+1), shape=(H, W))
        elif s_type == "ellipse":
            (y0, x0), (y1, x1) = verts
            cy, cx = (y0+y1)/2, (x0+x1)/2
            ry, rx = abs(y1-y0)/2, abs(x1-x0)/2
            rr, cc = ellipse(cy, cx, ry, rx, shape=(H, W))
        elif s_type == "polygon":
            rr, cc = polygon(verts[:, 0], verts[:, 1], shape=(H, W))
        else:
            return
        frame[rr, cc] = label_id
```

`skimage.draw` is already a dependency (used elsewhere via `skimage.transform` / `skimage.measure`).


### 7. Per-frame ΔArea in `results_engine.compute_measurements`

[nd2studios/backend/results_engine.py:19-115](nd2studios/backend/results_engine.py#L19-L115)

This applies to **all** pipelines, per the user's "no matter the analysis pipeline" requirement. After the main `for prop in props` loop builds `rows`, post-process:

```python
# Sort rows by (segmentation_channel, label_id, frame) so we can compute
# per-track per-frame deltas in one pass.
rows.sort(key=lambda r: (r["segmentation_channel"], r["label_id"], r["frame"]))
prev_key = None
prev_area_px = prev_area_um2 = None
for r in rows:
    key = (r["segmentation_channel"], r["label_id"])
    if key != prev_key:
        r["delta_area_px"] = None       # first frame for this label
        r["delta_area_um2"] = None
    else:
        r["delta_area_px"] = r["area_px"] - prev_area_px
        r["delta_area_um2"] = round(r["area_um2"] - prev_area_um2, 4)
    prev_key = key
    prev_area_px = r["area_px"]
    prev_area_um2 = r["area_um2"]
```

Edge cases worth verifying after implementation:
- For instance-segmentation pipelines (nuclei), `label_id` is **not stable across frames** — each frame's regionprops assigns fresh ids 1..N. ΔArea between frames for the same `label_id` is therefore noisy unless tracking is done first. **This is fine for V1.28** because (a) for manual masks the user controls label_id explicitly, (b) for single-object analyses there's typically only one label, and (c) for instance pipelines the per-frame `area_px` itself is still useful and ΔArea reflects "label_id=k between consecutive frames" which is documented behavior, not a bug. Document this in the column header tooltip.
- Volume: add `# TODO V1.27+: delta_volume_um3 when Z-stacks land`.
