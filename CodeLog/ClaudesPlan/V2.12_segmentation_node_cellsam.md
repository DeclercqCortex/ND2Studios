# V2.12 — One Segmentation node, and CellSAM as a method

**Date:** 2026-07-29 · **Status:** BUILT + both gates green ·
**Gates:** `python -m nodegraph.selftest` → 56 `[ok]` lines ·
`scripts/_nodelab_v2_phase5_probe.py` → ALL PASS · catalog **55 → 54**

## 1. The directive

> "Implement CellSAM as a new segmentation option. I want all segmentation to be in a
> central node named segmentation, since fundamentally, the domain from input to output of
> any segmentation is the same, only the analysis/method is different."

The observation is correct and it is the whole design. Every segmentation consumes an
image and produces **instance labels** — a `Domain.VOXEL` integer raster plus a
`Domain.LABEL` table of one row per object. Nothing else about the contract varies. So the
algorithm is a **Mode**, not a node type.

## 2. What shipped

### `analysis.segment` — "Segmentation" (category `analysis`)

`reads_domains={VOXEL}`, `adds_domains={VOXEL, LABEL}`, no `meta_transform`,
`granularity={2D: WHOLE_PLANE, 3D: WHOLE_VOLUME}`, `kernel_axes=_DIM_KAX`.

| `method` | backend | needs |
|---|---|---|
| `threshold` *(default)* | foreground cut at `level` → `structure.label_components` | nothing beyond scipy/skimage |
| `watershed` | the same cut, split at the peaks of the anisotropic EDT | nothing beyond scipy/skimage |
| `stardist` | StarDist2D star-convex CNN (`kernels/stardist_segment`) | `stardist`+`tensorflow`+`csbdeep` |
| `cellsam` | **CellSAM** — SAM ViT-B decoder prompted by CellFinder (`kernels/cellsam_segment`) | `cellSAM`+`torch`, weights + DeepCell token |

**Shared once, instead of once per method** (this is the payoff, and the pair it replaced
had already drifted apart on every line of it): the output layer `name` (one socket,
`layer_out=(VOXEL, LABEL)`), `fill_holes`, the size filter in **µm² (2D) / µm³ (3D)**, the
contiguous relabel, the global id offset that makes ids unique across every `(m,t,z,c)`
unit, the invariant `id,m,t,c,area,z,y,x` Label table with the right `z_kind`, the 2D/3D
lever, the progress reporting, and a `segment_method` / `segment_model` provenance stamp.

**The lever's meaning here:** 2D segments each `(m,t,z,c)` plane independently and emits
per-plane instances (`z_kind="plane_index"`); 3D segments each `(m,t,c)` volume and emits
z-connected instances (`z_kind="subpixel"`).

### Deleted

`analysis.watershed` and `detect.stardist_nuclei`. Both are now methods; their op_keys are
gone (the `analysis.tessellate_volume` precedent from V2.08 — a saved graph naming them
will not load). Everything they could do, the new node can:

* watershed's "split an existing mask" survives as the gated `mask` socket, which now
  **defaults to empty** — unset means *segment the image*, naming a layer means *split
  THAT foreground*. A Segmentation node should segment out of the box.
* stardist's area filter is the shared one, now correct in 3D too (µm³, not µm² reused).

### Kept, deliberately

`analysis.threshold`, `analysis.threshold_local`, `analysis.multiotsu`,
`analysis.histogram_threshold` (image → a Voxel **mask** or class raster) and
`analysis.label` (a **mask** → labels). None of them matches the segmentation contract —
their input or their output is a mask, not instance labels — and all of them compose into
the new node through its `mask` socket. Full histogram menus, local/adaptive thresholds and
the granule region table stay where they belong.

## 3. Framework addition — `ModeSpec.available_in` (Mode-level gating)

A node that unifies four algorithms hits a wall the socket contract already solved: the
`level` Mode (which foreground cut) means nothing to a learned detector. `SocketSpec` could
be gated; `ModeSpec` could not, so the dropdown would have sat there doing nothing — the
same "live-looking control the selected kernel ignores" the `track.objects` review declared
charter-forbidden.

So `ModeSpec` grew `available_in` with the identical semantics, plus
`NodeSpec.active_modes(state)`. Used by the inspector (`_rebuild`) and the node card
(`_layout`), and `NodeItem.refresh()` now compares the active **mode** list too, so a
method switch that gates only a Mode still relayouts.

Deliberately unchanged: `default_state()` still includes hidden Modes, so a gated-away Mode
keeps its value and the compute's `__modes__` lookup and the recipe hash are unaffected by
what the GUI draws — the same rule as a hidden socket. `test_param_socket_contract` grew a
clause (a0): a Mode's `available_in` must name a real mode and real values, and must never
gate on itself.

## 4. Five real bugs found and fixed on the way

Three of the five came out of an adversarial review pass (three independent lenses, each
finding verified by a separate agent told to refute it); four survived refutation, and one
of those was a RED gate the author's own `tail -2` check had hidden. Every one is now
pinned by an assertion.

**(a) The watershed shattered objects.** `peak_local_max` returns *every* pixel of a
plateau, and a distance transform is full of plateaus (a disk on an integer grid has
several pixels at its maximum; an elongated object has a whole ridge; an object with a hole
has an equidistant *ring*). The folded-in `analysis.watershed` numbered each returned pixel
as its own marker, so one object became one basin **per plateau pixel** — measured on the
new selftest fixture: four synthetic disks → **19** fragments per plane, the smallest 1
voxel. Fixed by connected-component labelling the peak mask first (scikit-image's own
watershed recipe) with **full** connectivity (8 in 2D / 26 in 3D) — cross-connectivity
still breaks a diagonal ring into one marker per step (that fixture: 11 instead of 4). The
selftest asserts the exact counts and pins the smallest object's size.

**(b) The watershed also DELETED objects near the frame — and every object in a thin
volume.** `peak_local_max` excludes a border shell `min_distance` wide on **every axis** by
default, and `min_distance` is a parameter this call does not even use (the physical
suppression is the per-axis `footprint`). Objects lying in that shell got no marker, and
`watershed(..., mask=fg)` leaves marker-less components at 0 — so they vanished from the
raster *and* the table, silently. In **3D on a volume with `z <= 2` there is no interior z
plane at all**, so ZERO peaks came back, the single-marker fallback fired, and every object
in the volume collapsed into one: four separated disks over a 2-plane stack returned **1**
object and dropped 294 of 392 foreground voxels, while the `threshold` method on the same
data returned the correct 4 — two methods of one node disagreeing on how many objects exist.
`DimMode`'s derive makes 3D the *default* for any `n_z >= 2`, so this was the natural
configuration for a z-stack, not an abuse. Fixed with `exclude_border=False`; the selftest
pins a 5-object z=2 volume including one object hard against the frame corner. (Byte-identical
to the deleted `analysis.watershed`, so carried over rather than introduced — but the fold-in
widened its reach, since `watershed` no longer needs an upstream mask layer and is one
dropdown click from a fresh node.)

**(c) A single non-finite voxel broke, or silently emptied, the segmentation.**
`_segment_level`'s degenerate-histogram guard is `lo == hi`, which is False in the presence
of NaN (`nan != nan`), so one NaN or inf reached skimage: otsu/triangle/yen raise
`ValueError: autodetected range … is not finite` (a message naming neither the node nor the
data), and `mean` returns NaN, after which `arr > nan` is all-False — **zero objects on an
image full of them**. NaN is reachable from deconvolution, a normalize of a flat region, or
an interpolating resample. Now the level is derived from the finite population only, and
non-finite voxels are excluded from the foreground: NaN falls out by itself, and `inf` is
excluded explicitly, since `inf > level` is True and an isolated inf would otherwise appear
as a phantom one-voxel cell in the table. (The pre-existing `analysis.threshold` has the same
NaN exposure and was left alone — out of this change's scope, worth its own pass.)

**(d) The four size-filter sockets went dead, and the gate went red.** Factoring the µm²/µm³
conversion into shared `lo_key`/`hi_key` variables meant the params were read as
`ctx.params.get(lo_key, …)` — and the socket contract's index is an **AST pass that resolves
only string literals** (and helper arguments), so all four sockets read as declared-but-never-
read and `test_param_socket_contract` failed. The keys are now spelled literally per dim, with
a comment saying why the repetition is required rather than sloppy. Lesson recorded: always
check the selftest's **final** line, never `tail -2`.

**(e) BOOL params rendered as `0.000` / `1.000`.** `inspector._param_row` had branches for
INT and STRING and fell through to a `QDoubleSpinBox` for everything else, so every
`InBool` in the catalog (9 sockets, 5 of them on this node) read as a mysterious decimal.
Now a `QCheckBox` committing a real `bool`.

Non-destructive hole filling is a third, smaller correction: cellpose's
`fill_holes_and_remove_small_masks` (which CellSAM also uses) writes the fill across the
object's whole bounding box and can steal voxels from a **neighbouring** label. The shared
stage paints only voxels that are currently background.

## 5. CellSAM specifics

`nodegraph/kernels/cellsam_segment.py` + `.md` — an "external wrapper" kernel in the same
class as `stardist_segment` / `dic_correlate`: it holds no algorithm, only the adapter, the
model cache and the quirk normalizations. Read the `.md` before touching it. The headlines:

* **Entry point.** `segment_cellular_image(img, model, …)` takes `model` as a **required
  positional** argument — the project README's `segment_cellular_image(img, device='cuda')`
  raises `TypeError`. `cellsam_pipeline` (the documented one-shot entry) is *not* used: it
  calls `get_model()` on every invocation, which per-plane re-reads the checkpoint for
  every frame of a series. The model is a process singleton keyed on
  `(model, model_path, device)`, loaded once per pull.
* **The no-cells path is broken upstream in two layers, and it is the one every z-stack
  hits.** `CellSAM.predict` returns the 4-tuple `(None,)*4` when no box survives, so
  `segment_cellular_image`'s `if preds is None` guard **never fires** (upstream issue #98):
  it unpacks the tuple and calls `fill_holes_and_remove_small_masks(None)` →
  `AttributeError: 'NoneType' object has no attribute 'ndim'`. A blank plane, an empty FOV
  or the dark end slices of a stack would crash the entire pull. The kernel absorbs exactly
  that AttributeError (only when the message names `NoneType`; anything else re-raises) and
  returns an empty plane — repairing a broken guard, not inventing behaviour, since "no
  cells" is an empty segmentation and that is what upstream's own dead branch was written to
  return. That dead branch is *also* mis-shaped — `np.zeros(img.shape[1:])` on the
  `(1,3,H,W)` tensor gives `(3,H,W)` — so any 3-D return is collapsed too, and an upstream
  fix lands safely. The tiled path is immune to both (`segment_chunk` catches per block).
  **Found by review; the original code handled only the unreachable branch.**
* **Channels.** CellSAM wants `(blank, nuclear, whole-cell)`; upstream right-aligns, so a
  single plane lands in the whole-cell slot — which is exactly how the paper handles
  nuclear-only datasets. **Multi-channel (nuclear + membrane) fusion is deliberately NOT
  exposed:** a fused segmentation has no single `c` to file its Label rows under, so it
  needs a Label-domain channel-key decision first. Select the marker channel upstream.
  This is the one CellSAM capability the node does not reach, and it matters most for
  tissue/multiplexed data — the obvious follow-up.
* **Device is an env knob** (`NODELAB_CELLSAM_DEVICE`, `auto|cpu|cuda`), never a socket,
  for the reason `NODELAB_STARDIST_CPU` is: a process-singleton model's device flag would
  silently stop taking effect after the first pull and would make one recipe hash mean two
  devices. An explicit `cuda` with no CUDA device is a hard error, not a silent fallback.
  `resolve_device("cpu")` returns without importing torch at all.
* **Weights** download to `$HOME/.deepcell/models` on first use and need
  `DEEPCELL_ACCESS_TOKEN` (<https://users.deepcell.org>, **non-commercial academic
  licence**). `model_path` loads a local `.pt` and skips both.
* **INSTALLED AND VERIFIED LIVE, 2026-07-29.** cellSAM 0.0.dev1 + weights
  (`cellsam_v1.2`, md5-verified) segment a 256² synthetic 12-cell field as **12/12 cells in
  10.0 s** headless (CPU) and **16.6 s through the GUI**, with the Labels overlay drawing
  per-label colours + outlines over the image and `analysis.measure` chaining off it. That
  matches the paper's ~12 s CPU benchmark; cost scales with cell count because the mask
  decoder runs once per detection. Getting there needed two machine-level fixes that are NOT
  cellSAM bugs — see the kernel `.md` §8: a token pasted with its `<>` placeholder brackets,
  and Norton TLS interception which blocks Python's downloader entirely (Python 3.13 rejects
  the AV root as RFC-non-compliant even when it IS trusted). The weights were fetched through
  the Windows TLS stack instead; `get_model()` is offline from then on, so the GUI needs no
  token. `scripts/_cellsam_smoke.py` reproduces the whole check in one command.
* **Tiling** (`tile`, `tile_size`, `tile_overlap`) routes through `cellSAM.wsi.segment_wsi`
  for large FOVs. Both are `unit="px"` on purpose: CellSAM resizes every tile to 1024²,
  so tile geometry is the model's input space and memory, not a physical extent.

## 6. Coverage

New selftest group `test_segment` (registered before the two structural sweeps):
the structural spec incl. per-method socket **and** Mode gating; both dependency-free
methods end-to-end in 2D and 3D; the property that distinguishes them (a touching pair is
one connected component, so only the watershed recovers the fourth object); every shared
stage; 16 distinct `method × dim × level` recipe hashes (keyed via `node_recipe_hash`
directly — asking a hash question must not load TensorFlow or trip a dependency gate); the
`pixel_size_um`/`z_step_um` fences; and every refusal (the 3D lever under a 2D-only method,
a named foreground layer that does not exist, an unknown method/level).

**CellSAM's glue is covered against a stubbed package** (`_stub_cellsam` injects a module
with a `__spec__` into `sys.modules`, which is what `find_spec` resolves through): singleton
reuse across planes, kwarg forwarding, `model_path` routing, the tiling call's
`iou_depth == overlap`, the `(3,H,W)` no-cells quirk, the contiguous relabel of upstream's
non-contiguous ids, and the shared postprocess applying to a learned method exactly as to a
classical one. StarDist stays run-free by the pre-existing policy (a seconds-long TF model
load + network fetch does not belong in the fast gate); its sockets are audited
structurally and by `test_param_socket_contract`.

Updated: `test_catalog_ported2`'s two watershed pulls; the catalog-size guard
(`audited >= 54`) and the layer-socket counts (`n_out >= 18` in both places — the fold-in
lost one `layer_in` and two `layer_out` sockets and gained one of each); the probe's P1
layer-picker block (now on `analysis.segment` with `method=watershed`, which makes its
long-dormant Mode-wheel branch go live for the first time, and which now also asserts that
both the gated socket and the gated Mode leave and return with the method).

## 7. GUI

**Zero structural GUI work was needed** — palette, card, inspector, domain rails, overlays
and spreadsheet are all registry- and domain-driven, so the new node appeared and the two
deleted ones vanished on their own. What did change: the two Mode-rendering sites now use
`active_modes`, the BOOL checkbox fix, and stale prose in `window._show_capabilities` and
`overlays.TAB_INFO`. Verified by rendering the real window offscreen: the palette lists
**Segmentation** under ANALYSIS (no Watershed / StarDist Segmentation), a `cellsam` card
shows its 13 controls with no `level` row, a `threshold` card shows `connectivity` + both
Modes, and the inspector shows µm² / px units and real checkboxes.

## 8. Follow-ups (not done)

1. **Multi-channel CellSAM** (nuclear + membrane → one segmentation). Needs a decision on
   which `c` a fused Label row belongs to; that is a domain question, not a wiring one.
2. **3D from 2D slices** — u-Segment3D consensus fusion (CellSAM paper Fig. 3d) as its own
   node. Until then the learned methods refuse the 3D lever, by design.
3. `cellsam_extra` vs `cellsam_general` is a free-text socket, not a Mode, so the two
   published names are documented rather than enumerated (a Mode would be nicer once the
   model list is stable).
4. A `Mode`-gated dim lever is *not* the answer for the 2D-only methods: hiding the lever
   would leave `ctx.is_volume` resolved from a hidden value. The explicit refusal stays.
