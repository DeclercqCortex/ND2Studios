# V1.11 — Partial-metadata tolerance in `compute_tile_layout`

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.11

## Goal

Handle ND2 files where `f.sizes['P']` reports more multipoints than
have valid `frame_metadata`. The user's `Well3_…Cy5,TD_Seq0000.nd2`
is a clean example:

- `f.sizes = {'P': 121, 'Z': 51, 'C': 2, 'Y': 1024, 'X': 1024}`
- Only **61 of 121** multipoints have valid stage XY metadata
  (`frame_metadata(i)` returns `None` for M = 61..120)
- 24 GiB on disk; all 12342 frames are present, so the **image data**
  is intact — only the per-frame **metadata** is missing for the
  trailing 60 multipoints. Most likely the acquisition was stopped
  after position 61 but the file's `sizes` field still reports the
  planned 121.

## Bug

`inspect_nd2.py` correctly reports the file's structure and shows
that V1.10's serpentine layout produces a clean 5 × 13 / 61-unique
output for the 61 valid positions. But the **GUI fails** because of
the way `compute_tile_layout` is wired:

1. `LoadWorker.read_nd2_metadata_extended` returns
   `stage_xy_um = [61 entries]` (valid positions only).
2. `LazyND2Volume` stores `n_multipoints = 121` (from `f.sizes`).
3. `MultiAxisViewer.set_volume` passes `stage_xy_um = 61_entries`
   *and* the volume's `n_multipoints = 121` to `LutSidebar`.
4. `LutSidebar` builds `m_indices = list(range(121))`.
5. `TileLayoutWidget` calls `compute_tile_layout(stage_xy_um=61,
   m_indices=range(121))`.
6. The first guard in `compute_tile_layout` —
   `if len(stage_xy_um) >= len(m_indices)` — is **false**
   (61 < 121), so the function falls through to `grid_fallback`,
   producing an 11 × 11 sqrt grid with 121 cells. Empty / wrong.

The diagnostic worked because `inspect_nd2.py` calls
`compute_tile_layout(stage_xy, ...)` without `m_indices`, which
defaults to `range(len(stage_xy_um))` = 61.

## Approach

Make `compute_tile_layout` tolerant of partial metadata:

```python
n_xy = len(stage_xy_um)
if n_xy < len(m_indices):
    # Partial metadata: truncate m_indices to the M's that have
    # stage XY data. Assumes missing positions are contiguous at
    # the end (the typical "acquisition stopped early" case).
    m_indices = list(m_indices[:n_xy])
    partial_metadata = True
else:
    partial_metadata = False
```

Then proceed with the existing path. If serpentine fires (which it
does for partial metadata because there's *almost certainly* sparsity
or revisits), set `serpentine_reason = "partial_metadata"` so the
diagnostic can explain.

**Trigger order in compute_tile_layout:**

1. `partial_metadata` (new, V1.11) — most informative; takes
   precedence when applicable.
2. `revisits` (V1.8) — `max_dup > 1`.
3. `sparse` (V1.10) — `fill_ratio < 0.9`.

If multiple conditions hold, the most informative reason wins.
"partial_metadata" is preferred because it explains the file-level
data loss; the user can still investigate further if they want.

## Key Decisions

1. **Truncate, don't pad.** Padding `stage_xy_um` with `None`s would
   require teaching every cluster/assign step to handle None — much
   bigger surgery. Truncating `m_indices` is one line.
2. **Assume contiguous missing at the end.** Matches "acquisition
   stopped early," the way this comes up in practice. If scattered
   missing positions ever show up, we'll add an explicit
   `valid_m_indices` field; for now the simple truncation handles the
   real cases.
3. **Slider can still scroll the full range.** The viewer's M slider
   uses `volume.n_multipoints = 121`, so the user can still navigate
   to M = 61..120. Those frames render whatever image data is at the
   underlying file position. The tile widget just doesn't make those
   M's clickable navigation targets, since they have no metadata to
   place them with.
4. **`partial_metadata` precedes `sparse`/`revisits`** in the
   diagnostic. The user wants to know first that the file is
   incomplete; the layout shape is secondary.

## Validation

Synthetic test reproducing this exact case:

- Build `stage_xy_um` with the user's first 61 (X, Y) values.
- Pass `m_indices = list(range(121))` to `compute_tile_layout`.
- Assert: `source = "serpentine"`,
  `serpentine_reason = "partial_metadata"`, layout 5 × 13,
  61 unique offsets, M=0 at top-left.
- Regression: dense regular mosaic with full metadata stays on
  physical layout; sparse / revisit cases retain their respective
  reasons.
