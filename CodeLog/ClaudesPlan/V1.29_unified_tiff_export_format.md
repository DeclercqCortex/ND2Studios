# V1.29 — Unify Z-Projection TIFF export and Stitched TIFF export

## Goal

The Z-Projection TIFF export (Export page → "Z-Projection TIFF" tab) and the
Stitched TIFF export (Import page → Stitch M… dialog) must produce files
with **the same metadata and file construction**. Today they diverge:

| Aspect           | Standard `export_tiff_stack`     | `export_stitched_tiff`           |
| ---------------- | -------------------------------- | -------------------------------- |
| Files written    | One per enabled channel          | One combined file                |
| Dim order        | `(T, H, W)` flat or `(T,Z,H,W)`  | `(T, 1, C, H, W)` ImageJ TZCYX   |
| ImageJ hyperstack| No (3D flat); Yes (4D TZYX)      | Yes                              |
| Channel labels   | No                               | `Labels=[<channel names>]`       |
| `unit=um`        | Yes                              | Yes                              |
| `spacing`        | Yes                              | **Missing**                      |
| Resolution tags  | Yes                              | Yes                              |

The user-selected target ("Single multi-channel ImageJ hyperstack") is that
**both paths** write ONE file containing all enabled channels as a
`(T, Z, C, H, W)` ImageJ TZCYX hyperstack with `Labels`, `unit=um`,
`spacing`, `resolution`, and `resolutionunit`.

## Approach

1. **Add `export_tiff_hyperstack(channels, enabled, filepath, bit_depth,
   pixel_size_um, progress_cb)`** in `nd2studios/backend/exporters/tiff_exporter.py`.

   - Accepts `Dict[str, np.ndarray]` of `(T,H,W)` or `(T,Z,H,W)` arrays,
     plus an `enabled` dict.
   - Filters to enabled channels (preserves dict insertion order).
   - Promotes 3-D channels to 4-D with `Z=1` so the output is uniformly
     `(T, Z, C, H, W)`.
   - Validates that all enabled channels share the same `(T, Z, H, W)`.
   - Applies the bit-depth selector. `passthrough` keeps the source dtype.
     `uint8`/`uint16` percentile-stretch each channel independently (0.5–99.5)
     so per-channel contrast is preserved (matches V1.0 behavior).
   - Writes via `tifffile.imwrite(..., imagej=True, photometric="minisblack",
     resolution=(1/px, 1/px), resolutionunit="MICROMETER",
     metadata={"Labels": names, "unit": "um", "spacing": pixel_size_um})`.
   - BigTIFF auto-switch above 3.9 GB.

2. **Update `export_stitched_tiff`** to add `spacing=pixel_size_um` to its
   ImageJ metadata so the two writers agree on the resolution declaration.

3. **Rewire `ExportWorker._export_tiff_stack`** to call
   `export_tiff_hyperstack` once with the full channel dict — no per-channel
   loop, no `_<name>` suffix files. Returns the single filepath.

4. **Rewire `ExportWorker._export_tiff_zstack`** to build a single
   `(T, Z, C, H, W)` ndarray (Z-stack mode) and call the new function. The
   per-channel suffix loop disappears.

5. **Update help text** on the Export page TIFF tab to reflect single-file
   output with channel labels.

6. **Export** `export_tiff_hyperstack` from
   `nd2studios/backend/exporters/__init__.py`.

## Files modified

- `nd2studios/backend/exporters/tiff_exporter.py` — new function

- `nd2studios/backend/exporters/__init__.py` — re-export
- `nd2studios/workers/export_worker.py` — call new function
- `nd2studios/pages/export_page.py` — update help text
- `CodeLog/Updates/CHANGELOG.md` — Changed entry
- `CodeLog/Architecture/ARCHITECTURE.md` — function signature note

## What stays the same

- `export_tiff_stack` is **kept** — `analysis_page.py` still uses it to
  write single-channel label masks. That call site doesn't need
  multi-channel labels or an ImageJ wrapper.
- RGB composite and movie exporters are out of scope.
- Bit-depth UI (`passthrough` / `uint16` / `uint8`) is preserved on the
  Export tab. The Stitch dialog stays passthrough — its UI has no
  bit-depth control, and adding one is a separate concern.

## Reload compatibility

`tiff_loader.read_imagej_tiff_metadata` and
`load_imagej_tiff_channels` already understand `(T, Z, C, H, W)` ImageJ
hyperstacks with `Labels`. Files produced by both writers will round-trip
through the import path identically.
