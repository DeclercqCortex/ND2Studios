# V1.9 — Defensive frame-shape normalization in the viewer

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.9

## Goal

`MultiAxisViewer._compose_current_frame` blew up with
`ValueError: too many values to unpack (expected 2)` because it
assumes every frame returned by a channel data source is 2D `(H, W)`.
That assumption breaks for:

- **RGB / RGBA TIFFs** (e.g. `Stitch_test.tif` from V1.1 export):
  `tifffile.imread(path, key=t)` returns `(H, W, 3)` for RGB pages.
- **Hyperstack TIFFs** with extra T/Z axes leaking through.
- **Future loaders** that don't perfectly match the 2D-per-frame
  contract.

Make the viewer tolerant of shape variation rather than relying on
loaders to be perfect.

## Approach

Add a single helper:

```python
@staticmethod
def _normalize_to_2d(frame: np.ndarray) -> Optional[np.ndarray]:
    a = np.squeeze(np.asarray(frame))
    if a.ndim == 2:
        return a
    if a.ndim == 3:
        if a.shape[-1] in (3, 4):
            r, g, b = a[..., 0], a[..., 1], a[..., 2]
            return (0.299 * r + 0.587 * g + 0.114 * b).astype(a.dtype)
        return a[0]                # Z-stack or T-stack: take first slice
    while a.ndim > 2:
        a = a[0]
    return a if a.ndim == 2 else None
```

Apply it everywhere the viewer reads a frame:

- `_compose_current_frame` (both volume path and flat-channels path).
- `_populate_lut_samples_from_volume` (the histogram seeding loop).

If a non-trivial reduction happens (more than just squeezing), log a
one-line status message via the parent `MainWindow.set_status_text`
so the user knows the loader returned something unexpected.

## Cases handled

| Input shape | Reduction | Result |
|---|---|---|
| `(H, W)` | none | unchanged |
| `(1, H, W, 1)` | squeeze | `(H, W)` |
| `(H, W, 3)` RGB | luminance | `(H, W)` |
| `(H, W, 4)` RGBA | luminance (drops alpha) | `(H, W)` |
| `(Z, H, W)` | first Z slice | `(H, W)` |
| `(T, Z, H, W)` | first T, first Z | `(H, W)` |
| `(1,)` or `(N,)` 1D | n/a | None (can't display) |

## Key Decisions

1. **Defense in the viewer, not the loaders.** Loaders can return
   whatever shape makes sense for their format; the viewer adapts.
   Future TIFF / OME-TIFF / Zarr loaders won't need to maintain a 2D
   contract.
2. **RGB → luminance, not first channel.** Stitch_test.tif and other
   composite outputs encode signal across all 3 channels;
   `0.299·R + 0.587·G + 0.114·B` (Rec. 601) preserves that signal in
   one channel for grayscale display.
3. **No silent reductions.** Status-bar text reports the reduction so
   the user can tell the difference between "I loaded the right file"
   and "I loaded a TIFF that's already RGB".
