# V1.6 — Adaptive clustering tolerance + scrollable tile widget

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.6

## Goal

Two related fixes after the V1.5 flush-grid layout still showed
horizontal stacking on the user's 68-tile data:

1. **Make the clustering robust to typical microscopy acquisitions.**
   V1.5 used `tolerance = 30 % × tile-size-in-µm`. For a 1024 µm tile
   that's ~307 µm — larger than typical column spacing (100-200 µm).
   Result: all real columns collapsed into 1-2 clusters and tiles
   overlapped horizontally.
2. **Let the layout occupy as much room as it needs.** V1.5 fixed the
   widget at 240 px tall; with 17 rows letterboxed into that, each
   tile renders ~10 px and labels overlap. We need to give the
   widget a "natural" size based on tile count and let the sidebar
   scroll when that exceeds the visible area.

## Approach

### 1) Adaptive bimodal clustering

Replace the fixed-fraction tolerance with a tolerance derived from
the gap structure of the data:

```python
def _cluster_axis(values, max_tolerance=None):
    sorted_vals = np.sort(values)
    diffs = np.diff(sorted_vals)
    nonzero = diffs[diffs > 1e-6]
    if len(nonzero) == 0:
        return [mean(sorted_vals)]
    sorted_gaps = np.sort(nonzero)
    if len(sorted_gaps) == 1:
        tol = sorted_gaps[0] * 0.5
    else:
        ratios = sorted_gaps[1:] / sorted_gaps[:-1]
        i = argmax(ratios)
        if ratios[i] > 3.0:
            # Bimodal: gap ratio > 3 between "small" and "large" gaps.
            # Tolerance = midpoint between the largest small gap and
            # the smallest large gap.
            tol = (sorted_gaps[i] + sorted_gaps[i+1]) / 2
        else:
            # Unimodal (regular grid, no jitter): half the smallest gap.
            tol = sorted_gaps[0] * 0.5
    if max_tolerance is not None:
        tol = min(tol, max_tolerance)
    # ... sweep-line clustering with this tol ...
```

`max_tolerance` is kept as a sanity cap (defaulting to
`tile_size_um × 0.5`) so a degenerate single-row scan with a
tiny accidental gap doesn't get clustered into hundreds of separate
positions.

This handles:

- **Regular grid, no jitter** (most common): all positive gaps equal
  to the step → unimodal → tolerance = half the step → clusters
  separated correctly.
- **Regular grid + stage jitter** (well-calibrated stages, ~µm
  jitter): bimodal → tolerance = jump midpoint → jitter absorbed,
  steps preserved.
- **Tile size much larger than step** (the user's case): tolerance
  comes from data, not tile size, so heavy overlap acquisitions
  cluster correctly.

### 2) Auto-sized tile widget + scrollbars

`TileLayoutWidget`:

- Drop the V1.5 ``setFixedHeight(240)``.
- After every `set_tile_layout` call, set `setMinimumSize` to
  `(n_cols × 50 + margins, n_rows × 50 + header + margins)`.
  50 px per tile is comfortable for 2-digit M labels.
- Letterbox painting unchanged — the widget paints at whatever size
  the layout actually gives it, which will be ≥ minimum.

`LutSidebar`:

- Remove the explicit `tile_widget.setFixedHeight(...)` call.
- Switch the body's horizontal scroll policy from
  `Qt.ScrollBarAlwaysOff` to `Qt.ScrollBarAsNeeded` so wide mosaics
  also work.

`TileLayoutDialog`:

- Wrap the widget in a `QScrollArea` so a very large layout still
  scrolls within the modal rather than getting squashed.

## Key Decisions

1. **Data-driven tolerance, not tile-driven.** Tile size is *not* a
   reliable upper bound on step size; acquisitions with heavy overlap
   routinely have step ≪ tile. Driving the tolerance from gap
   structure makes the algorithm independent of acquisition style.
2. **Sanity cap at 0.5 × tile_um.** Protects against pathological
   single-row scans where every M is at the same Y; without a cap,
   a tiny rounding error could produce a cluster boundary.
3. **50 px target tile size.** 2-digit labels fit clearly. Comfortable
   density. The user can still hit `⤢` for an even bigger view.
4. **Both scroll directions on demand.** Simpler than dynamically
   choosing one, and accommodates wide-format mosaics if they appear.

## Validation

- Regular 4 cols × 17 rows, step 100 µm, tile 1024 µm: V1.5 clusters
  to 1 col, V1.6 clusters to 4 cols.
- Regular 4 × 17, step 200 µm, tile 200 µm: both versions get 4 cols.
- 4 × 17 with ±2 µm jitter, step 100 µm: bimodal detection → 4 cols.
- All-equal positions (single-position file): 1 cluster, no crash.
