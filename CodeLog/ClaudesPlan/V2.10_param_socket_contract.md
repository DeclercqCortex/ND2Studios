# V2.10 — The param↔socket contract: 18 nodes rebuilt + a permanent guard (2026-07-28)

> **Status: BUILT + all gates green.** Addendum to canonical `V2.00`. Closes a defect class
> that spanned a third of the catalog and that no behavioural test could have caught.

## 0. The defect class

The engine does **not** filter params against a node's socket list
(`engine.py:404` — `params = {**node.params, "__modes__": dict(state)}`). So a compute can
read `ctx.params.get("X")` while `register_node` never declares a socket `X`, and:

* headlessly everything works — a test or script just passes `X` and it arrives;
* in the **GUI** the param is unreachable, because the inspector builds its widgets from
  `NodeSpec.inputs`. The value is pinned to its fallback forever.

No functional test can see this: the node computes the right answer for the only value it
can ever have. It is a *structural* defect, so it needs a *structural* check.

The **mirror** case — a socket declared that no compute reads — is the "live-looking GUI
control the selected kernel path silently ignores" that the `track.objects` adversarial
review established as **charter-forbidden**.

Found while fixing `analysis.extract_boundary` (V2.08 §10): a sweep of all 55 node types
flagged **28**, of which **18 were real defects**.

## 1. Method

An AST sweep of `nodegraph/nodes.py` comparing params-read against sockets-declared, then a
per-family judgment pass (10 families, each verdict adversarially refuted), graded against
an independent resolver. **1 verdict was overturned and 10 proposed edits were caught as
unsafe** before anything was applied.

The naive sweep is badly false-positive-prone, and resolving that was most of the work.
Keys reach `ctx.params` through five indirections a literal scan cannot see:

| indirection | example | would falsely report |
|---|---|---|
| helper with a variable key | `_radius_px(ctx, "radius", 0.3)` | every `radius` socket dead |
| **constructed** key | `_radius_z_px` reads `name + "_z"` | every `radius_z` socket dead |
| **transitive** forwarding | `_rad(n)` → `_cleanup_um(n)` → `ctx.channel(0).param(n)` | 3 histogram sockets dead |
| subscript, not `.get` | `ctx.params["min_radius_z"]` | both spots axial sockets dead |
| per-channel derive (C8) | `ctx.channel(c).param("emission_nm")` | deconvolve's optics dead |

Resolving all five took 28 flags → **1**, and that one is a genuine documented alias.

## 2. Verdicts

**No action — 10 nodes.** All seven `enhance.*` radius/sigma nodes plus `detect.spots`'
lateral radii, `analysis.threshold`'s `threshold` (already correctly `available_in`-gated to
the `fixed` method) and `enhance.deconvolve`'s `emission_nm`/`na` were false positives of the
indirections above. `util.resample`'s `scale` is a real back-compat alias (read only as the
fallback inside `scale_xy`'s lookup) — the sole allowlist entry.

**One verdict overturned by refutation.** `enhance.deconvolve` was told to declare
`reads_domains={VOXEL}`; the refuter proved the empty declaration is a *documented locked
decision* for the whole enhancement family (annotated nodes are domain-*introducers*;
`nodelab_v2/ops.py:52` supplies the VOX chip at the loader and it flows through). Applying it
would have made 7 of 14 in-family nodes inconsistent. **Not applied.**

**Rebuilt — 18 nodes.**

Every default equals the old hardcoded fallback, so **no existing graph changes behaviour**.
Domain rails were corrected on 7 nodes; `analysis.label`/`watershed` now also declare
`adds_domains ⊇ {VOXEL}` (they emit a label *raster*, not only a table).

### Three judgments worth the reasoning

**`transform.transfer_domain` — Modes, not sockets, and the legacy param form REFUSED.**
Domains and reducers are closed enumerations, so they render as header pickers (the
`util.stack` / `analysis.threshold` precedent); `attr` is a layer *name*, so it stays an
`InString`. The dropdowns offer **lattice domains only** — `execute_transfer` raises on a
BridgeStep, so a Label/Point/Track/Mesh entry would be a control that always errors, and
every lattice pair is routable, so the cross-product holds no dead choice. Back-compat by
silent fallback proved *impossible*: the engine passes the **resolved** mode state, so
"unset" and "explicitly set to the default" are indistinguishable, and honouring the param
would mean guessing which happened. A stale headless caller is therefore **refused with
instructions** — silently running it on the defaults is the exact failure this pass exists to
remove. `reducer` is additionally refused on a pure broadcast (no axes dropped ⇒ it is
ignored); `available_in` cannot express that, since it gates only a *rectangle* of mode
values and "src drops an axis vs dst" is not one.

**`detect.stardist_nuclei.disable_gpu` — an env var, deliberately NOT a socket.**
`get_stardist_model` is a process **singleton** that returns the cached model and ignores the
flag on every call after the first, and the kernel must clear `CUDA_VISIBLE_DEVICES` *before*
the first TF import. As a socket it would be a live control that silently stops working after
one pull and whose effect depended on process history — which would also make the memo
non-deterministic (identical recipe hash, different device). Now `NODELAB_STARDIST_CPU`,
following the `NODELAB_GL` precedent (`nodelab_v2/app.py:15`).

**`enhance.deconvolve.z_step_um` — the one PROVEN dead socket, and a real bug.**
The 3D-only socket declares `derive="z_step_um"`, so an *unset* socket already resolves to
the calibration — but the compute read `ctx.calib("z_step_um")` **directly**, so a *set* one
was silently dropped. C8 taught this node to honour an `emission_nm`/`na` override and left
`z_step_um` behind. The calib read stays unconditional (so the memo fence survives in the
common unset case) and an override now wins, re-keying through params.

## 3. The permanent guard

`nodegraph/selftest.py::test_param_socket_contract` re-runs the resolver over the catalog and
fails on either direction, with a documented allowlist (1 entry). It:

* resolves all five indirections above, and **asserts it can** — four positive probes, so it
  cannot pass vacuously by seeing nothing;
* audits only computes whose `__module__` is `nodegraph.nodes`. Without that, a full-suite run
  flags every `test.*` fixture (their computes live in `selftest.py`), which would be
  order-dependent — green alone, red in suite — the fixture/registry overlap the project
  already warns about;
* asserts a coverage floor (`audited >= 55`) so a broken index fails loudly instead of passing
  with nothing to check.

**Verified it actually fails:** re-registering `analysis.label` without its `mask` socket is
caught as unreachable, and with an extra `ghost` socket as dead. Both restore clean.

The guard's strictness paid for itself immediately — it caught the `ctx.params["X"]` subscript
gap (via `detect.spots`' axial radii) that the standalone script had missed.

Coverage added beyond the guard: a non-default-name chain
(threshold→label/watershed/edt each reading the previous node's renamed output) proving the
redirects compose; a missing source layer raising rather than no-opping; `stats` selecting and
validating columns; and `transfer_domain`'s modes proven **live** — the old test set `reducer`
to a value equal to the default, so it could not have told a working lever from an ignored
one, which is precisely how the missing sockets survived there.

## 5. Forward

* `analysis.roi_mask.shapes` is now a JSON-text socket. That makes a previously inert node
  usable, but the real answer is an ROI-draw surface in the GUI writing the same list.
* Two agent-volunteered findings were **out of scope** and are NOT fixed: `enhance.bilateral`
  carries a `dim` lever although it is honestly stack-of-2D (a GUI-hint or lever-removal
  decision), and `enhance.dog` has no eager guard that the axial `high_sigma >= low_sigma`.
* The multi-layer keying UX (`CONTEXT_v2_remaining` §6.4) is now *half* solved: every node can
  be pointed at a named layer, but nothing offers a **picker of the layers actually present**
  — the sockets are free text. That is the natural next step.
  **Correction (2026-07-29):** this section originally called that "purely a GUI change" on the
  grounds that `propagate_meta` already carried the layer catalog. It does not.
  `MetaEnvelope.layers` is declared and **never populated** — the pass accumulates `domains`
  only, and the field's single consumer (`engine.py:501`) just copies it. The picker needs the
  edit-time layer catalog built first, which is core work, not GUI work. Built in
  [`V2.11`](V2.11_layer_picker.md).
