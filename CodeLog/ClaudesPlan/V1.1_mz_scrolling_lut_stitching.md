# V1.1 — M/Z scrolling, live channel toggle, LUT histogram, M stitching

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.1

## Goal

Address four limitations surfaced after V1.0 first-load:

1. The viewer collapses Z to a single projection at import and pins M to
   position 0. Users want to **scroll through M positions and Z slices**
   inside any timepoint.
2. Channel show/hide only takes effect on Confirm Import. Users want a
   **live toggle** in the viewer itself.
3. Auto-percentile contrast is a black box. Users want **manual LUT
   histogram manipulation per channel** — drag min/max, set gamma.
4. Multi-position acquisitions need to be **stitched into a single
   field** and exported as a new file, leaving the original ND2 untouched.

## Non-Goals (intentional, V1.1)

- No multi-Z plugin support. The recipe pipeline still operates on
  `(T, H, W)`; Z scrolling is a *viewer* feature. If the user picks
  `Z projection = none`, the pipeline runs on a single user-chosen Z
  slice, not the full Z stack.
- No manual offset entry for stitching. We use ND2 stage XY positions
  exclusively in V1.1; manual override is V1.2.
- No overlap blending in the stitch — V1.1 places tiles, V1.2 can add
  feathered seams.
- No ND2 output. Stitch results go to TIFF (single-channel or RGB) since
  writing valid ND2 files needs Nikon's SDK.
- No theme switching, no autosave (still out of scope).

## Approach

### Data model: keep `(T, H, W)` as the recipe contract

The recipe / export pipeline keeps the V1.0 contract: each channel is a
`(T, H, W)` array (or lazy proxy). M selection and Z mode are *viewer
configuration* that determines *which* (T, H, W) slice the rest of the
app sees.

This is the cleanest way to add M/Z scrolling without breaking
plugins. Plugins are written for `(T, H, W)`; we don't want to teach
all 19 of them about Z planes.

### New backend: `LazyND2Volume`

A class exposing `(M, T, Z, H, W)` lazy reads against an ND2 file. The
viewer creates one of these and asks for individual `(m, t, z)` frames
on demand. When the user picks an M and a Z mode (project / fixed
slice) the volume produces a `LazyND2Channel` (V1.0 contract) for the
recipe/export pipeline.

```python
class LazyND2Volume:
    shape: Tuple[int, int, int, int, int]   # (M, T, Z, H, W)
    n_channels: int
    channel_names: List[str]

    def get_frame(self, c, m, t, z) -> np.ndarray:
        """Return a single (H, W) frame."""

    def to_lazy_channel(self, c, m, z_mode, z_index=0,
                         z_start=0, z_end=None) -> LazyND2Channel:
        """Collapse to a (T, H, W) lazy channel for the pipeline."""
```

### New widget: `LutHistogramWidget`

Compact widget (one per channel) showing:
- Histogram of pixel intensities computed from a sample of frames
  (every Nth frame to stay fast on long timeseries).
- Two draggable handles for `lo` and `hi` (the displayed contrast
  bounds).
- Gamma slider.
- Reset (= auto-percentile 0.5..99.5) and Auto buttons.

Emits `contrast_changed(channel_name, lo, hi, gamma)` whenever a
handle moves. The viewer subscribes and recomposes immediately.

The histogram is rendered with `MplCanvas` (already in `widgets/common.py`).
Drag interactions are matplotlib `event_handlers` with two vertical
markers.

### New widget: `MultiAxisViewer`

A new top-level viewer that replaces the V1.0 `ImageViewer` on the
Import and Recipe pages. Layout:

```
┌────────────────────────────────────┐
│       large image canvas           │
│                                    │
│                                    │
├────────────────────────────────────┤
│  M ◀────●────────▶  3 / 9          │
│  T ◀──────────●──▶  142 / 200      │
│  Z ◀────●────────▶  4 / 11         │
├────────────────────────────────────┤
│  ☑ DAPI    [ blue ▾ ] [histo ▆▆▆] │
│  ☑ GFP     [green ▾ ] [histo ▆▆▆] │
│  ☐ TRITC   [ red  ▾ ] [histo ▆▆▆] │
└────────────────────────────────────┘
```

- M slider visible only if `M > 1`. Z slider visible only if `Z > 1`
  *and* the user is in "show Z planes" mode (ie not a projection).
- Per-channel rows hold: enable checkbox, color combo, mini LUT
  histogram. Toggling enable / changing color / dragging LUT recomposes
  immediately.
- The viewer wraps a `LazyND2Volume`; sliders trigger `get_frame`.

The V1.0 `ImageViewer` stays available for any code that wants the
simple compositor (e.g. the Stitch preview).

### New backend: `stitch_exporter`

```python
def compute_tile_layout(stage_xy_um: List[Tuple[float, float]],
                       pixel_size_um: float,
                       tile_h: int, tile_w: int) -> StitchLayout:
    """Place tiles on a canvas based on stage XY (in pixels).

    Returns the canvas size and per-tile (y, x) corner offsets.
    Falls back to a grid layout if stage_xy is empty or degenerate.
    """

def stitch_timepoint(tile_frames: List[np.ndarray],
                    layout: StitchLayout) -> np.ndarray:
    """Place tiles on the canvas for one timepoint."""

def export_stitched_movie(volume: LazyND2Volume,
                         layout: StitchLayout,
                         channel_indices: List[int],
                         filepath: str,
                         z_mode: str = "max",
                         progress_cb=None) -> None:
    """Walk T → for each timepoint, walk M, fetch frame, place on canvas,
    write to multi-page TIFF (or RGB composite if multiple channels)."""
```

### New page (or dialog) for stitching

A `StitchDialog` is launched from a "Stitch M positions" button on the
Import page. It shows:
- Layout preview (a small canvas with tile rectangles drawn at stage
  XY positions).
- Tile selector (checkbox per M position).
- Channel selector + color choice (mirrors Import).
- Z mode (max / mean / min / fixed slice).
- Output path picker.
- Export button → spawns `StitchWorker`.

A dialog is lighter weight than a fourth page and matches the
"this is a one-shot operation" feel.

### Data model additions

`ND2StudiosRecord` gains:

```python
m_index: int = 0                       # currently displayed M position
z_view_mode: str = "max"               # max/mean/min/none
z_view_index: int = 0                  # which Z slice when z_view_mode == "none"
lut_params: Dict[str, Dict[str, float]] = {}
    # {channel_name: {"lo": float, "hi": float, "gamma": float}}
```

These round-trip through `to_dict` / `from_dict` so a saved session
restores M/Z navigation state and LUT settings.

The `_raw_volume: Optional[LazyND2Volume]` cache is added to the
record (not serialized; rebuilt from `import_config.filepath`).

## Key Decisions

1. **Viewer-time M/Z navigation; pipeline-time M selection + Z mode.**
   Plugins stay simple. The volume → channel collapse step happens
   when the user is satisfied with viewer settings.
2. **LUT params live on the record.** Save/load preserves contrast
   choices; Recipe and Export read from the same source.
3. **Stitch by stage XY only in V1.1.** Manual override is real work
   (cross-correlation, optimization) and belongs in its own version.
4. **Stitch output = TIFF.** Writing ND2 from scratch requires Nikon's
   SDK. We document the choice and move on.
5. **Stitch is a dialog, not a page.** It's a one-shot derived export,
   not part of the normal pipeline. Adding a fourth page would imply
   it sits in the recipe/export flow, which it doesn't.

## Open questions

- For long timeseries, computing histogram from every frame is slow.
  Default to sampling at most 50 frames; expose a "Refresh from current
  frame only" button so users can re-sample after navigation.
- Stitch preview density: at large M counts the layout preview should
  decimate (max 50 tile rectangles drawn).
