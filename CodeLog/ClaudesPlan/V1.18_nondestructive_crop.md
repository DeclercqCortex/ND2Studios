# V1.18 — Non-Destructive Crop (Re-crop Without Re-import)

## Goal

When the user applies a crop on the Recipe page the original (uncropped)
channel data must remain accessible so they can apply a different crop region
without navigating back to the Import page. The existing implementation was
almost correct but stored the pre-crop snapshot as a page-local attribute
(`RecipePage._original_raw_channels`), which was lost whenever the user
navigated away from the Recipe tab. For ND2 files the snapshot was
reconstructed from `_raw_volume` on re-entry; for TIFF files (no volume) the
Reset Crop button was enabled but non-functional after tab navigation.

## Approach

Move `_original_raw_channels` from `RecipePage` to `ND2StudiosRecord`.
Because `ND2StudiosRecord` is the single source of truth for session state, the
snapshot now survives tab switches for every file type with no reconstruction
hacks.

### Files to modify

| File | Change |
|------|--------|
| `nd2studios/core/experiment_manager.py` | Add `_original_raw_channels` field to `ND2StudiosRecord` |
| `nd2studios/pages/recipe_page.py` | Replace `self._original_raw_channels` with `exp._original_raw_channels`; remove the `_raw_volume` reconstruction block from `on_activated()` |
| `CodeLog/Updates/CHANGELOG.md` | Document under Bug Fixes |
| `CodeLog/Architecture/ARCHITECTURE.md` | Note new field in session-state table |

## Key Decisions

- **No serialization.** `_original_raw_channels` is in-memory only (same
  policy as `_raw_channels`, `_raw_volume`). After a session save/reload, no
  crop is active (the current policy for `crop_rect` too), so there is no
  inconsistency. The ND2 file on disk is never touched.
- **Lazy proxies stay lazy.** For ND2 sources `_original_raw_channels` holds
  `LazyND2Channel` objects. Storing them on the record is free — no arrays are
  materialized.
- **Re-crop always from original.** `_apply_crop()` already crops from
  `_original_raw_channels` (first snapshot wins), so applying a second crop
  region does not nest crops.
