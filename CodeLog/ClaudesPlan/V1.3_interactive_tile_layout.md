# V1.3 — Interactive tile layout (sidebar nav + stitch selection)

**Date:** 2026-04-30
**Author:** Gabriel Declercq (with Claude)
**Status:** in progress
**Branch:** Version-1.3

## Goal

Make the tile layout the primary navigation surface for multi-position
ND2s. The V1.2 corner thumbnail (160×120) breaks down at 68 tiles —
each tile is two pixels wide and unreadable. The user needs:

1. The layout shown at usable size, in the LUT sidebar.
2. Clicking a tile in the sidebar jumps the M slider to that tile.
3. An "expand" button that pops a much larger version for files where
   even the sidebar size is tight.
4. In `StitchDialog`, clicking tiles toggles their inclusion in the
   stitch — replaces the per-tile checkbox grid.

## Non-Goals (intentional, V1.3)

- No Z scrolling on the tile widget. The widget is XY-only.
- No drag-rect selection in stitch mode. Click-toggle is enough for
  the common cases; a marquee can come in V1.4 if 68-tile selection
  workflows demand it.
- No overlap blending in the stitch. Still parked on V1.4+.
- No keyboard navigation (arrow keys to move M). Mouse-only for V1.3.

## Approach

### `TileLayoutWidget` — supersedes `TilePreviewWidget`

Same `QPainter` rendering math reusing `compute_tile_layout()`, but:

- **Configurable size**, not the V1.2 fixed 160×120.
- **Two modes** controlled at construction or via `set_mode()`:
  - `"navigate"` — click a tile → emit `navigate_requested(m: int)`.
  - `"select"` — click a tile → toggle membership in
    `selected_indices: set[int]`; emit `selection_changed(set[int])`.
- **Cached widget-space rects**. On every repaint we recompute each
  tile's rect in widget pixel coordinates and stash it in a list
  parallel to `m_indices`. `mousePressEvent` runs point-in-rect against
  this list; the topmost hit wins.
- **Always shows the current M** as a highlighted ring (purple in
  navigate mode, green in select mode if selected).
- **Hover preview**: paints a faint outline on the tile under the
  cursor so the user knows what they're about to click.
- **Expand button** (small `⤢` glyph in the corner) emits
  `expand_requested`. The host (`LutSidebar`) opens a
  `TileLayoutDialog` showing the same widget at a much larger size.

`TilePreviewWidget` is removed (only `multi_axis_viewer` imports it,
and we update that import).

### `TileLayoutDialog` — modal "expand"

Trivial wrapper: a `QDialog` with `setMinimumSize(720, 600)`,
containing a `TileLayoutWidget` configured with the host's current
state (mode, tile data, current M, selected set). On
`navigate_requested`, the dialog forwards the signal and closes — one
click → "find that tile" is done. On `selection_changed` (in select
mode), the dialog forwards the signal continuously and stays open —
selection is iterative.

### `LutSidebar` — Tiles section above the LUTs

A new collapsible "Tiles" group is inserted at the top of the inner
scroll area. Layout:

```
┌── LutSidebar ────────────────┐
│ ▶  Tiles                    │  ← independently collapsible
│ ┌──────────────────────────┐│
│ │   tile layout widget     ││
│ │   (sidebar size, navigate││
│ │    mode)                 ││
│ └──────────────────────────┘│
│ ▶  LUTs                     │  ← V1.2 toggle still here
│   …per-channel LUTs…        │
└──────────────────────────────┘
```

`LutSidebar.set_tile_layout(stage_xy_um, pixel_size_um, tile_h, tile_w,
n_multipoints, current_m)` rebuilds the embedded widget. The sidebar
re-emits the widget's `navigate_requested(m)` as
`tile_navigate_requested(m)` for the viewer.

### `MultiAxisViewer` changes

- Remove the corner `TilePreviewWidget` instance and its
  `_reposition_overlay()` machinery.
- Forward `stage_xy_um` and friends to `LutSidebar.set_tile_layout(...)`.
- Subscribe to `lut_sidebar.tile_navigate_requested(m)` and set the M
  slider value (which fires the existing `_on_m_changed` path —
  highlight, LUT re-sample, frame redraw).
- Also notify the sidebar when M changes (via the existing
  `_on_m_changed`) so the highlight stays in sync with slider drags.

### `StitchDialog` changes

Replace the matplotlib `MplCanvas` preview *and* the row of per-tile
`QCheckBox`es with a single `TileLayoutWidget` in `select` mode. The
"Select all / Select none" buttons remain — they call
`widget.set_selected_indices(set(range(N)))` /
`set_selected_indices(set())`. The dialog reads
`widget.selected_indices()` when the user clicks Export.

This shrinks `stitch_dialog.py` (the MplCanvas + checkbox + grid code
all goes) and gives the user a single, consistent interaction
pattern.

## Key Decisions

1. **One widget, two modes.** Same paint code, same hit-testing — only
   the click handler differs. Cleaner than two parallel classes.
2. **Hit-testing in cached widget pixels.** Rebuilding the layout-to-
   pixel mapping on every click is wasteful; we cache after every
   paint and invalidate on resize.
3. **The Tiles section is independently collapsible from the LUTs
   section.** Two distinct workflows (spatial navigation vs contrast
   tuning) deserve separate hide controls.
4. **Expand modal in `navigate` mode auto-closes after click; in
   `select` mode it stays open.** Different goals: "find one tile" is
   one-shot, "build a stitch set" is iterative.
5. **Stitch dialog drops the per-tile checkbox grid entirely.** The
   visual layout is the better UI; carrying both would be confusing.

## Validation

- `py_compile` clean across new + modified files.
- AST import-resolution check (every `nd2studios.*` import resolves).
- Manual GUI test on a 68-tile ND2:
  - Sidebar tiles widget shows the layout at readable size.
  - Click any tile → M slider jumps; LUT histograms re-sample for the
    new M; image redraws.
  - Click expand → modal pops with a large version; click a tile →
    M slider jumps and modal closes.
  - Open stitch dialog → tiles widget is in select mode; click toggles
    selection; canvas size in the layout summary updates as you click.
  - Export → produces the same TIFF as V1.2 with the user-selected
    subset.
