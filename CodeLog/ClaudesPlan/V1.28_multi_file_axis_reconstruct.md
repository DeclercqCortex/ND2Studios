# V1.28 — Universal multi-file reconstruction

## Goal

Replace V1.27's Z-only multi-file Browse with an explicit
**Reconstruct…** dialog: the user picks N files, sees each file's
`(T, M, Z, C, H, W)` in a table, and tells the app which axis to chain
along (`T`, `M`, `Z`, or `C`). Downstream code (viewer, recipe, export,
batch, analysis) keeps seeing a single composite volume — no special
casing per axis.

## Motivating datasets

- **T-chain (new):** `E:\ELISA_3D\20260515_141025_848\Count0000X_..._Seq000X.nd2`
  ×5. Each file `sizes={P:66, Z:10, C:2, Y:1024, X:1024}`; the five files
  are sequential timepoints (event 0's `Time [s]` advances 7.7 → 1715
  → 3417 → 5128 → 6844). Need `chain_axis='T'` to combine into
  `(M=66, T=5, Z=10, C=2)`.
- **Z-chain (V1.27 regression):** the 76-file `ZStack####` dataset at
  `F:\ELISA_in_LLS_Density_Test\20260515_112707_675\` continues to work
  via `chain_axis='Z'`.

## Decisions (locked with user)

1. **Replace V1.27 Browse multi-select.** Browse single-file only; the
   new Reconstruct button is the canonical multi-file route.
2. **ND2 or TIFF, not mixed** in a single reconstruction.
3. **Auto-suggest chain axis from filename, user override allowed.**
4. **Each file contributes its native axis size**, summed across files.

## Backend changes

### `backend/nd2_volume.py`

- `LazyMultiFileND2Volume(filepaths, chain_axis="Z")`. Validates every
  axis *except* `chain_axis` matches across files. Cumulative-offset
  table `chain_offsets` per `chain_axis` indexes into the file list.
- `get_frame(c, m, t, z, z_mode, ...)` routes the chain coordinate to
  the owning file; non-chain coordinates pass through. For
  `chain='Z'` + `z_mode in {max,mean,min}`, reduces planes across
  files (V1.27 behavior).
- Rename `MultiFileLazyZChannel` → `MultiFileLazyChannel`. Its
  `_read_frame(t_local)` calls into the composite using whichever
  coordinate the chain axis controls.
- `to_lazy_channel(c, m, z_mode, z_index, ...)` returns:
  - `chain='T'` — `MultiFileLazyChannel` walking files along T.
  - `chain='M'` — directly delegates to the file owning that M
    (uses existing `LazyND2Channel`).
  - `chain='Z'` — V1.27 logic preserved (`MultiFileLazyChannel` for
    projections, single-file delegation for `z_mode='none'`).
  - `chain='C'` — delegates to the file owning channel `c`.
- `all_channels_as_lazy(m, z_mode, z_index)`:
  - `chain='C'` — iterates the concatenated channel name list, each
    name resolved to its owning file.
  - Otherwise — iterates file 0's channel names (validated identical).
- `reopen()` round-trips `(filepaths, chain_axis)`.

### `backend/nd2_loader.py`

`read_nd2_metadata_extended_multi(filepaths, chain_axis="Z")`:

| chain | overrides |
|---|---|
| `Z` | `n_zslices` = sum, `z_step_um` from event `Z Coord [µm]` deltas, `stage_z_um` |
| `T` | `n_timepoints` = sum, `frame_timestamps_s` concatenated (file *i* offset by `events[0]['Time [s]']` for monotonic series) |
| `M` | `n_multipoints` = sum, `stage_xy_um` concatenated |
| `C` | `n_channels` = sum, `channel_names`/`exposure_ms`/`emission_nm`/`excitation_nm`/`colors` concatenated |

Always adds `source_filepaths` and `chain_axis` to the dict.

### `backend/tiff_loader.py`

New `LazyMultiFileTIFFVolume(filepaths, chain_axis="Z")` mirroring the
ND2 composite's surface. Each member file wrapped via existing
`get_tiff_info` / `read_imagej_tiff_metadata` / `LazyTIFFChannel`.
Single-channel TIFFs treat C=1; ImageJ multi-channel TIFFs use the
metadata-derived layout.

Add a cheap `read_tiff_meta_fast(path)` helper that returns
`{n_t, n_z, n_c, height, width, dtype, channel_names, pixel_size_um}`
for the dialog table.

## Worker

`workers/load_worker.py`:
- `LoadWorker.__init__` gains `chain_axis: str = "Z"`.
- `_load_nd2_multi` reads `read_nd2_metadata_extended_multi(paths, chain_axis)`,
  builds `LazyMultiFileND2Volume(paths, chain_axis)`, and builds
  channel proxies via `volume.to_lazy_channel(...)`.
- New `_load_tiff_multi` does the same for the TIFF composite.
- `run_task()` routes by extension and `len(filepaths)>1`.

## Dialog (new file)

`pages/reconstruct_dialog.py` — `ReconstructDialog(QDialog)`:

- File table (`QTableWidget`): `#`, filename, T, M, Z, C, HxW, dtype.
- Buttons: Add files…, Remove selected, Move ↑, Move ↓.
- File-type lock: first added file's extension (`.nd2` or `.tif`/`.tiff`)
  fixes the type; subsequent adds must match.
- Chain-axis combo box (`T / M / Z / C`).
- Auto-suggest label: detects shared filename pattern, preselects combo.
- Combined-shape preview line, live-updated.
- Load button disabled when invalid; tooltip explains why.

Filename pattern detection (case-insensitive, must hit ≥2 filenames):
- `Count\d+|T\d+|Time\d+` → `T`
- `ZStack\d+|Z\d+` → `Z`
- `M\d+|Pos\d+|P\d+` → `M`
- `C\d+|Ch\d+|Channel\w+` → `C`

On `accept()`: caller reads `filepaths()` and `chain_axis()` getters.
