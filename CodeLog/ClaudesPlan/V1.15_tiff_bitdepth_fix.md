# V1.15 — TIFF bit-depth fix (black display + 8-bit export)

## Goal
Fix two related bugs:
1. TIFF files loaded into the viewer appear black because the LUT
   auto-percentile is skipped when data dtype differs from the initial
   `_hi=65535` default.
2. Multi-channel stitch exports are silently converted to 8-bit RGB via
   `_percentile_uint8`, losing the original bit depth.

## Root Causes

### Bug 1 — `LutHistogramWidget.set_data()` condition
The auto-percentile guard is:
```python
if self._lo == 0.0 and self._hi == self._dtype_max:
```
`_hi` starts at 65535.0. After `_dtype_max` is updated from the actual
data dtype (e.g. float32 with max ~0.5), `_hi != _dtype_max`, so the
percentile branch is never entered and the widget stays at 0–65535.
Any data with values below ~16 (out of 65535) renders as black.

### Bug 2 — `export_stitched_tiff()` RGB path
When `rgb=True` (triggered whenever ≥2 channels are selected in the
stitch dialog), every channel is passed through `_percentile_uint8()`
and written as `uint8`. The stitch dialog always sets
`rgb=len(channel_indices) > 1`, so multi-channel exports are *always*
8-bit regardless of source depth.

Additionally, the `not rgb` path only writes `channel_indices[0]`,
silently discarding all additional channels.

## Approach

### Fix 1 — `lut_histogram.py`
Add a `_contrast_explicitly_set: bool = False` instance flag.
- Set it `True` in `set_contrast()` (the only entry point for
  programmatic/user-driven contrast changes).
- Replace the fragile dtype comparison with:
  `if not self._contrast_explicitly_set:`
- This means: auto-percentile is applied unless the user (or session
  restore) has explicitly set a contrast, regardless of dtype.

### Fix 2 — `stitch_exporter.py`
Remove the `_percentile_uint8` conversion from the multi-channel path.
Write every selected channel as a separate `photometric="minisblack"`
page in the volume's original dtype (e.g. uint16). This creates an
ImageJ-compatible hyperstack that Fiji/napari read correctly.

The now-unused `_percentile_uint8` import from composite_exporter and
the `rgb` conditional are removed from the inner loop.

### Fix 3 — `stitch_dialog.py`
Change `rgb=len(channel_indices) > 1` → `rgb=False` so the stitch
worker always calls the passthrough-dtype path.

### Fix 4 — `load_worker.py` (minor)
Add `"dtype"` key to the TIFF metadata dict so the Import page
metadata table shows the correct bit depth instead of an empty cell.
