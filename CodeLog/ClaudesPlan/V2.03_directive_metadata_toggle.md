# V2.03 — Directive addendum: per-edge metadata intelligence + the 2D/3D node toggle

> **Status: amendment addendum to the LOCKED design.** V2.00 remains the canonical
> locked doc; this file records the design delta forced by the **2026-07-21 user
> directive** and is cross-referenced from V2.00 §13/§14. Nothing here re-opens a
> V2.00 §2 / V2.02 §1 locked decision except the one explicitly noted (the *rendering*
> clause of decision 4). Provenance: distilled from a 36-agent fan-out → dedup →
> adversarial per-hole verification workflow (2026-07-21); 26 holes verified against
> the 11 locked decisions (7 REAL, 19 PARTIAL; 8 blocker / 16 major / 2 minor; only
> 1 amendment touched a locked decision, resolved). Hole IDs (H1–H26) are cited inline.

## 0. The directive (verbatim) + the four locked interpretations

> "For the v2 plan, the metadata intelligence referred to for the nodes is the data
> package transferred from node to node with the intended objective of the node. Each
> node that deals with domains compatible in both 2D and 3D should have a top right
> 2D/3D toggle lever that changes the parameters and node sockets appropriately."

Locked by the user 2026-07-21 (grill answers):

1. **Directive-A source = per-edge (reading a).** A node's metadata intelligence =
   deriving its params/toggle from the metadata of the Dataset arriving on **its own
   input socket** (as transformed by upstream nodes) + the node's own objective (op,
   in-body modes, 2D/3D toggle). **No new data on the wire.** Readings (b) "intent
   annotation on the Dataset" and (c) "advertise objective upstream" are **REJECTED**
   — (b) has no payload slot and bloats the memo key; (c) is push/negotiation and
   violates locked decision 9 (lazy pull). (H1)
2. **The 2D/3D lever = a distinguished in-body Mode**, header-rendered (top-right), not
   a new state type. It reconfigures sockets/params via the mechanism modes already
   own; it inherits memo-keying (V2.02 §6) and serialization (V2.00 §12) for free. This
   amends **only the rendering clause** of locked decision 4. (H5)
3. **Anisotropic scalar params = paired floats + an axial unit.** 2D shows one `sigma`
   (`unit="um"` ÷ `pixel_size_um`); 3D shows `sigma_xy` + `sigma_z`, the latter
   `unit="um_axial"` ÷ `z_step_um`. Each independently field-able and derivable; no
   cross-socket derive. True vector *values* keep one `VECTOR` type with a runtime
   `dims`. (H13)
4. **Build order = mechanisms first.** The NodeSpec/registry mechanisms + the metadata
   machinery precede the node port and the eval engine ("Phase 2a-prime", §8). (H4)

## 1. The unifying model — one "derived property", two mechanisms

Both directives collapse into **one abstraction and two mechanisms**:

- **Derived property (H9).** A value-socket's metadata-derived default and the 2D/3D
  lever's default (`z>1 ⇒ 3D`) are the *same* thing: a property derived from the
  node's **resolved incoming metadata**, with a sticky `__locked__` override,
  re-derived on graph edits. `ModeSpec` gains an optional `derive`; the toggle default
  becomes metadata-intelligence exactly like a socket default.
- **Mechanism 1 — the edit-time MetaEnvelope pass (H4).** A cheap forward
  topological walk that propagates `AxisSizes` + calibration + layer-catalog through
  each node's declared `meta_transform`, **touching no pixels** (preserves lazy pull,
  decision 9). It feeds widget re-seeding and the toggle default at edit time. It is
  **advisory** — see Mechanism-2 memo note.
- **Mechanism 2 — the lever as a distinguished Mode (H5).** Sockets/params/granularity/
  kernel-axes become functions of mode state via a declarative variant resolver.

**Memo authority is unchanged (H4, H10).** `recipe_hash` continues to fold the
**eval-time** recorded `ReadContext` reads (V2.02 §8) resolved upstream-first at pull
time. The MetaEnvelope pass is advisory (UI + planning). The lever value enters
`recipe_hash` as an ordinary in-body-option param (V2.02 §6), so 2D and 3D memoize as
distinct entries with no new hash machinery.

## 2. Directive A — metadata is the per-edge package

- **A1 · Structured, propagating calibration (H2).** Add `Dataset.with_metadata(**changes)`
  — copy-on-write (`{**self.metadata, **changes}` then `replace`), the **only** write
  path (read path stays the §8 ReadContext). Define `CALIBRATION_KEYS` reusing the
  V1.91 vocabulary verbatim (`pixel_size_um`, `z_step_um`, `dt_s`, `channel_emission_nm`,
  `objective_na`, `objective_magnification`) so `metadata_adapt` stays reusable. A frozen
  `Calibration` view may exist only inside ReadContext — never a second source of truth.
  Per-channel optics stay **Channel-domain AttributeLayers** (V2.00 §3.2), not a Dataset
  field. Per-axis (y,x) pixel size + `origin_um` are deferred to V2.00 §16 until a data
  source needs them (z-vs-xy anisotropy is already `pixel_size_um` + `z_step_um`).
- **A2 · `meta_transform` on NodeSpec (H3).** A declarative
  `meta_transform: Optional[Callable[[MetaEnvelope, params, modes], MetaEnvelope]]`,
  default identity, mapping incoming calibration/axes to outgoing. Named helpers in
  `nodegraph/metadata.py`: `resample` (scale px/z per-axis), `z_project` (drop `z_step_um`,
  z→1, set `z_collapsed`), `stack_time` (t→1, drop `dt_s`), `channel_select` (subset/reindex
  channels), `crop` (preserve px, change extent), `stitch` (grow y,x, m→1, extent may be
  UNKNOWN). **Every node returning a new `AxisSizes` MUST return the matching calibration
  update in lockstep** (amends V2.02 §7b consequence 2). Add
  `Dataset.reshaped_axes(new_axes, *, drop_stale=True)` to drop/error on lattice layers
  orphaned by an axis change.
- **A3 · MetaEnvelope pass (H4).** New module `nodegraph/metadata.py` +
  minimal `nodegraph/graph.py`: `propagate_meta(graph, seeds) -> {node_id: MetaEnvelope}`,
  a forward topo walk. Statically-unknowable dims (stitched Y,X) are marked **UNKNOWN**;
  downstream derives referencing UNKNOWN fall back to the nearest known value and badge
  the widget provisional — never a silent stale number. Runs on load + every graph edit.
- **A4 · derives resolved eval-time via ReadContext (H10).** An unlocked, unconnected
  derived socket resolves inside `evaluate` (`ctx.value`) against the incoming Dataset's
  metadata through the recording ReadContext, so every key read folds into `recipe_hash`.
  Locked/wired sockets contribute a plain literal/field. The GUI preview from the
  MetaEnvelope pass is display-only, non-authoritative.
- **A5 · derive vocabulary + axial unit (H17).** Reuse boundary of `metadata_adapt`:
  only the **leaf math** (`symbol_table` building, `_safe_eval`, `_coerce`, sticky
  `__locked__`) is reused verbatim; **source/lifecycle/vocabulary** are rebuilt. The
  derive namespace gains node-state symbols (`is_3d`, `mode`, read-only sibling params).
  `to_pixels` gains `um_axial` (÷ `z_step_um`) alongside `um` (÷ `pixel_size_um`), and
  accepts a Vector → per-axis pixel vector. This change lives in the **v2 ctx wrapper**,
  not in `metadata_adapt.to_pixels` (V2.00 §13 keeps it as-is); a required-but-missing
  calibration field yields an explicit **uncalibrated** flag, not a silent 1:1 factor.
- **A6 · per-channel derive resolution when c>1 (H12).** Per-channel symbols
  (`emission_nm`, `na`, …) resolve against the node's **declared channel selection** read
  from the *incoming* Dataset — never file order (the v1 `channel_sets` plumbing has no v2
  counterpart). c==1 → that channel; c>1 with selection → the selected channel; c>1
  without selection on a c-iterating node → re-resolve per c at `evaluate` via
  `ctx.channel`; else the widget shows "varies by channel" and refuses a silent scalar.
  Optics never auto-coarsen — `join(Channel,Frame)=None` already blocks it; a **Select
  Channel** data-layer node (decision 6) is the explicit path and a **blocker
  prerequisite for the deconvolve PSF** (H18).
- **A7 · metadata adaptation inside zones (H23).** *Edit time:* socket topology + the
  toggle default use the metadata at the **zone-input boundary** (iteration 0); the
  back-edge is excluded from the pass exactly as from the cycle check (V2.00 §7). An
  axis-collapsing node inside a zone that would make a body node's toggle inconsistent
  post-iteration-1 raises a zone-design warning. *Evaluate time:* per-iteration values
  stay fully dynamic through ReadContext; `recipe_hash` legitimately differs per
  iteration; the output-fingerprint cutoff short-circuits fixpoints. Only the edit-time
  seed is frozen.

## 3. Directive B — the 2D/3D lever

- **B1 · variant socket model (H5).** `SocketSpec` gains
  `available_in: Optional[Mapping[str, frozenset[str]]]` = `{mode_name: allowed_values}`
  (None = always). `NodeSpec.inputs/outputs` are the **full union**; a pure resolver
  `active_sockets(state)` returns the sockets active for the current mode state (dim
  lever + all in-body modes). Declarative (not an imperative `update()`) so the layout is
  statically knowable at edit time (memo + GUI). `SocketSpec.instantiate()` carries
  `domain` and `dims` through to `Socket`.
- **B2 · the dim lever (H5, H24).** `ModeSpec` gains `presentation` ("body" default |
  "header"), `role` ("dim_lever"), and `derive`. The lever is `Mode("dim", ["2D","3D"],
  presentation="header", role="dim_lever", derive="'3D' if n_z>1 else '2D'")`. Declared
  **only** by nodes whose op is meaningful both planewise and volumetrically.
- **B3 · Granularity + kernel_axes resolvers (H6, H15, H16, H25).** `NodeSpec` gains
  `granularity` and `kernel_axes`, each either static or a `{dim_value: value}` map;
  `resolve_granularity(state)` / `resolve_kernel_axes(state)` pick per dim. `Granularity`
  = `TILEABLE | WHOLE_PLANE | WHOLE_VOLUME | WHOLE_SERIES | MULTI_VIEW` (V2.02 §7b).
  **true-3D vs stack-of-2D becomes a runtime capability** (H15): declare `supports_2d`,
  `supports_true_3d`, and a `three_d_fallback` — a 2D-only backend in 3D mode resolves to
  WHOLE_PLANE-looped-over-z with an honest "stack-of-2D" badge. structure.py CCL/watershed
  take `(dim, connectivity, size_filter)` (4/8 in 2D, 6/18/26 in 3D; px² vs px³) — already
  hashed via §6 params; golden test: 2D-CCL and 3D-CCL of the same input → distinct
  recipe_hashes (H16).
- **B4 · metadata-driven default + z==1 guard (H11).** `AxisSizes.is_volumetric`
  (`z>1`) + a `z_collapsed` provenance flag (set by Z-Projection; do NOT infer collapse
  from `z_step_um` absence). Lever default resolves from the incoming edge's inferred
  axes. When z==1 the 3D position is **disabled/greyed** and the node pins 2D; a
  serialized/locked 3D state on a z==1 edge is a **validation error** (no memo entry is
  written); 2D-locked on z>1 is legal (stack-of-2D) with an informational pip. Sticky
  `__dim_locked__` serialized beside `__locked__`.
- **B5 · vanishing sockets = hidden-not-deleted (H14).** A node owns the union of
  per-state sockets; toggling marks a subset unavailable (hidden), never deletes. Incident
  links are preserved but **inert** (excluded from pull traversal and thus from
  `recipe_hash`); per-state unconnected widget values are retained (keyed `(socket,state)`);
  multi-input order indices retained. Toggling back restores losslessly, re-validated by
  `can_connect`; a link that fails re-validation is kept and flagged invalid (red), never
  silently dropped. Group interface sockets bound to a member socket that becomes
  unavailable are hidden with the same rule.
- **B6 · which nodes get the lever (H24).** Eligibility test: a node exposes the lever
  **iff** it is a stencil/statistic/segmentation op whose `granularity` **and**
  `kernel_axes` genuinely differ per-plane vs volumetric, with both sides backend-supported.
  Survey partition (58 nodes): **43 toggle-bearing, 15 not** — excluded are (1) pointwise
  nD-agnostic (Gamma, Threshold-apply, If/Else, Channel Select/Split/Merge, Summary),
  (2) inherently-2D (DIC family, Tear Detection, Manual Mask, pyALDIC), (3) inherently-3D /
  axis-collapsing / temporal-only (DVC/ALDVC, 3D Mask Drawing, Z-Projection, Bleach,
  Temporal Fold). Nodes whose real variable is the **statistic scope** (Normalize,
  auto-Threshold) get a separate `Mode("scope", ["plane","volume","series"])`, never the
  dim lever (may carry both). The build-node verify gate checks every NodeSpec declares
  granularity/kernel_axes and every dim-lever node passes the test.
- **B7 · invariant: the toggle is kernel-axes, never a domain change (H25).** The domain
  lattice, `plan_transfer`, and the reducers are **toggle-invariant** by construction
  (a Voxel→Voxel op stays Voxel→Voxel in either mode). Never conflate the three
  "dimensionality" notions: (1) **kernel-axes** (this toggle: {y,x} vs {z,y,x}), (2)
  **axis-changing** nodes (new AxisSizes), (3) **lattice reduce/broadcast** (domain
  transfer). Known ripple: a 2D per-plane statistic computed per channel reduces {y,x}
  keeping {m,t,z,c} — an *unnamed* axis-set; resolve by requiring channel handling before
  the reduction (Select Channel or a Channel-domain transfer), **not** by naming an 11th
  domain (would re-open locked decision 2).

## 4. Type-system & structure ripples

- **C1 · VECTOR arity (H13).** Keep one `SocketType.VECTOR` (decision 3 intact). `Socket`
  and `SocketSpec` gain `dims: int = 3`. `can_connect` for VECTOR→VECTOR: equal dims
  connect; `src.dims < dst.dims` widens (pad axial 0, a value-level conversion, decision 6
  intact); `src.dims > dst.dims` is rejected (needs an explicit drop/swizzle node).
  Float/Int→Vector broadcast fills `dst.dims`. `dims` folds into `recipe_hash` as a param.
- **C2 · field memo key gains kernel-axes (H7).** Field stencil-dimensionality is
  **producer-owned** by default: a dimensionality-sensitive field operator (EDT, gradient,
  morphology) declares its kernel axes via an in-body mode on the producing node, so
  `field_expr_hash` folds operator identity + **all** params including `kernel_axes`. For a
  consumer-inherited (polymorphic) field, inject `kernel_axes` into the field key
  `("field", field_expr_hash, domain, kernel_axes, token)`. Add a per-plane/volumetric
  wire badge distinct from the domain-transfer badge (annotation only). Amend V2.02 §9.
- **C3 · Point/Track Arrow schema (H19).** Lock an **invariant** schema: columns
  `id,m,t,c,z,y,x` always present (z never NaN). Set-level metadata folded into the
  content hash: `z_kind ∈ {plane_index, subpixel}` (2D-mode detection stores the integer
  plane index; 3D stores sub-pixel z) and `channel_kind ∈ {single, per_point}`. Bridges
  never branch on mode. Answers "a 2D point set on a 3D dataset lives on which planes?" —
  on the plane(s) detected; z = plane index; never collapsed.
- **C4 · Fill/Extract Boundary contour-vs-surface (H20 — the one conflicts-locked).**
  The naive fix (register them as auto-routed transfer bridges) would violate decision 6;
  **resolved** by keeping them **explicit data-layer nodes** whose dimensionality derives
  from the input point-set's **z-span** (single z → planar contour on that plane; multi-z →
  surface), with the header toggle a **consistency assertion only** (hard error on
  contradiction). Do **not** add them to `transfer.py`'s `_BRIDGES` registry. Prerequisite:
  the C3 z_kind/z-span field. The "2D ROI on a z>1 dataset" case → filled on its own
  plane, never extruded.

## 5. Provider / store / benchmark

- **D1 · volume read path (H8).** Amend the V2.02 §3 `TileProvider` with
  `get_subvolume(level,m,t,c,z0,z1,iy,ix)` (a z-ranged brick, not a MIP) and
  `get_region_volume(...)`. Engine routing: TILEABLE/WHOLE_PLANE stay on `get_tile`/
  `get_region` (scalar z); WHOLE_VOLUME (and WHOLE_SERIES z-range) route to the volume
  path, feeding the "realize whole once, memoize as one proxy-keyed payload" flow. Lazy
  pull preserved (nothing realized until pulled). The block *shape* (512² day-one vs a
  z-spanning block) is orthogonal and benchmark-gated; the interface is stable regardless.
- **D2 · 3D in the keystone benchmark (H26).** Add a 3D section to
  `scripts/_bench_provider_granularity.py`: a `(Z,512,512)` b2nd stack with 3D block
  partitions (bz ∈ {1,4,full-Z}); time whole-volume, z-range subvolume brick, and
  single-plane reads → subvolume/whole + plane/whole ratios. Add "efficient bounded 3D
  subvolume + whole-volume read" to the b2nd-vs-TensorStore criteria (handoff §7.4). Keep
  "block = tile = memo unit" + Store=b2nd; this only picks the z-extent of the block.

## 6. Flagship + GUI

- **E1 · two-mode deconvolve (H18).** The flagship `deconvolve` becomes the reference
  two-mode metadata-intelligence node: **2D** derives an Airy/Gaussian PSF from NA + λ +
  `pixel_size_um` (no z-step), Granularity WHOLE_PLANE; **3D** derives the Gibson–Lanni PSF
  from NA + λ + `pixel_size_um` + `z_step_um` + immersion RI, Granularity WHOLE_VOLUME. PSF
  params carry V1.91 `unit`/`derive` resolved from the incoming Dataset via ReadContext.
  Optional PSF-override on the **existing Dataset socket** (secondary/multi-input — no new
  socket type). The two-mode reference example for the v2 build-node skill.
- **E2 · GUI header lever + relayout + re-seed (H21).** Amend V2.00 §14.5: the lever is a
  reserved header-rendered ModeSpec; deterministic socket relayout on toggle (vanished
  sockets collapse, wires detach with an undoable pip; shared sockets keep order; card
  reflows); live widget re-seed on graph-structure change driven by the MetaEnvelope pass
  (never a pull); properties panel mirrors **only** the active dim-variant; `__locked__`
  entries namespaced per dim-variant (`"2D:radius"`/`"3D:radius"`).
